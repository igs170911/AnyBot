# `web/api-client` · API client (skeleton)

Per `spec/06` section 2.4 and `spec/07` section 2: this package is a TypeScript
client **generated from `api/openapi.yaml`**; data fetching with TanStack Query
comes in later milestones.

## Generation source

- **Source**: `api/openapi.yaml` (the single source).
- That openapi.yaml is itself **generated by `crates/protocol` and committed**
  (`spec/07` section 2: `api/` = generated by code, committed). The real client
  types appear here once the generated schema is committed.
- The M2 skeleton keeps a placeholder in `src/index.ts`: `createApiClient()`
  fails before generation, so nobody pretends an API is usable at the skeleton stage.

## Commands (generate the client)

Once the client is generated, every update of `api/openapi.yaml` must regenerate
it and the generated file is committed together:

```sh
# types (openapi-typescript, output to src/generated/schema.ts)
pnpm exec openapi-typescript api/openapi.yaml -o web/api-client/src/generated/schema.ts
```

> The `api-client` gate in the Makefile regenerates into `target/` and diffs
> against the committed file; any difference blocks.

## Tests

`vitest run` (M2 tests only the placeholder behavior: the client cannot be created before generation).
