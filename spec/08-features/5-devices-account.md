## 0. 這一組被新架構改得最多

舊版有很多功能，只是因為「一台當大腦、其他當螢幕和手腳，中間靠帳號伺服器的長連線轉送」才存在。新版（`02`）腦跟著做事的那台走、每台留本機副本、伺服器負責帳號和協調；下面這些會自然消失或換掉。**使用者看得到的能力要保住**：每一條都在後面的表裡對到新的做法。

| 舊版的東西 | 為什麼存在 | 新版 | 使用者的能力怎麼保住 |
|---|---|---|---|
| 大腦／螢幕／手腳三種角色、「改用它當大腦」 | 資料只有大腦那一份，其他電腦都要連過去 | 沒有角色；每台都有本機副本和執行端（A1、A6） | 任何一台都能聊天、看到同一份結果（`account-brain` 拆成 `account-n4`～`n8`） |
| 雲端大腦（伺服器替每個帳號開一個容器） | Mac 關機時 Bot 照樣跑、手機有地方送指令 | 伺服器上的執行服務＋每人一台 Bot 的電腦（A2、A3） | 手機發起的回合、例行任務照樣在電腦都關著時跑（`server-brains`） |
| 帳號伺服器的長連線轉送（WebSocket 隧道、job／call） | 手機和螢幕要問大腦，大腦在使用者家裡 | 一般 HTTP POST＋SSE 依編號補送（A7） | 斷線只暫停即時更新，不掉資料（`phone-net`、`account-n4`～`n8`） |
| 同一個網路直接連（手機密碼、8793 埠、自簽憑證） | 沒有帳號伺服器時手機也要能用 | 一律有伺服器，沒遠端的就在本機 Docker（A13） | 同一個 Wi-Fi、不上網照樣能用手機（`account-direct`） |
| 加密備份（伺服器打不開） | 資料只在大腦一台，怕電腦壞掉 | 資料本來就同步在伺服器（`02` §3） | 電腦壞了資料還在（`account-backup`；隱私的取捨見 Q2） |
| Caddy 反向代理、`.env`、`make update-server` | 一行裝好 HTTPS | 不附反向代理、設定寫進資料庫（A10、A11） | 安裝時決定網址和聽的位址（`server-address`） |
| 從原始碼編譯安裝 | 舊版沒有給一般人的發行包流程 | 待決定（Q10） | 「一行裝好」照樣成立 |

## 要問使用者

最重要的在前。每題附建議。

1. **沒有 Docker 的電腦怎麼辦？**（`install-n27`、`computers-kinds`）舊版不需要任何伺服器，沒 Docker 也能用（Mac 上 Bot 的電腦退回封閉資料夾＋沙盒）；新版 A13「一律有伺服器」，沒有遠端伺服器的人要靠本機 Docker。**建議**：桌面 App 安裝時自動裝好容器環境（Mac 用內建的輕量 VM、Windows 用 WSL2、Linux 用套件）；真的裝不起來時，先讓這台自己能聊天、能在本機做事，畫面清楚說「手機和例行任務要等伺服器裝好才有」，不要整個不能用。
2. **對話放在伺服器上，隱私邊界跟舊版不一樣。**（`account-backup`、`server-brains`）舊版的承諾是「Bot 跑在你自己的機器上，伺服器只有打不開的備份」（SECURITY.md）；新版伺服器存著所有對話（`02` §6）。自架沒差別；如果是 5,000 人的雲端服務（`06` T1），管伺服器的人看得到所有人的對話。**建議**：自架和本機 Docker 接受；開放別人註冊的伺服器，註冊和邀請畫面寫清楚「伺服器的管理者看得到你的對話」，資料庫靜態加密；端對端加密延後。「加密備份」功能砍，改成伺服器端的 PostgreSQL 備份＋使用者自己「匯出我的全部資料」。
3. **明文 http 的規則和手機推播。**（`account-n1`、`account-can`、`server-address`）舊版：帳號密碼和電腦金鑰不走非 Tailscale 的明文，連不上寧可不連；`02` A8：http 可以用，一般 Wi-Fi 跳警告。另外手機推播（「不理他」的核心：只在需要時叫你）一定要 https。**建議**：密碼和金鑰只在 loopback、tailnet、或安裝時明確打開「區網 http」的位址上送，其他 http 一律不送（沿用舊版的保護）；走一般區網 http 的裝置只能收緊、不能放寬（沿用舊版「只能收緊」）。安裝時主動引導拿到 https（偵測到 Tailscale 就教 `tailscale serve`；否則自簽憑證＋手機信任一次），手機上說清楚「沒有 https 就沒有通知」。
4. **誰能叫你的電腦做事？**（`computers-n3`、`computers-pair`、`computers-n2`）舊版：配對加入的電腦只接受它的大腦簽過的指令，帳號伺服器被攻破也偽造不了；新版的任務經伺服器的信箱交到你的電腦。**建議**：以「每台電腦自己的信任層把關＋裝置連結預設關」為底；交到使用者電腦的任務帶「誰發起的」（人、例行任務、別的 Bot），由使用者自己的裝置簽、收的那台驗，伺服器只轉送；伺服器自己發起的（例行任務）在那台照「由伺服器發起」的規則問（`02` §5.3「規則看得到這一輪是誰發起的」）。「配對加入的電腦權限比較少」（不能叫別台、不能發布網站…）照留。
5. **每個帳號都有一台 Bot 的電腦之後，隔離和上限怎麼定？**（`server-brains`、`install-n28`）舊版只有擁有者的雲端大腦拿得到 Docker，其他人用自己的電腦當手腳，而且每個大腦有上限（記憶體 4 GB、CPU 2、程序 2048、最多 20 個）。新版每個人都有 Bot 的電腦（A2），在個人部署的同一台主機上。**建議**：個人部署也預設每人上限（沿用舊值當起點）和同時回合數上限（S7）；只有拿到邀請碼的人能註冊；安裝時問「只有你和家人用，還是會給別人」——會給別人就預設 gVisor（主機不支援時說清楚風險）。
6. **砍掉「同一個網路直接連」之後怎麼遷移？**（`account-direct`、`account-devices`）**建議**：砍；舊的手機密碼、直接連線的裝置清單、`lan-cert*` 都不搬；使用者升級後在本機伺服器建帳號，手機用帳號重新登入（升級說明裡寫清楚）。本機伺服器預設只綁 loopback，安裝時問「要不要讓同一個 Wi-Fi 的手機連」。
7. **指名的電腦不在線：自動改派，還是等？**（`computers-default`）A5 說能改派就自動改派到 Bot 的電腦；舊版的規則是「不准自己換到別台做同一件事」。**建議**：由程式判斷「一定要那台」：使用者在 Bot 設定選的、或訊息裡指名的電腦，就是一定要那台 → 放進它的信箱等，10 分鐘通知手機（繼續等／取消）；只有沒指名（預設 Bot 的電腦）才談改派；Bot 自己換電腦一律不准（程式規則）。
8. **遠端跑的回合要用家裡網路的模型（例如區網的 Ollama）怎麼辦？**（`computers-n5`）**建議**：沿用舊版——經使用者在線的電腦代連（只轉到那台網路裡的私有位址、只限自己帳號）；那台不在線時這一輪標「模型連不到」並通知，不偷偷換成雲端模型。
9. **SSH 電腦留不留、誰去連？**（`computers-n1`）**建議**：留，當電腦介面的一種轉接器；由有 SSH 金鑰的那台（使用者的電腦）去連，伺服器的執行服務不拿使用者的 SSH 金鑰；遠端回合要用 SSH 電腦時，交辦到那台的信箱。
10. **安裝方式：還是從原始碼編譯，還是發行包？**（`install-n1`、`install-n24`、03b Q4）**建議**：一般使用者一律裝預編譯、簽過章的發行包（桌面 App、只當電腦的版本、伺服器映像）；從原始碼編譯只給開發者。`ANYBOT_DIR`、`ANYBOT_SKIP_PACKAGES`、`PULL` 這類隨之不需要；簽章檢查保留、不給一般使用者跳過。
11. **伺服器管理員和伺服器設定畫面。**（`server-n13`、`server-n14`、`account-n11`）舊版沒有管理畫面，全靠 `.env` 和指令。**建議**：第一個註冊的帳號是伺服器管理員；App 裡給管理員一頁「伺服器設定」（邀請碼、對外網址、推播聯絡方式、每人上限、使用者清單與停用）；另給命令列的救援（忘記管理員密碼）。一般使用者忘記密碼要不要能自己重設（寄信）延後。
12. **「這台電腦的名字」合成一個？**（`computers-n8`）舊版有兩個名字（設定 › 電腦 的、手機上看到的）。**建議**：合成一個，存在伺服器的裝置清單。
13. **補三個伺服器有、畫面沒有的功能？**（`account-n10`、`account-n12`、`account-share`）改密碼、擁有者從手機移除某台電腦、退出別人分享給我的電腦。**建議**：三個都補畫面。
14. **通知種類「空的」是什麼意思？**（`account-push`、03b Q8）舊版訂閱時給空的＝全部，之後設成空的＝都不要。**建議**：沒設過＝全部；設成空的＝都不要。
15. **邀請碼要不要改成每人一組？**（`server-invite`）**建議**：先照舊（一組、管理員可以換）；每人一組、有期限次數延後。
16. **手機的量尺留不留？**（`phonefit-ruler`）服務「都不是」。**建議**：留（做法小，是唯一能在使用者手機上量出 iOS 問題的方法）。
17. **命令列留哪些？**（`install-n15`～`n21`）**建議**：留 `--ask`（腳本和外部 agent 用）、`--doctor`、`setup`（接上帳號）、`--version`、`--help`、`--data-dir`；`--install-skill` 延後；`--serve` 變成背景服務本身；開發用的不對外。
18. **舊的裝置身分和登入要不要搬？**（01a `remote.host_id`／`host_token`、01b `data.json` 的 `sessions[]`、`hosts[]`）**建議**：不搬，升級後每台電腦重新登入或配對、手機重新登入（`00` 決定 3 本來就一起升級）；帳號、密碼雜湊、兩步驟驗證、團隊成員、推播訂閱（連 `vapid.pk8`）、發布的網站要搬。

- 這一組是其他組的地基：「證明」幾乎都靠別組，這裡只有「對話和證據同步到每台」（`account-n4`）。「都不是」多半是安裝、命令列和手機外觀，照 `04` 的原則優先考慮砍或延後，但它們決定新版裝不裝得起來、手機用不用得了，所以大多建議留或改，沒有直接砍。
