# 08 · 功能清單（五個來源交叉盤點）

> 來源：OLD 的現有文件、舊程式（含 `01a`、`01b`、`03a`–`03c` 的盤點）、git 歷史、實際操作、使用者本人。看過舊版的一方盤點，**只寫從外面看得到的行為**，不含舊程式結構。
> 用途：新版要做哪些功能的總清單。每條都標出它服務 `04` 的哪一條，並附「留／改／砍／延後」的**建議**；最後由使用者決定。
> 互查：`00-boundaries.md`（邊界 B1–B18）、`04-product-core.md`（取捨標準）、`01`、`03a`–`03c`（覆蓋檢查的對象）。

## 怎麼盤

1. **以 feature-map 的子功能為底**（298 條，編號沿用，例如 `chat-steer`）。
2. **用其他來源補**：FEATURES.md、MECHANICS.md、SECURITY.md、git 歷史（commit 訊息寫了很多行為和邊界情況）、舊程式。找到 feature-map 沒寫的，就新編號：`<區>-n1`、`<區>-n2`…
3. **覆蓋檢查**：`03a`（App 的介面）、`03b`（帳號伺服器、命令列、環境變數）、`03c`（給模型的工具、`/` 指令）、`01a`／`01b`（資料）裡的每一項，都要對到某條功能，或明確標「沒有對應的功能，建議砍」。
4. **實際操作**（第 4 個來源）這一輪先不做：需要在隔離環境開一份 OLD 來點。需要實際操作才確定的，標「待操作確認」。
5. **使用者本人**（第 5 個來源）：每組最後列「要問使用者」，逐條跟使用者討論。

## 每條功能的欄位

| 欄位 | 寫什麼 |
|---|---|
| 編號 | 沿用 feature-map 的代號；新找到的用 `<區>-n<數字>` |
| 功能 | 一句話的名字 |
| 行為 | 從外面看得到的：使用者做什麼、看到什麼、留下什麼結果；**數字要寫出來**（上限、逾時、天數） |
| 邊界 | `00` 的 B 編號，可以多個 |
| 來源 | 文＝現有文件；程＝舊程式（含 01a/01b/03a–03c）；史＝git 歷史（附 commit 短碼）；操＝實際操作；人＝使用者 |
| 服務 | `04` 的哪一條：**不理他／跟進／證明／信任／都不是**（可以多個） |
| 建議 | **留／改／砍／延後**，附一句理由。「改」要寫怎麼改（例如照新架構、照確定性優先） |

## 每組檔案的結尾

1. **覆蓋檢查**：這組負責的 01a／01b／03a–03c 項目，哪些對到了、哪些沒對到。
2. **要問使用者**：最重要的問題，附建議。
3. **統計**：功能條數（沿用的、新找到的）、各建議的條數、各「服務」的條數。
