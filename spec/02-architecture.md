# 02 · 新版架構

> 來源：2026-11-24 與使用者的架構討論；參考 OpenBot（`CopilotKit/openbot` @bdb6280，MIT）的公開文件與 API 設計（只借想法）；**不含舊程式的結構**。
> 用途：新版的整體形狀：誰負責什麼、事情在哪跑、資料怎麼同步、連線怎麼用、資料存哪。
> 互查：`00-boundaries.md`（邊界與決定）、`01-data-inventory.md`（舊資料怎麼遷移進來）。

## 一句話

**腦跟著做事的那台走；每台裝置都留一份本機副本；伺服器負責帳號、排順序、轉送和協調。**

## 最高原則：使用者無感

使用者看到的永遠是：**他一直都可以聊天，結果永遠會同步，不用管現在在哪台做，事情都會有人做。**
在哪台跑、哪個桌面、哪台 Docker、同步、改派、重連，全部在底層處理。下面每一條機制都要照這個原則檢查：會不會讓使用者需要知道、需要等、需要重做。

## 已定的決定（2026-11-24）

| # | 決定 |
|---|---|
| A1 | Bot 的腦（問模型、跑工具、把關、寫紀錄）在**做事的那台**上跑。伺服器的 API 本身不跑腦。 |
| A2 | 每個使用者自動有一台**共用的 Bot 電腦**（Docker），至少能跑新版支援的工具。每個 Bot 一個自己的桌面；網站登入所有 Bot 共用；桌面不夠時底層自動加開一台，登入照樣共用；有事就開、閒置一段時間就存檔休眠、要用時幾秒內恢復，例行任務到點前先叫醒（2026-11-24 修訂，原本是一直開機，見 `06` S9）。使用者看不到這些。 |
| A3 | Docker 電腦**拆成兩半**：跑腦的執行服務拿得到金鑰，但 Bot 不能在裡面跑指令；Bot 用的電腦沒有任何金鑰。 |
| A4 | **一個任務只在一台跑。** 要用到另一台，就交辦一個新任務到那台的信箱。 |
| A5 | **指定的電腦不在線時，一律自動改派到 Bot 的電腦，並通知使用者改到哪台**（2026-11-24 修訂，`09` K39）。 |
| A6 | **對話和記憶只往後加；設定以欄位為單位、後寫的贏；「誰去做」由伺服器裁判。** 不追求所有資料只有一份真相。 |
| A7 | **連線只是加速器。** 動作用一般 HTTP，變化用 SSE 加編號補送；WebSocket 只用在看畫面和語音，而且只在使用中開。 |
| A8 | **不一定要 HTTPS。** http 下能用的功能有明確清單，不能用的就關掉並說明。 |
| A9 | **模型金鑰**加密存在伺服器，同步到每台電腦的系統鑰匙圈；執行端直接呼叫模型，用量事後回報。 |
| A10 | **伺服器用 PostgreSQL；客戶端和執行端的本機資料用 SQLite。** 不用環境變數、不用 JSON 設定檔；設定在安裝時決定、寫進資料庫。（2026-11-24 因 5,000 人目標修訂，原本是「全部 SQLite」，見 `06` §1） |
| A11 | **伺服器全部是 Docker**：一個映像、一個程序，啟動時自己跑資料庫遷移。**不附反向代理**（不帶 Caddy）：HTTPS 交給使用者自己的 nginx、Cloudflare Tunnel 這類。**第一階段只用 Docker（compose）**，架構保留擴充的路；量大了再上 Kubernetes，同一套映像（2026-11-24，見 `06` S4）。 |
| A12 | **HA**：第一階段做到「可恢復」（PostgreSQL 備份）；之後要擴充時用 API 多副本＋PostgreSQL 高可用＋NATS。（2026-11-24 修訂，原本是 SQLite＋Litestream，見 `06` §1） |
| A13 | **一律有伺服器。** 沒有遠端伺服器的人，伺服器和 Bot 的電腦就在自己電腦的 Docker 裡跑，由桌面 App 自動裝好。手機一樣能用，手機發起的回合在 Bot 的電腦上跑。這台電腦裝不起 Docker 時，先讓它能聊天、能在本機做事，畫面說清楚「手機和例行任務要等伺服器裝好才有」（`09` K34）。 |
| A14 | **相容期 6 個月**：伺服器要能服務 6 個月內發佈的 App 和執行端（怎麼算見 `09` K84：最新版一律接受；被取代的舊版再接受 6 個月）。 |
| A15 | Bot 和工具中間有一層**信任層**：每個動作都經過「把關 → 做 → 留證據 → 驗收」。證據由程式從工具的實際回傳自動記，不靠模型自己說（`04` §2）。 |
| A16 | **「任務」是資料庫裡的一級物件**：目標、做完的標準、狀態、下次跟進、證據清單、交付報告（`04` §3）。 |
| A17 | **可以接外部 agent（Claude Code 等）當成 Bot。** 內建執行端和外部 agent 講同一套「AnyBot 執行事件協定」（參考 AG-UI，改成自己的版本）；外部 agent 的動作也要經過信任層（§11）。 |
| A18 | **三個可插拔的介面：Bot、電腦、工具。** 每個都有預設的做法，也能換成自己的（§0.1）。使用者自己的電腦（手腳）只是「電腦介面」的其中一種實作。 |
| A19 | **桌面和手機講同一套：對話、工具、核准。** 桌面（Mac、Windows、Linux）、手機網頁；手機維持網頁版，不做原生 App。**聊天頻道第一版是 Slack、Discord、Telegram，只能聊天、看進度，一律不能按允許**（2026-11-24 修訂，`09` K42、K43，§0.2）。 |
| A20 | **遠端回合可以用保險庫填密碼**（2026-11-24 決定，原 D1）。保險庫只在執行服務裡解開，由它直接把密碼填進瀏覽器，Bot 跑的指令碰不到；填之前照核准規則問；每次都留紀錄。代價是管伺服器的人理論上解得開：伺服器開放別人註冊時，邀請畫面要說清楚；規模部署用 KMS 信封加密（`06`）。 |
| A21 | **外部 agent 的金鑰經執行服務轉發**（2026-11-24，原 D3，`09` K6）：它問模型的請求先到執行服務，由執行服務加上金鑰，金鑰不進它跑指令的環境；做不到的 agent 在 Bot 設定裡標出來。 |
| A22 | **手機一律連伺服器**（`09` K16）：舊版「手機直接連桌面 App」（手機密碼）砍掉。 |
| A23 | **只有擁有者能匯出自己的 Bot 和聊天**（`09` K17）：管理員管帳號，但看不到、匯不出別人的內容。 |

## 0. 分層

參考 OpenBot 的分層，每一層先定好介面、附一個預設的做法；之後要換某一層，上面都不用動。

| 層（由上往下） | AnyBot 新版 |
|---|---|
| 工作區 | 桌面 App、手機網頁：聊天、任務、交付報告、核准 |
| Bot（執行端） | 在使用者的電腦上，或伺服器上的執行服務，跑 Bot 的腦；也可以是接進來的外部 agent（Claude Code 等，§11） |
| **信任層**（AnyBot 多加的） | 夾在 Bot 和工具中間：把關 → 做 → 留證據 → 驗收（A15） |
| 模型 | 模型供應商 |
| 工具 | 內建工具＋MCP |
| 執行環境 | Bot 的電腦（Docker，可換 gVisor）、使用者的電腦（沙盒） |
| 基礎設施 | 使用者的電腦（本機 Docker）、自架伺服器、雲 |

「先把底打好」＝下面幾層先做好、介面先定好，再往上蓋（`05` §1）。

### 0.1 三個可插拔的介面（A18）

參考 OpenBot 的架構：伺服器管身分、權限、核准規則與答案、紀錄；下面接三種可以替換的東西，每種都「預設的、自帶的，可以只用一種，也可以兩種一起用」。

| 介面 | 預設的做法 | 自帶的 | 介面要提供的能力 |
|---|---|---|---|
| **Bot** | 內建執行端（使用者的電腦上，或伺服器上的執行服務） | 外部 agent：Claude Code 等（§11） | 講 AnyBot 執行事件協定；動作經過信任層 |
| **電腦** | Bot 的電腦（Docker，§2）；使用者自己的電腦（手腳） | 第三方沙盒（例如 Daytona、E2B、Modal）、之後的 Kubernetes，各用一個轉接器 | 開一台、關一台、跑指令、讀寫檔、瀏覽器、截圖、即時畫面 |
| **工具** | 內建工具（例行任務、記憶、保險庫、卡片、交辦給別的 Bot…） | 任何 MCP 伺服器或 MCP hub | 統一的工具描述；**不管哪一種，都經過信任層** |

- **每種電腦先宣告自己的能力**：有沒有桌面、瀏覽器，能不能一直開機，能不能共用登入。「這一輪用哪台」由程式照能力和 §2 的規則決定，不交給模型（`04` §2）。
- 預設的做法先做好；第三方沙盒和 Kubernetes 之後再接。

### 0.3 一個 Bot 裡面的九個模組（`09` K93）

上面的分層講「東西放在哪一層」；這一張講「一個 Bot 的腦由哪幾塊組成」。九個模組合起來是**一個** Agent，不是九個 Agent（`09` K94）。行為寫在 `10-behavior/`，這裡只指過去。

| 模組 | 管什麼 | 行為規格在 |
|---|---|---|
| 執行迴圈 | 一輪照固定的順序一步一步跑：問模型、做動作、記紀錄、收尾 | 第 1 組 `turn-loop` |
| 上下文編譯器 | 每次問模型前，從事件、原始紀錄、記憶重新組出要給它看的內容 | 第 3 組 `context-*` |
| 模型閘道 | 各家模型的格式、重試、備用、資料政策 | 第 6 組 `models-*` |
| 狀態引擎 | 任務狀態由事件算出來；預算；工具的三個等級 | 第 1 組 `task-events`、`task-state`、`task-done-gate`、`task-budget`、`task-effects` |
| 大腦（記憶與搜尋） | 記憶怎麼進來、怎麼找、怎麼帶進上下文 | 第 3 組 `memory-*` |
| 證據與信任 | 把關 → 做 → 留證據 → 驗收；交付報告 | 第 2 組 |
| 技能 | 技能怎麼學、怎麼上線、任務鎖定版本 | 第 3 組 `skills-*` |
| 學習與整理 | 從成功和失敗整理教訓；有自己的預算 | 之後的里程碑（`09` K99、K105） |
| 政策與評估 | 核准規則、資料可以送到哪、能力報告 | 第 2 組 `safety-*`、`autonomy-*`，第 6 組 `models-egress`；能力報告之後做（`09` K105） |

### 0.2 前端（A19）

| 前端 | 說明 |
|---|---|
| 桌面 App | Mac、Windows、Linux |
| 手機 | 網頁版（PWA），不做原生 App |
| 聊天頻道 | 第一版 Slack、Discord、Telegram（舊版已有）；由伺服器上的頻道轉接收發 |

- 桌面和手機講同一套：**對話、工具、核准**。
- **聊天頻道只能聊天、看進度，一律不能按允許**（`09` K43）；核准只在 App 和手機。
- 頻道來的訊息照 `00` 的安全承諾，一律不受信任。

## 1. 角色

```
 手機（網頁）──┐
               │  POST：送訊息、按允許、叫某台做事
 電腦 A ───────┼──────────────────────────→ ┌──────── 伺服器（Docker）────────┐
 （桌面 App：   │  SSE：收變化（帶編號）       │  API：帳號、裝置、紀錄彙整、      │
  畫面＋執行端） │ ←────────────────────────── │       信箱、檔案暫存、排程、      │
               │                              │       推播、協調                  │
 電腦 B ───────┘                              │  執行服務：跑 Bot 的遠端回合（有金鑰）│
 （手腳＋執行端）                              │  Bot 的電腦：每個使用者一台共用（無金鑰）│
                                              │  HTTPS：使用者自己的反向代理（選配）   │
   每台都主動連出去，不用開連接埠                   └──────────────────────────────────┘
```

| 角色 | 做什麼 | 不做什麼 |
|---|---|---|
| **伺服器 API** | 帳號登入、裝置名單與配對、對話和記憶的彙整與排序、每台電腦的信箱、檔案暫存、排程到點投遞、推播、協調（見 §3.3）、加密保存金鑰與保險庫 | 不問模型、不跑工具、不保存進行中的回合 |
| **執行端** | 跑 Bot 的腦：問模型、跑工具、照核准規則把關、把每一步寫回伺服器 | — |
| ├ 在使用者的電腦上 | 桌面 App 裡的執行端；在這台本機做事 | — |
| └ 在伺服器上 | 執行服務：一個服務跑所有 Bot 的遠端回合，操作 Bot 的電腦 | Bot 不能在這裡跑指令 |
| **Bot 的電腦**（Docker） | 每個使用者一台共用，每個 Bot 一個桌面；Bot 跑指令、讀寫檔、開瀏覽器的地方 | 沒有任何金鑰和伺服器設定；不同使用者絕不共用 |
| **桌面 App** | 畫面＋執行端＋手腳；留一份本機副本 | — |
| **手機（網頁）** | 畫面：送指令、看紀錄、按允許 | 不跑腦 |
| **聊天頻道**（Slack、Discord、Telegram…） | 由伺服器上的頻道轉接收發：聊天、通知、按允許 | 頻道來的訊息不受信任 |

## 2. 這一輪在哪跑

| 從哪裡發起 | 在哪跑 |
|---|---|
| 在電腦 A 上叫 Bot | A |
| 在手機上叫 Bot | Bot 的電腦 |
| 例行任務 | Bot 的電腦 |
| 指定了某台電腦 | 那台 |

- 預設不顯示在哪台跑（使用者不用管）；步驟詳情裡看得到，出問題時查得到。
- 一個任務只在一台跑（A4）。跨台＝交辦新任務到另一台的信箱。
- 指定的電腦不在線：一律改派到 Bot 的電腦，並通知使用者改到哪台（A5）。這件事如果一定要原本那台（它的檔案、它的 App），Bot 在報告裡說清楚哪些部分做不到。

### Bot 的電腦（電腦介面的預設做法）

- 每個使用者一台共用的 Bot 電腦；每個 Bot 一個自己的桌面（各自的畫面、各自的工作資料夾）。
- **網站登入所有 Bot 共用**：一個 Bot 登入過，其他 Bot 不用再登入。
- 桌面不夠用時，底層自動加開一台，登入資訊照樣共用。
- 有事就開；閒置一段時間就存檔休眠，要用時幾秒內恢復；例行任務到點前先叫醒。（2026-11-24 修訂，原本是一直開機，見 `06` S9）
- 同一個使用者的 Bot 共用；**不同使用者絕不共用**。
- 以上都在底層做，使用者看不到「哪台、哪個桌面」。
- **技術上最難的是登入共用**（見 D2）：同一份瀏覽器登入狀態，不能同時給兩個瀏覽器用。初步做法：
  - 一台電腦只開一個瀏覽器，每個 Bot 用自己的分頁；Bot 的畫面就是那個分頁的即時畫面。
  - 加開的電腦之間同步登入狀態。
  - 遇到不允許同時登入的網站，用保險庫自動重新登入（跟 D1 有關）。

## 3. 資料與同步

### 3.1 只往後加的紀錄（對話、記憶、任務的進度與證據）

1. 訊息、步驟、重新產生、刪除，**全部都是「加一筆」**，不回頭改舊的。
2. 每一筆在**產生它的裝置上**就給一個全域唯一的 ID（建議用依時間排序的 ID，例如 UUIDv7）。
3. 伺服器收到時給一個**遞增編號**，代表它在彙整後的順序。
4. 每台裝置有一份**本機副本**，加一個「還沒送出」的匣子。
5. 同步只有兩個動作：**把匣子裡的送上去**；**跟伺服器要第 N 號之後的**。

因為只往後加、ID 不重複，各台的紀錄合起來就是全部，不需要合併邏輯。

### 3.2 設定

以欄位為單位，**後寫的贏**。離線時可以改，回到線上時後寫的覆蓋。不做逐項合併。

### 3.3 每樣東西的主人

| 資料 | 主人 | 有衝突時 |
|---|---|---|
| 對話、記憶 | 沒有單一主人 | 只往後加，合起來就是全部；伺服器只負責排順序 |
| 設定、核准規則 | 沒有單一主人 | 欄位後寫的贏 |
| **這一輪由誰跑、例行任務由誰執行、核准卡片的答案** | **伺服器（唯一裁判）** | 不能有兩份真相，不然會寄兩封信、跑兩次、一張卡被答兩次。伺服器連不上時這類事要等；只有本機發起的那一輪可以先在本機跑 |
| 帳號、裝置名單 | 伺服器 | — |
| 電腦上的檔案 | 檔案所在的那台 | — |
| 金鑰 | 使用者的裝置（系統鑰匙圈） | 伺服器只存加密的 |

### 3.4 同步範圍

| 同步 | 不同步 |
|---|---|
| 對話（訊息、步驟） | 各台電腦上的檔案：留在做事的那台，聊天裡點開時才去拿 |
| 記憶 | 瀏覽器的登入狀態 |
| 設定、核准規則 | 紀錄檔、當機報告 |
| 用量 | |

### 3.5 情境

| 情境 | 其他裝置看得到嗎 |
|---|---|
| A 正常關機 | 全部看得到：每一步做的時候就送上去了 |
| A 做到一半關機 | 看得到做到哪；那一輪標成「中斷」。可以在別台叫 Bot 接著做 |
| 伺服器掛了，A 照常做事 | 暫時看不到；A 存在本機匣子，伺服器回來自動補上 |
| 伺服器掛了，而且 A 關機 | **看不到那一段，等 A 再開機連上才補上**（資料只在 A 上） |
| A 離線時和 B 在同一個對話各說了話 | 兩邊都保留，照送到伺服器的順序排；A 的標「離線時送出」 |
| 遠端跑完，之後打開 A | A 先顯示本機副本，再補第 N 號之後的，畫面閃一下「同步中」 |

## 4. 連線

### 4.1 原則：連線只是加速器

1. **所有動作用一般的 HTTP POST**，每個請求帶 `Idempotency-Key`，失敗就重送，不會做兩次。
2. **每個變化都有遞增編號**；斷線重連時，裝置照「我最後看到第 N 號」跟伺服器要之後的（SSE 上只送提示，`09` K118 ⑧）。
3. **紀錄才是真相，通知只是提示**：收到通知就回頭重讀；漏掉的通知靠重連或下一次補回來。

斷線只會讓即時更新暫停，不會掉資料、不會讓狀態錯亂。

### 4.2 每條路用什麼

| 誰 → 誰 | 用什麼 | 斷線時 |
|---|---|---|
| 手機、電腦 → 伺服器（送訊息、按允許、叫某台做事） | POST ＋ `Idempotency-Key` | 重送 |
| 伺服器 → 正在看聊天的手機、電腦 | SSE，**只在打開聊天時才連** | 自動重連，從編號補 |
| 伺服器 → 背景中的手機 | Web Push | 系統負責 |
| 伺服器 → 執行端（有信、核准的答案） | SSE；遇到會把 SSE 卡住的代理就退回長輪詢 | 自動重連，從編號補 |
| 執行端 → 伺服器（步驟、結果、Bot 打的字） | POST，每 0.2–0.5 秒送一批 | 先存本機匣子，回來再補 |
| 看畫面、接管電腦、語音 | WebSocket 或 WebRTC，**只在使用中才開** | 重連；即時畫面沒有要補的資料 |

### 4.3 細節

- **心跳**：伺服器每 15 秒在 SSE 送一行空的心跳；客戶端 30 秒沒收到東西就自己重連。經過 Cloudflare（cloudflared）時，太久沒資料大約 100 秒會被切，15 秒的心跳可以避開。
- **HTTP/3**：由使用者自己的反向代理提供（有支援的話）。手機切網路時連線不斷、重連更快；網路擋 UDP 時自動退回 HTTP/2。新版不依賴它，程式碼也不用為它改。
- **放在反向代理後面時**：SSE 的回應帶 `X-Accel-Buffering: no`，nginx 才不會把它卡住不送；代理的讀取逾時要大於 30 秒。
- **伺服器對聊天頻道的連線**：有些平台（例如 Slack、Discord）只提供長連線，這條連線在伺服器上，不違反 A7。A7 管的是我們自己的客戶端。
- **手機在背景**：iPhone 會暫停背景的網頁，SSE 會斷，這是正常的；背景靠 Web Push，打開時從編號補齊。

## 5. 安全

### 5.1 金鑰

- 模型金鑰加密存在伺服器，同步到每台電腦的系統鑰匙圈；執行端直接呼叫模型，用量事後回報（A9）。
- 伺服器上的執行服務也要解開金鑰才能跑遠端回合。
- **鑰匙圈的項目名稱帶上「這個資料庫的編號」**：每份資料各用各的鑰匙，測試用的那一份不會讀到使用者真正的鑰匙圈。

### 5.2 Bot 跑指令的地方沒有金鑰

- **Docker 電腦**：執行服務和 Bot 的電腦是兩個容器（A3）。Bot 的電腦拿不到任何金鑰和伺服器設定。
- **使用者的電腦**：執行端拿著金鑰；Bot 跑的指令在沙盒裡，而且環境變數裡的金鑰先拿掉。
- 使用者自己交給 Bot 用的密鑰（例如 GitHub token）是另一回事，見 §5.6。

### 5.3 核准

- **在執行端把關**：每一步由跑腦的那台照規則決定直接做、先問或拒絕。
- 規則存在伺服器，同步到每個執行端；每個決定的紀錄寫回伺服器。
- **卡片的答案由伺服器裁判**：一張卡只能被答一次，答案只落在使用者按下時看到的那張卡上（`00` 的安全承諾）。
- 回答卡片的路：執行端把卡片寫到伺服器 → 推播到手機 → 使用者按 → 執行端從信箱拿到答案。
- **權限的先後順序**（由高到低，`09` K29）：
  1. **內建安全底線**：私密檔不能讀改、危險指令拒絕、Bot 不能點 AnyBot 自己的核准按鈕、Windows 沒有沙盒時在這台執行指令每次都問。誰都關不掉。
  2. **管理員**的規則和鎖定。
  3. **使用者**的規則和「一律允許」。
  4. **預設規則**。
- **預設規則由程式判斷**（K26）：刪除、寄給別人、分享、發佈、付款、改密碼這幾類，由程式認出來、一定先問；模型只處理規則沒涵蓋的，結果標「模型判斷」。
- **使用者的「一律允許」蓋過預設的「先問」，包括上面那幾類**（K26）；蓋不過內建底線和管理員。
- **「一律允許」套用到所有 Bot，記的是同一種具體動作**（K27）：例如「在 Slack 的 #team 發訊息」「跑 git push」；別的刪除、別的發文照問。
- **回答種類**：允許這次／這段對話都允許／一律允許／拒絕（`09` R10）。
- **/always-approve 開著直到使用者關掉**（K28）；這期間的判斷來源標「一律放行」。
- **沒人在旁邊時等核准**（K30）：15 分鐘後這一輪先收工，任務停在「等你」並推播；使用者回來答了再接著做，不算失敗。
- **聊天頻道一律不能按允許**（K43）。
- 改網站密碼直接交給人做；規則壞了就一律拒絕；拒絕規則先比對；規則看得到「這一輪是誰發起的」（人、例行任務、別的 Bot）。

### 5.4 Docker 網路

- 伺服器資料庫和 Bot 的 Docker 電腦放在**不同的網路**。
- 預設只綁 loopback（**`127.0.0.1` 和 `::1` 都要綁**），給同一台的反向代理用。要讓手機或別台直接連（例如 tailnet、區網上的 http），安裝時選要聽哪個位址。
- 只相信安裝時設定的反向代理帶來的來源 IP（`X-Forwarded-For`），登入次數限制才不會被繞過。
- Bot 的電腦拿不到伺服器的任何設定。

### 5.5 HTTP 模式（A8）

| 客戶端 | http 下 |
|---|---|
| 電腦上的 App（桌面、手腳） | 正常可用。在 tailnet 上已經被 WireGuard 加密；在一般區網用自簽憑證，配對時確認一次指紋 |
| 手機瀏覽器 | **能用**：登入、聊天、叫某台做事、看即時進度、頁面開著時按允許。**不能用**（瀏覽器規定 https 才給）：推播通知、麥克風、安裝成 App、部分剪貼簿功能 |

- 一般 Wi-Fi 上用 http，密碼和對話是明文：介面要跳警告。使用者決定只跳警告，不沿用舊版「非 tailnet 的明文 http 不送密碼和金鑰」的保護（`09` K36）。

### 5.6 其他安全與隱私決定（2026-11-24）

- **隱私**（`09` K35）：開放別人註冊的伺服器，在註冊和邀請畫面寫清楚「伺服器的管理者看得到你的對話」；資料庫磁碟加密；端對端加密延後；舊版的「加密備份」改成「匯出我的全部資料」。
- **信任伺服器**（K37）：伺服器交到使用者電腦的任務就照做，不另做裝置簽章。代價：伺服器被攻破時，就能指揮使用者的電腦。
- **使用者交給 Bot 電腦用的密鑰**（K40）：跟 AnyBot 自己的金鑰分開。AnyBot 的金鑰絕不進 Bot 的電腦；使用者的密鑰加密存伺服器、只在跑指令時注入、輸出裡出現就遮掉、每次使用記進證據。
- **指令型連接器**（npx、uvx，K44）：在這個連接器指定的電腦跑，預設是使用者的電腦；要在 Bot 的電腦跑，設定上明寫「金鑰會放進 Bot 的電腦」，由使用者自己打開。網址型由執行端直接連。
- 手機要完整功能就要有 https，交給使用者自己的反向代理：nginx 加憑證、Cloudflare Tunnel、Tailscale 等。

## 6. 儲存

| 放哪 | 放什麼 |
|---|---|
| **伺服器資料庫**（PostgreSQL，A10） | 帳號、裝置、彙整後的對話和記憶、任務與證據、信箱、排程、協調狀態、加密的金鑰與保險庫、用量 |
| **伺服器資料庫裡可重建的表** | 文件索引、向量（pgvector）：隨時可以清掉重建，備份時可以略過 |
| **每台電腦的本機資料庫**（SQLite） | 本機副本、還沒送出的匣子、進行中的回合（當機後接著做）、這台的身分與權限 |
| 檔案（資料庫只記編號和雜湊） | 附件、頭像、教學錄製、長輸出、快照 |
| 別人的格式，照原樣放 | 瀏覽器設定檔、技能資料夾（`SKILL.md`）、Bot 工作區、下載的檔案 |
| 純文字檔 | 紀錄檔、當機報告（資料庫壞了也要寫得進去） |
| 系統位置 | 管理員政策與 hooks（`00` 決定 6）、系統鑰匙圈 |

- **不用環境變數，不用 JSON 設定檔**（A10）。設定在安裝時決定、寫進資料庫，之後在設定畫面改。
- **唯一留在外面的是「資料庫在哪」**：
  - 客戶端：本機資料夾，預設照作業系統的慣例，命令列 `--data-dir` 可以改。
  - 伺服器：PostgreSQL 的連線位址，和加密秘密的主鑰匙（`09` K113 ④）。放在一個小的啟動檔裡，用命令列 `--bootstrap <檔案>` 指定；因為裡面有密碼和鑰匙，所以用檔案，不放在命令列參數上。這是唯一不在資料庫裡的東西。

## 7. 伺服器部署

- **全部 Docker**（A11）：伺服器 API 一個映像、一個程序（API、手機網頁、啟動時自己跑資料庫遷移、排程），外加執行服務、Bot 的電腦。執行服務和 Bot 的電腦可以用同一個映像，各自用不同的啟動指令。**不附反向代理。**
- **安裝檔**：安裝時決定設定（網址、要聽哪個位址、相信哪個反向代理、邀請碼等），寫進資料庫。
- **沒有遠端伺服器的人**（A13）：伺服器和 Bot 的電腦在自己電腦的 Docker 裡跑，由桌面 App 自動裝好；之後換到遠端伺服器時，把紀錄搬過去。
- **HA**（A12）：第一階段做到可恢復；之後要擴充時用 API 多副本＋PostgreSQL 高可用＋NATS（`06`）。
  - 伺服器重開時，各執行端照樣在做事，寫不回去的先存本機，伺服器回來再補。
  - 三條規則從第一天就守：
    1. 狀態全部放在資料庫或物件儲存，不留在某一台的記憶體或本機檔案裡。API 副本是無狀態的。即時通道上經過的東西（正在打的字、「有新的」這種提示）不算狀態：丟了只會慢一點，不影響結果（`09` K118 ⑭）。
    2. 回合可以從紀錄接著做。
    3. 例行任務和排程，只由拿到主控權的那個副本執行。

## 8. API 原則

- **API 規格是唯一來源**（OpenAPI），客戶端由它產生。
- **每個寫入都帶 `Idempotency-Key`。**
- **相容期 6 個月**（A14；怎麼算見 `09` K84）：新版上線後，各台電腦不會同一天更新。最新的版本一律接受；被新版取代的舊版本，從新版發佈那天起再接受 6 個月。相容的承諾從第一個正式版開始（`main` 上第一個沒有 `-rc` 這種尾巴的 `v*` 標籤，`09` K111 ④、K118 ⑥）；開發版和 `-rc` 版不算發佈，沒有這個承諾。資料庫只加不刪，要拿掉東西等舊版不再用了才刪（確切的規則見 `05` §2）。

## 9. 參考 OpenBot：借了什麼、沒借什麼

**借的（只借想法）**：
- 通知只是提示，紀錄才是真相
- 工作佇列＋輪詢＋叫醒
- 每個寫入帶 `Idempotency-Key`
- 一個映像一個程序，啟動時自己跑遷移
- Docker 網路隔離、只綁 loopback、Bot 的電腦拿不到伺服器設定
- 核准的設計（§5.3）
- API 規格當唯一來源、相容期

**刻意不借的**：
- 一個 Bot 一台電腦、閒置休眠（改成每個使用者一台共用、一直開機）
- 即時的東西全部走 WebSocket
- 腦在伺服器、每一步都經伺服器把關（需要隨時通的連線，而且不能操作使用者自己的電腦）
- PostgreSQL ＋ Kubernetes
- 對話和記憶交給另外授權的服務

## 10. 對遷移的影響（`01` 互查）

- 舊的本機資料夾 → 遷移進新版的**本機資料庫**，再同步到伺服器。
- 舊的雲端大腦（每個帳號一個容器）新版不再有；它資料卷裡的資料，在伺服器上遷移進那個帳號。
- 舊的 Bot 電腦（`anybot-box` 和它的家目錄資料卷）：直接變成這個使用者共用的 Bot 電腦。舊版本來就是一台給所有 Bot 共用。

## 11. 接外部 Agent（AnyBot 版的 AG-UI）

**目的**：讓 Claude Code（Claude Agent SDK）這類現成的 agent，在 AnyBot 裡就是一個 Bot。使用者照常在聊天裡跟它說話；它的進度和結果同步到所有裝置；它的動作照樣經過信任層、留證據。

### 11.1 AnyBot 執行事件協定

參考 AG-UI（CopilotKit 的開放協定），改成 AnyBot 自己的版本：

- **內建執行端和外部 agent 講同一套。** 伺服器和畫面不用分辨這一輪是誰在跑。
- **協定是傳輸的包裝，不是另一份內容**（`09` K119 ⑬）：紀錄流裡只有一種紀錄，一筆帶一個種類；帶任務編號的就是任務事件（`09` K113 ①）。同一件事只寫一筆。
- **事件種類**以 `10` 第 1 組 `task-events` S2 那張表為準（`09` K104）：
  - 任務：任務建立、做完的標準設定或修改、取消、停止、叫醒。
  - 一輪：一輪開始／結束、組了上下文、問模型、模型的回答（文字、思考、工具要求）、用量、換了模型、收起、開始驗收、驗收結果。
  - 動作：把關結果、要做什麼（意圖）、開始、完成、失敗、結果不知道、沒執行、對帳結果、證據。
  - 預算：預算用量、超過預算。
  - 你：卡片出現、卡片回答、裝置回報。
  - Bot 正在打的字（文字片段、思考）只走即時通道，打完才寫完整的一筆（`10` 第 5 組 `conn-batch` S2）。
- **沒有「任務狀態變更」這種事件。** 狀態由伺服器和每台裝置各自從事件算（`task-events` S3）；SSE 上可以帶一個算好的值當提示，那個值不進紀錄流。
- **傳輸跟 §4 一樣**：每個事件有編號；用 POST 送上去、用 SSE 收；斷線從編號補。
- 協定有版本號，適用 6 個月相容期（A14）。

### 11.2 轉接器

每種外部 agent 一個轉接器，跑在執行端上（使用者的電腦，或伺服器上的執行服務），負責三件事：

1. **翻譯事件**：把外部 agent 的事件翻成 AnyBot 的事件。
2. **接上信任層**：用外部 agent 自己提供的掛鉤（Claude Code 有 hooks 和權限設定），在它每個動作之前問信任層要不要放行，動作之後回報結果；證據照樣由程式自動記。
3. **提供 AnyBot 的工具**：用 MCP 把 AnyBot 的工具給它，例如保險庫填密碼、問使用者的卡片、交辦給別的 Bot、記憶、任務。

### 11.3 信任的底線

- 外部 agent 內建的工具（例如 Claude Code 自己的指令、改檔），**只有在動作之前能讓信任層把關的，才算經過把關**。
- 沒辦法把關的動作，交付報告照實標「未經把關」，不能標「已驗證」（`04` §5）。
- 可以設定讓某個外部 agent 只能用 AnyBot 提供的工具。

### 11.4 執行環境與金鑰

- 外部 agent 跑在哪，照 §2 的規則。
- **衝突**：外部 agent 自己要拿金鑰（例如 Claude Code 要登入），但它跑指令的地方也是同一個環境，這跟 A3「Bot 跑指令的地方沒有金鑰」衝突。見 D3。

### 11.5 範圍

- 第一個接 Claude Code（Claude Agent SDK）；之後再接 Codex 這類。
- 事件格式、掛鉤怎麼接，照各家官方文件確認後才寫進規格。OpenBot 的 repo（MIT）有現成的 Claude Agent SDK 轉接器，可以參考它的做法。
