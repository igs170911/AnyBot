# 04 · 產品核心

> 來源：使用者 2026-11-24 對產品的定義（原話照錄），加上對應的機制設計。
> 用途：所有設計和功能取捨的標準。盤點功能、決定留改砍、設計任何機制時，都拿這份來對。
> 互查：`02-architecture.md`（信任層、任務物件放在哪）、`05-engineering-principles.md`（寫程式時怎麼守這些原則）。

## 使用者的原話

> 「我可以把這個當成**數位同事**，完全可以**不用理他**，**主動跟進**，**主動提出證明自己做的事情是對的**，**可以信任**，這是我這個軟體最重要的地方。」

> 「所有機制就是要**使用者無感知**：我聊天跟誰聊，使用者看到的結果就是他一直都可以聊天，結果永遠都會同步，不用管現在在哪做，事情都會有人做。」

> 「可以靠工具做的就不要靠模型；可以用 code 來決定的就不要靠模型。」

## 1. 數位同事的四個性質

| 性質 | 使用者感受到的 | 需要的機制 | 放在哪一層（`02`） |
|---|---|---|---|
| **可以不理他** | 交代完就可以走開；只有真的需要時才被叫 | 只在真的有風險時才問；等你回答時先去做別的；問題集中一次問；做完才通知 | 信任層＋伺服器排程 |
| **主動跟進** | 不用追問「好了沒」 | 任務有「怎樣算做完」的標準；沒做完就自己接著做；說了要做就真的去做；到了約定的時間自己回來看 | 執行端＋伺服器排程（電腦都關著也照跑） |
| **主動證明做對了** | 不用自己去檢查 | 每個動作自動留證據；做完跑一次驗收；交付報告裡每一句「我做了 X」都連到證據 | 信任層 |
| **可以信任** | 敢把事情交給它 | 沒有證據的標「未驗證」；不確定就寫不確定；做錯能還原；`00` 的安全承諾一條不破 | 信任層＋資料 |

## 2. 確定性優先：能用程式決定的，不交給模型

任何判斷都照這個順序：

1. **程式規則**：寫死的規則、樣式比對、狀態機。
2. **程式檢查**：實際去驗證，例如看狀態碼、比對檔案雜湊、看測試的結束碼、重新讀一次頁面。
3. **模型判斷**：前兩種都做不到時才用，而且**結果要標成「模型判斷」**。

| 事情 | 由程式決定的部分 | 模型只做 |
|---|---|---|
| 核准 | 規則（樣式、動作種類）先決定；規則壞了一律拒絕 | 規則沒涵蓋的才交給模型審核，結果標「模型判斷」 |
| 證據 | 執行端從工具的**實際回傳**記錄：改了哪些檔（前後雜湊）、跑了什麼指令（結束碼和輸出）、截圖、寄給誰（信件編號）、去過哪些網址 | 模型不能新增證據，也不能改證據 |
| 驗收 | 優先用程式檢查：重開頁面確認真的送出、重讀檔案、跑測試 | 程式檢查做不到時才讓模型判斷，標出來 |
| 跟進時間 | 伺服器排程到點就叫醒 | 模型只提議時間 |
| 這一輪在哪跑、改派 | 程式規則（`02` §2） | 不用模型 |
| 秘密遮罩、截圖裡的卡號和驗證碼塗黑 | 格式比對 | 不用模型 |
| 交付報告 | 結構、步驟清單、證據連結由程式產生；每一句宣稱都要連到證據，由程式照證據標等級：已驗證／有來源支持／推論／不知道（`09` K101），沒連到的標「不知道」 | 只寫摘要文字：就是它最後那則回覆，不另外問一次（`09` K119 ②） |

**交付報告裡的每一個判斷，都標出它是怎麼來的：規則／程式檢查／模型判斷。**

**寬嚴**（`09` K25、K101）：交付報告嚴格，每句宣稱都要連到證據，程式照證據標四個等級，沒連到的標「不知道」；一般聊天寬鬆，只把明顯跟步驟對不上的標「未驗證」，免得滿畫面都是標記。 使用者一眼就知道哪些可以直接信、哪些要自己看一下。

## 3. 任務是一級物件

「任務」是資料庫裡獨立的東西，不只是一段聊天。聊天是任務的對話，不是反過來。

| 欄位 | 說明 |
|---|---|
| 目標 | 要做成什麼 |
| 做完的標準 | **盡量寫成程式能檢查的條件**（檔案存在、測試通過、頁面出現某段字、信件已送出） |
| 狀態 | 八種主狀態：進行中／等你／卡住／完成／未驗收／失敗／已取消／已停止。「完成」底下再標細項：你已確認、已交付、已驗收、已回覆。未驗收是自己的主狀態，只是誠實的標記，不需要使用者做任何事（`09` K32、K100；`10` 第 1 組 `task-state`） |
| 誰在做、在哪跑 | 哪個 Bot、哪台電腦（底層用，預設不打擾使用者） |
| 下次跟進 | 時間，由伺服器排程 |
| 證據清單 | 只往後加，跟對話一起同步 |
| 交付報告 | 有動手或有標準的任務，到了完成、未驗收、失敗時產生；每句宣稱連到證據，標等級（已驗證／有來源支持／推論／不知道，`09` K101）和判斷來源 |

一個 Bot 的腦由九個模組組成（執行迴圈、上下文編譯器、模型閘道、狀態引擎、大腦、證據與信任、技能、學習與整理、政策與評估；`09` K93），地圖在 `02` §0.3。

## 4. 用這份文件做取捨

盤點功能時，每條功能都標出它服務的是哪一條：**不理他／跟進／證明／信任／都不是**。

- 服務這四條的，是核心，要做得最好。
- 標「都不是」的，優先考慮砍或延後。
- 舊版 feature-map 的 claims、goal、tasks、autonomy、replay 這幾區直接對應這四條，盤點時排最前面、看最仔細。

## 5. 接進來的外部 agent 也一樣

Claude Code 這類接進來的外部 agent（`02` §11），同樣要守 §1、§2：

- 動作經過信任層，證據由程式自動記。
- **沒經過把關的動作，交付報告照實標「未經把關」，不能標「已驗證」。**
- 使用者在畫面上看不出、也不用管這個 Bot 是內建的還是接進來的，但看得到它的每個判斷是怎麼來的。
