# 01 · 資料清單（遷移的輸入）

> 來源：看過舊版的一方盤點 OLD 實際寫到磁碟、鑰匙圈、Docker、帳號伺服器上的資料（2026-11-24 初稿）；只記位置、格式、內容，**不含舊程式結構**。
> 用途：資料遷移的範圍。新版的資料格式可以全新，但這裡列的「搬」都要能完整轉過去、意思不變。
> 互查：`00-boundaries.md` 的 B11、B12、B13、B16 與待決定 Q1–Q5。

## 狀態

- 這是**初稿**：只列了位置、格式、內容大類、分類。
- 欄位級格式已拆到 `01a-data-state.md`（`state.json`、聊天檔）和 `01b-data-files.md`（其他所有資料）。
- 標「待確認」的，是用途或結構還沒核對清楚的。

## 分類

- **搬**：一定要轉進新版。
- **重建**：新版自己重新產生，不用搬（快取、索引、下載的模型）。
- **丟**：不搬（暫存、鎖、過期紀錄）。
- **原地**：本來就是使用者的檔案，不是 AnyBot 的格式，留在原處給新版用。
- **待決定**：要你決定。

## A. 本機資料夾的位置

| 平台 | 位置 |
|---|---|
| macOS | `~/Library/Application Support/AnyBot/` |
| Linux | `~/.local/share/AnyBot/`（有設 `XDG_DATA_HOME` 就在那下面） |
| Windows | `%APPDATA%\AnyBot\` |

可以用環境變數 `ANYBOT_DATA_DIR` 改到別的地方；命令列 `--data-dir` 只有「問一輪」（`--ask`）認得（`03b` Q11 更正）。伺服器映像固定用 `/data`。遷移工具要問使用者資料夾在哪，或照這幾個位置找。以下簡稱「資料夾」。

#### B1. `state.json` 的內容大類

- **全域**：外觀（主題、強調色、對比、密度、動畫、語言）、側邊欄、時區、通知與提示音、語音設定。
- **模型**：各供應商的設定、嵌入模型的選擇。
- **權限與安全**：本機執行、直接操作模式、自動審核與規則（允許／詢問）、一律放行、聰明模式與逾時、送出前檢查與規則、訊息不問。
- **連接**：遠端電腦清單、帳號與遠端設定、機器名稱、訊息頻道、MCP 伺服器。
- **內容**：技能清單、關於你、頁面、工作流、改善建議（含每日／每週報告設定）、文件資料夾、資料夾與釘選順序。
- **每個 Bot**：
  - 名字、描述、指示、個性（Soul）、強項、不適合做的事、外觀
  - 供應商、模型、步驟模型、備援模型、思考強度、脈絡上限
  - 工作資料夾、允許規則、群組成員、記憶
  - 語音設定、教學示範
  - 例行任務、追蹤事項、任務事件、目標、計畫
  - 預設電腦、可用技能、能力與電腦、團隊、分支
  - 草稿、重新產生的還原、上一輪的結算
- **分支 Bot**：另外一份 Bot 清單。

## F. 遷移規則（草案）

1. **在使用者自己的電腦上跑**：需要開鑰匙圈。舊資料遷移進新版的本機資料庫，再同步到伺服器（`02` §10）。**雲端大腦例外**：它的保險庫鑰匙放在自己資料卷裡的 `/data/vault.key`，伺服器解得開，所以可以直接在伺服器上遷移（`01b`）。
   - **鑰匙要每個位置都找**：所有秘密共用一把鑰匙，可能在系統鑰匙圈、`vault.key`，或環境變數指定的路徑。
   - **SQLite 要連 `-wal`、`-shm` 一起複製**，複製完才打開；不然最近寫入的記憶會不見。
   - **聊天裡的附件是用絕對路徑記的**，遷移時要改寫成新位置。
   - **雲端大腦的技能可能在資料卷外面**（容器裡的 `/skills`），容器重建過就可能已經不見；`/skills` 和 `/data/skills/` 兩處都要找。
   - Bot 電腦的秘密、帳號伺服器的兩步驟驗證秘密，舊版是明文存的。新版要加密存。
   - `state.json` 裡也有明文的秘密：Linear 觸發的 `apiKey`、webhook 的 `secret`；`brain-copy.json` 裡有螢幕電腦自己的帳號金鑰（`01a`）。新版一律加密。
   - **舊版讀檔很嚴格**：少了必填欄位、或遇到不認得的列舉值，整份檔案就被移到旁邊、從空的開始。遷移工具要**逐欄容錯**：讀不懂的欄位列進遷移報告，不能整份放棄。
   - **時間單位混用**：有的是毫秒、有的是秒（例行任務、工作流是秒），遷移時統一。
   - **同一個供應商有四種寫法**（`OpenAi`、`openai`、`openai/<model>`、`openai:<model>`），遷移時統一成一種。
   - 聊天檔寫失敗時，舊版會把所有聊天塞回 `state.json`：`chats/` 和 `state.json` 兩處都要讀。
   - **webhook 網址綁著例行任務、工作流的編號**：新版不保留舊編號，也不轉址（`09` R3）。遷移報告要列出每個 webhook，提醒使用者到外部服務換成新網址。
   - **Bot 的記憶同時存在 `state.json` 和 `memory.db`**：遷移時合併、去重。
2. **遷移前**：所有 Bot 閒置；裝置傳檔送完；Bot 的電腦沒有在重建或更新。遷移工具要先檢查，不符合就停下來說原因。
   - **帳號搬、登入不搬**（`09` K10）：使用者名稱和密碼雜湊搬；登入工作階段、裝置身分、配對資料不搬。升級後每個人重新登入、重新配對裝置。
   - **讀不懂的逐欄救回**（`09` K12）：能讀的欄位都搬，讀不懂的列進遷移報告。
3. **舊資料夾唯讀、原封不動**（決定 8）：新版寫到自己的位置，遷移失敗可以直接退回 OLD。
4. **只吃 OLD 最後一版的格式**（決定 4）：使用者先升到 OLD 最後一版並開過一次。例外：技能的舊位置 OLD 不會搬，遷移工具要自己掃。
5. **產出遷移報告**：搬了什麼、丟了什麼、壞檔有哪些、哪些沒搬成功。
6. **驗收（黑箱）**：拿一份真實的舊資料夾跑遷移，新版裡看到的下列內容要跟 OLD 一樣：
   - Bot 清單與每個 Bot 的設定
   - 目前的聊天、過去的對話
   - 記憶的筆數與內容
   - 保險庫項目數
   - 技能、例行任務、工作流、頁面
   - 用量統計
