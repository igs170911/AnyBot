## 1. 訊息管道（channels）

### channels-kinds 管道種類

- 決定：改（`09` K42）　服務：不理他　邊界：B1、B2、B10
- 行為：
  - S1 設定 › 整合 ›「訊息管道」›「新增管道」只列 **Slack、Discord、Telegram** 三種。
  - S2 管道由伺服器上的頻道轉接收發：U 所有的電腦都關著，頻道來的訊息照樣收、照樣回。
  - S3 頻道來的一輪照 `02` §2 算「不是從電腦發起的」，在 Bot 的電腦（伺服器的執行服務）跑；Bot 用本機或區網模型時照 `models-n9`。
  - S4 從舊版遷移來的 Teams、「訊息」、「郵件」、簡訊（Twilio）、X 管道：設定和 Token 照搬、保持關閉，在「已連接」裡那一列寫「新版還沒支援這種管道，設定已保留」，開關打不開。
- 永遠成立：頻道收發只在伺服器上做，不需要任何一台使用者的電腦開著。

### channels-manage 管理管道

- 決定：改（`08` 建議：手機也能新增；狀態由伺服器回報）　服務：不理他　邊界：B1、B2、B10、B11
- 行為：
  - S1 桌面和手機都能新增。點一種才打開表單：名稱、回覆的 Bot、Token、頻道或聊天 ID；表單下面寫這一種去哪拿 Token、要開哪些權限。先按「測試 Token」：通了寫「已連上 Telegram：@{Bot 帳號}」（Slack 寫「已連上 Slack：{工作區}」，Discord 寫「已連上 Discord：{Bot 名稱}」）；不通寫平台回的原因，「新增」按不下去。
  - S2 Token 送到伺服器加密保存。之後任何前端都只看得到「已設定」；Token 不出現在畫面、紀錄檔、模型的請求裡。
  - S3「已連接」每列：「名稱 · 種類」、「{Bot} 回覆」、狀態（連線中…／已連上，等待新訊息／收到 N 則／已暫停／紅字錯誤原因）、開關、「⋯ › 移除這個管道」。狀態由伺服器回報，桌面和手機看到同一個，變了就即時更新。
  - S4 開關關掉：狀態「已暫停」，之後頻道來的訊息不收、不回；再打開從打開那一刻起收，暫停期間的不補。
  - S5 移除：先問「移除這個管道？」；確定後不再收、不再回，伺服器上的 Token 刪掉。
  - S6 改名稱、Token 或頻道 ID：伺服器用新的設定重新連，不用重開任何東西。
  - S7 開關或移除一個已經不存在的管道（例如別台剛移除）：回「找不到這個管道」。
- 永遠成立：Token 只在伺服器的頻道轉接裡解開，不進任何前端、Bot 的電腦和模型的請求。
- 測試：

### channels-poll 怎麼收

- 決定：改（`09` K42、R52）　服務：不理他　邊界：B10、B15
- 行為：
  - S1 伺服器用平台的推送收：Slack、Discord 用平台的長連線；Telegram 用長輪詢（一次等 25 秒），伺服器有對外的 https 網址時改用平台的 webhook。
  - S2 從管道連上那一刻起算；連上之前的舊訊息不回。
  - S3 Slack、Discord 上別的 Bot 和自己發的訊息不理；Slack 訊息裡點名這個 Bot 的「@Bot」先拿掉再交給模型。
  - S4 Telegram 只收文字；照片、貼圖、語音不開一輪。
  - S5 平台說太頻繁：照它給的秒數等（1–300 秒）再繼續，訊息不丟。
  - S6 連線斷了：伺服器自己重連，第一次等 5 秒，之後每次加倍、最多 300 秒；重連期間狀態「連線中…」。
  - S7 伺服器停機（`09` R52）：恢復後，平台還留著的訊息補收，最多補停機前 24 小時內的；每則照原本的順序各開一輪，聊天裡那則標「（伺服器停機期間收到，HH:MM）」，模型收到的請求也帶這個時間。平台不給補、或超過 24 小時的，在回覆的 Bot 的聊天留一行「伺服器停機期間，{管道名稱} 可能有訊息沒收到。」
- 測試：

| 編號 | 種類 | 前提 | 步驟 | 預期 |
|---|---|---|---|---|
| T-channels-poll-1 | 整合 | 假 Telegram 已經有一則「舊的」 | 新增 Telegram 管道；頻道送進「新的」 | 只有「新的」開了一輪；假頻道沒有回「舊的」 |
| T-channels-poll-2 | 整合 | Slack 管道已連上 | 頻道送進「hi」（來自另一個 Bot）；頻道送進「hi」（來自這個 Bot 自己）；頻道送進「@小幫手 幫我查天氣」（來自 Alice） | 只開了一輪；模型收到的請求包含「幫我查天氣」、不包含「@小幫手」 |
| T-channels-poll-3 | 整合 | Telegram 管道已連上 | 頻道送進一張照片（來自 Alice）；頻道送進一張貼圖 | 沒有開任何一輪 |
| T-channels-poll-4 | 整合 | 假 Discord 送出時回「太頻繁，30 秒後再試」 | 頻道送進「hi」；假模型：回「好」；時間快轉 29 秒；時間快轉 2 秒 | 29 秒時假頻道還沒記下送出；31 秒時記下送出「好」 |

### channels-queue 每則訊息自己一輪

- 決定：留（`08` 建議：由伺服器排隊）　服務：信任　邊界：B10
- 行為：
  - S1 Bot 正在跑任何一輪（使用者自己的、例行任務、另一則頻道訊息）時，頻道來的訊息排隊，不混進正在跑的那一輪；空下來後照伺服器收到的順序，每則各開新的一輪。
  - S2 使用者在聊天裡插話，不會混進頻道開的那一輪（插話規則見第 3 組 `chat-steer`）。
  - S3 每人同時回合數上限（`06` S7）滿了：頻道訊息照樣排隊，不丟。
- 永遠成立：每則頻道訊息剛好開一輪，照收到的順序。
- 測試：

| 編號 | 種類 | 前提 | 步驟 | 預期 |
|---|---|---|---|---|
| T-channels-queue-1 | 整合 | 假模型第一步呼叫一個要跑 10 秒的指令 | 在桌面送「A」；工作中頻道送進「X」 | 「A」那一輪模型收到的請求不包含「X」；那一輪結束後開新的一輪，第一個請求包含「X」 |
| T-channels-queue-2 | 整合 | 頻道開的一輪正在跑（第一步要跑 10 秒） | 在桌面送「插話」 | 頻道那一輪模型收到的請求不包含「插話」；之後另開一輪回「插話」 |
| T-channels-queue-3 | 性質 | 兩個管道對同一個 Bot | 隨機產生 1,000 組「頻道送進／使用者送／例行任務到點」的先後順序 | 每則頻道訊息剛好出現在一輪的第一個請求裡，順序跟伺服器收到的一樣；沒有一則混進別的一輪 |
| T-channels-queue-4 | 整合 | 管理員把 U 的同時回合數上限設成 1；有一輪正在跑 | 頻道送進「1」「2」「3」 | 三則都依序各開一輪，沒有一則被丟 |

### channels-reply 回覆

- 決定：留（`08` 建議）　服務：不理他　邊界：B10
- 行為：
  - S1 一輪做完，把 Bot 這一輪**最後一則文字回答**傳回原處：Slack 回在那則訊息的討論串（一則最多 39,000 字）；Discord 引用原訊息（一則最多 2,000 字）；Telegram 引用原訊息（一則最多 4,096 字）。超過上限就照順序切成幾則，每則都不超過。
  - S2 這一輪出錯結束：回「抱歉，這次沒有完成，請再試一次。」
  - S3 擁有者按停止：不回。
  - S4 只傳文字：Bot 的檔案、卡片、頁面只留在 AnyBot 的聊天裡，不傳到頻道。
  - S5 看進度（`09` K43）：開始做這則訊息的 3 秒內，在原訊息上標「處理中」（Slack、Discord 在原訊息加 👀 反應；Telegram 顯示「正在輸入」，每 4 秒續一次）；回覆送出後拿掉。還在排隊時不標。
- 測試：

| 編號 | 種類 | 前提 | 步驟 | 預期 |

### channels-untrusted 外面的人不受信任

- 決定：留（`00` 硬契約「外部訊息不受信任，不帶核心記憶」；`09` K43）　服務：信任　邊界：B8、B10
- 行為：
  - S1 頻道開的一輪，模型收到的請求不帶核心記憶、跟著訊息帶的記憶、「關於你」；請求裡註明傳訊的人不是擁有者。
  - S2 工具清單拿掉：App 操作工具（記憶、例行任務、設定、連接器管理、hooks、頁面、任務、ChatGPT 登入…）、文件搜尋、AnyBot 瀏覽器（公開網頁照樣用讀網頁的工具）、保險庫、Mac App、連接器、`ask_person`、`send_to_device`、`open_for_person`、`publish_site`、`replay_skill`；使用者電腦的工具和「在這台電腦上執行」當作沒開。
  - S3 擁有者的「一律允許」、直接操作、自動審核、智慧模式、一律放行都不算；要核准的照 `channels-unattended`。

- 永遠成立：頻道開的一輪一律不受信任，不管傳訊的人是誰（`09` K43）。判斷來源：規則（看這一輪是誰發起的）。

### channels-unattended 等核准時（頻道不能按允許）

## 2. 連接器（connectors，MCP）

### connectors-local 指令型連接器

- 決定：改（`09` K44）　服務：都不是（`02` A18 的工具介面）　邊界：B9、B10
- 行為：
  - S1 新增指令型連接器：填指令（例如 `npx -y …`、`uvx …`）、環境變數，和「在哪台電腦跑」。預設是使用者現在用的這台電腦；也可以選帳號裡的其他電腦，或「Bot 的電腦」。
  - S2 選「Bot 的電腦」：下面明寫「這個連接器的金鑰（環境變數、密碼、登入權杖）會放進 Bot 的電腦，Bot 在那台跑的指令讀得到。」，要使用者自己勾「我了解，放進 Bot 的電腦」才存得了。Bot 用 `manage_connectors` 不能選 Bot 的電腦，回「要在 Bot 的電腦跑，請使用者到 設定 › 整合 › 連接器 自己打開」。
  - S3 連接器在指定的那台啟動；第一次啟動要下載時，狀態寫「連線中…（第一次要下載，可能要一分鐘）」。缺 Node.js、uv 等照 `connectors-n2`。
  - S4 一輪拿得到它的工具，只有這一輪就在那台跑的時候（`02` A4：一個任務只在一台）。在別台跑的一輪，工具清單裡沒有它；Bot 的指示裡列「在〔電腦〕上才能用的連接器：〔名稱〕」，要用就交辦一個任務到那台（`09` K64）。
  - S5 那台不在線：狀態「〔電腦〕不在線」；那台上線後自己連上。
- 永遠成立：AnyBot 自己的金鑰（模型金鑰、帳號）絕不因為連接器進到 Bot 的電腦；只有使用者自己打開「放進 Bot 的電腦」，這個連接器自己的秘密才會進去。

### connectors-remote 網址型連接器

  - S5 舊式 SSE 連線不支援：狀態寫「舊式 SSE 連線，AnyBot 還不支援」。

### connectors-oauth 用帳號登入（OAuth）

- 決定：改（`08` 建議；`02` §5、A9）　服務：都不是　邊界：B10、B11
- 行為：
  - S1 網址型連接器回 401（或要求登入的 403）、又沒填金鑰：狀態「這個連接器要先登入帳號（OAuth）：在聊天裡請 Bot 幫你登入，或在 設定 › 整合 › 連接器 按「登入」」；填了金鑰則說「金鑰不對或過期」。
  - S2 登入照 MCP 的授權規格（至少支援 2025-06-18 版）：找連接器的資源說明、找登入伺服器的說明、自己註冊成「AnyBot」、PKCE（S256）、resource 指到連接器網址。登入伺服器不讓 App 自己註冊或不支援 PKCE：照實說「這個連接器的登入伺服器不讓 AnyBot 自己註冊（或不支援 PKCE），登不進去。」
  - S3 登入後瀏覽器回到哪：伺服器有對外 https 網址 → 回到伺服器；沒有，而且是從桌面按的 → 回到那台桌面的本機網址（`http://127.0.0.1:<臨時埠>/callback`）；都不行（例如手機配 http 伺服器）→ 畫面請使用者把登入後那頁的網址整個貼回「完成登入」欄或聊天。回到的小網頁寫「已登入「X」，可以關掉這頁」；連接器馬上重連，聊天寫「已登入連接器「X」，正在連線。」。登入最多等 10 分鐘；登入網址只能用一次。
  - S4 桌面和手機都有「登入」「重新登入」鍵（舊版手機沒有）。
  - S5 權杖加密存在伺服器，只交給跑這個連接器的執行端，只送往登入當時的網址；不進手機、不進 Bot 的電腦、不進模型的請求。

  - S7 登出先問「登出連接器「X」？」。

### connectors-password 帳號、密碼

- 決定：留（`08` 建議）　服務：都不是　邊界：B10、B11
- 行為：
  - S1 「帳號」「密碼」兩欄。指令、環境變數、網址或標頭裡寫了「{username}」「{password}」就填在那裡。

## 4. 保險庫（vault）

### vault-kinds 三種項目

- 決定：留（`08` 建議）　服務：信任　邊界：B1、B2、B11
- 行為：
  - S1 登入資訊：網站最多 10 個（子網域也會填）、使用者名稱（最多 512 字）、密碼（最多 4,096 bytes）、提示（最多 2,000 字）。
  - S2 卡片：卡號（12–19 位、檢查碼要對；自動認卡別 Visa、Mastercard、American Express、Discover、JCB、UnionPay、Diners Club，認不出寫「卡片」）、有效期限、安全碼（3–4 位）、持卡人、暱稱、帳單地址（可以用聯絡資訊的地址）、提示。
  - S3 聯絡資訊：姓名、地址、電話和電子郵件（各最多 10 個，可以設主要的）、標籤、提示。「提示」是寫給 Bot 的：什麼時候用這一筆。
  - S4 畫面：設定 ›「保險庫」右上「新項目」、分頁「全部／登入資訊／卡片／聯絡資訊」帶數量、「搜尋保險庫」、每筆「編輯」「移除」。桌面和手機都能管理（新版保險庫存在伺服器，手機也是完整前端）。
  - S5 密碼一律顯示 ••••，沒有顯示或複製鈕；編輯時密碼留空＝不變。卡號存好後鎖定、安全碼不能再看；同一張卡號不能存兩次（「這張卡已經存過了」）；要改卡號就移除再新增。

### models-n9 本機或區網模型的 Bot 在連得到的電腦上跑

> **以 `09` 為準**：S5 的雲端備用只有在使用者自己把那家加進這個 Bot 的資料政策時才用（`models-egress` S3、`09` K109 ④）；從舊版搬來、本來就設了雲端備用的，照使用者原本的選擇把那家加進政策。

- 行為：

### models-normalize 各家的回應整理成同一種格式

- 決定：新增（`09` K102：核心資料用中立格式；使用者 2026-11-25 定的：各家的怪格式在接頭整理掉，有工具呼叫就算工具呼叫，非標準的 `reasoning` 欄位算思考）　服務：信任　邊界：B7、B8
- 行為：
  - S1 執行端交給模型閘道的是同一種中立的請求：系統說明、訊息（你的、Bot 的、工具結果）、工具清單、思考模式、這一步最多輸出多少。閘道照那家的格式翻成請求：Claude 用 Claude 的格式，其他用 OpenAI 相容格式，OpenCode Go 照每個模型（`models-providers` S4、`models-capabilities` S1）。模型能串流就一律用串流。
  - S2 每家的回應都整理成同一種中立的結果：文字、思考、工具呼叫（編號、名稱、參數）、用量、結束原因、那家的原生內容（S7）。同一個回答，串流和不串流整理出來的一樣。
  - S3 結束原因只有五種：說完了、要用工具、到長度上限、拒答、中斷。照下面判斷，不照各家寫的字面：
    - 有完整的工具呼叫 → 要用工具，不管 `finish_reason` 寫什麼（例如本機模型伺服器呼叫工具時寫 `stop`）。
    - 說要用工具（`tool_calls`、`tool_use`）卻沒有任何工具呼叫 → 說完了。
    - 到長度上限（`length`、`max_tokens`）→ 到長度上限；這時沒寫完的工具呼叫不交出去。
    - Claude 的拒答結束原因 → 拒答（`models-n2` S2）。
    - 串流沒有正常結束（連線斷了、沒有結束標記）→ 中斷：已經收到的文字和思考留著；工具呼叫一律不交出去，那一步的工具不執行（`models-chatgpt` S5 對每一家都成立）。
  - S4 思考：Claude 的思考區塊、OpenAI 相容格式裡非標準的 `reasoning` 欄位（本機模型伺服器用的），都放進結果的「思考」。思考不算回答的文字：只有思考、沒有文字也沒有工具呼叫，算回了空白（`models-n1` S4 再問一次）。
  - S5 工具呼叫：
    - 串流裡分好幾段送來的參數，照編號接起來，收完整才交出去。
    - 同一個回答裡有好幾個工具呼叫，照收到的順序交出去。
    - 那家沒給呼叫編號 → 閘道照順序給一個，同一個回答裡不重複。
    - 參數不是合法的 JSON → 這個呼叫標「參數壞了」，帶著原本的字交給執行端，由執行端回給模型；閘道不猜它的意思、不重試。
  - S6 那家多送的欄位（例如本機模型伺服器的 `kv_transfer_params`、`token_ids`、`metrics`）一律略過，不算錯誤，也不存進任務狀態。每次只要一個回答。
  - S7 原生內容（`09` K102、K13）：要「原樣送回」的東西（例如 Claude 帶簽章的思考區塊、被遮住的思考區塊）存成附件，記下是哪一家、哪個模型。
    - 只有下一個請求是**同一家、同一個模型**時，才原樣、逐位元送回。
    - 別家、同一家的別的模型，一律不送（`models-switch` S3）。
    - 原生內容不是任務狀態：把附件全部拿掉，任務狀態算出來一樣。
  - S8 用量整理成同一種：輸入總數（含快取讀到和快取寫入）、其中快取讀到、輸出、其中思考。串流時照那家的方法要用量（例如 OpenAI 相容的 `stream_options.include_usage`）。那家沒回用量 → 記「沒有」，不填 0。
  - S9 對話紀錄裡的工具呼叫和它的結果用中立格式存。送給某一家時照那家的規則翻譯（例如呼叫編號能用哪些字），同一個呼叫和它的結果翻出來的編號一樣。
- 永遠成立：正常結束、有完整工具呼叫的回答，一定交出工具呼叫；沒有正常結束的回答，一定不交出工具呼叫；一家的原生內容只送回同一家、同一個模型。判斷來源：規則。

### models-errors 錯誤怎麼分類

    1. 內建表：各家的建議模型（`03c` §13），上線前照當時的官方文件填。
    2. 取得模型清單時那家有回的（例如可讀長度）。

  - S7 估算由程式算：同樣的內容、同樣的校正狀態，一定得到同一個數字（`chat-stall` S1 用的就是它）。
  - S8 估算加上安全邊際超過 S4 的數字，閘道就不送出，回「上下文預算不夠」（`09` K95），不截斷、不讓那家自己截。

### models-handoff 做到一半換模型

- 決定：新增（`09` K104；補 `models-switch` S2、S3，`models-fallback` S2）　服務：信任、不理他　邊界：B7、B8
- 行為：
  - S1 會換模型的情況：
    - 你在 ＋、Bot 設定、手機換（`models-switch`）。
    - Bot 用 `update_my_profile` 換，你按了允許（`models-bot` S3）。
    - 備用模型（`models-fallback`）。
    - 本機模型連不到，改用你設的備用（`models-n9` S5）。
  - S2 只在**安全的步驟邊界**換：
    - 正在問的模型照舊把這次回答收完，不在回答到一半切。
    - 這一步的工具都做完、留好收據（`task-events`）；有「結果不知道」的動作，先照 `task-effects` S2 處理完。
    - 下一次問模型才用新的。不用等這一輪結束（取代 `models-switch` S2）。
    - 備用模型：失敗的那一次沒有任何結果（`models-n1` S3），所以那裡就是邊界，從同一步接著做。

### models-egress 資料只送到准許的地方

- 決定：新增（`09` K102、R44；補 `models-where`、`models-n9`，取代 `goal-judge` S2）　服務：信任　邊界：B7、B8
- 行為：
  - S1 每個 Bot 有一個資料政策，說它的資料（對話、檔案內容、截圖、工具結果、記憶）可以送到哪裡：
    - 「只送本機和區網」：只准送到 `models-where` 分成本機或區網的網址。
    - 「也可以送雲端」：本機、區網，再加上你勾的那幾家雲端供應商。
  - S2 預設：Bot 的模型是本機或區網的 → 只送本機和區網；是雲端的 → 也可以送雲端，只勾 Bot 自己那家。

  - S6 不在政策裡的備用模型跳過，聊天寫「跳過 ○○：「{Bot}」的資料只送本機和區網。」（或「…只送到你准許的供應商。」）

### agent-ext-protocol AnyBot 執行事件協定

- 決定：新增（`02` A17、§11.1；`00` B17）　服務：證明、信任　邊界：B5、B17
- 行為：
  - S1 內建執行端和外部 agent 的轉接器送同一套事件：回合開始、回合結束、文字片段、思考摘要、工具呼叫開始、工具呼叫結果、要核准（卡片）、證據、任務狀態變更、錯誤。伺服器和畫面不分辨這一輪是誰在跑：聊天、步驟、思考、卡片、任務長得一樣。
  - S2 每個事件帶：協定版本、這一輪的 ID、產生它的那一端給的全域唯一 ID；伺服器收到時給一個遞增編號。
  - S3 傳輸跟 `02` §4 一樣：用 POST 每 0.2–0.5 秒送一批上去，每批帶 Idempotency-Key；用 SSE 收；斷線從「最後看到第 N 號」補。同一個事件 ID 送兩次只記一次。
  - S4 正在打的字只走即時通道，步驟完成才寫進紀錄（`06` S6）。斷線重連後，做完的步驟全部補得回來；斷線那一刻打到一半的字，以步驟完成時的完整內容為準。
  - S5「證據」事件只能由執行端或轉接器的程式，從工具的實際回傳產生；模型或外部 agent 自己說的話、自己送的證據事件都不算證據（`04` §2）。

- 永遠成立：同一輪的紀錄編號連續、沒有重複；每個步驟剛好記一次。

### agent-ext-gate 信任層掛鉤

- 決定：新增（`02` §11.2 第 2 件、§11.3、A15；`09` K26、K27、K29）　服務：信任　邊界：B9、B17
- 行為：
  - S1 外部 agent 每個動作之前，轉接器用 agent 自己的掛鉤（Claude Code 有 hooks 和權限設定）問信任層：直接做、先問、或拒絕。跟內建 Bot 走同一套順序和規則（第 2 組 `safety-gates`）：內建底線 ＞ 管理員 ＞ 使用者 ＞ 預設（`09` K29）。
  - S2 先問：核准卡出現在 App 和手機，寫「{Bot} 想 {動作}」，回答照 `09` R10；答案回到 agent，允許了才做。
  - S3 拒絕：動作不做；agent 收到「使用者拒絕了這個操作」或規則擋下的原因；畫面寫「被安全規則擋下：…」。
  - S4 一律允許（`09` K27，所有 Bot 共用）、直接操作、一律放行對外部 agent 的 Bot 一樣有效；內建底線（私密檔、危險指令）誰都蓋不過。
  - S5 動作之後轉接器回報結果，證據由程式從實際結果記：改了哪些檔（前後雜湊）、指令的結束碼和輸出、去過的網址。
  - S6 掛鉤問不到信任層（例如執行端出錯）：一律拒絕這個動作（`02` §5.3：規則壞了一律拒絕）。
  - S7 不受信任的一輪（頻道訊息）交給外部 agent 的 Bot：照 `channels-untrusted` 拿掉 AnyBot 的工具，agent 內建的工具全部由掛鉤拒絕；這個 agent 有動作前擋不住的內建工具時，不啟動，回頻道「這個 Bot 沒辦法安全地回覆外部訊息。」

### agent-ext-ungated 「未經把關」

- 決定：新增（`04` §5、`02` §11.3）　服務：證明、信任　邊界：B1、B2、B17
- 行為：
  - S1 轉接器宣告每個工具有沒有動作前的掛鉤；沒有的列在 Bot 設定的「不能把關」清單（`agent-ext-setup` S2）。
  - S2 沒有動作前掛鉤的動作：事後由轉接器回報，程式照實記證據，標「未經把關」；聊天裡那一步也標「未經把關」。
  - S3 交付報告裡連到這種證據的宣稱，標「未經把關」，不能標「已驗證」（就算結果看起來對）；判斷來源照樣寫。
  - S4「只能用 AnyBot 提供的工具」：agent 啟動時能關掉的內建工具全部關掉；有關不掉又擋不住的，這個開關打不開，寫「這個 agent 有擋不住的內建工具：{清單}」。
- 永遠成立：連到「未經把關」證據的宣稱，永遠不會標「已驗證」。
