# 10 · 行為規格與測試清單

> 來源：`08-features/`（功能清單）、`09-decisions.md`（決定）、`02`、`04`、`00`（架構、產品核心、安全承諾）；細節可以參考 OLD 的**行為文件**（feature-map、FEATURES.md、MECHANICS.md、SECURITY.md），**不讀 OLD 的程式碼和掃描筆記**。
> 用途：新版每條功能「從外面看應該怎樣」的規格，加上能自動跑的黑箱測試清單。寫程式的人只看這份和 `00`–`09`。
> 互查：`08-features/`（每條的來源和編號）、`09`（決定以它為準）、`05`（「完成」的定義：關卡全綠＋對應測試通過）。

## 原則

1. **寫新版的行為，不是舊版的。** `08` 標「留」的照舊版行為寫；標「改」的照 `09` 和 `02` 的新設計寫；**`09` 跟 `08` 的建議欄不一致時，以 `09` 為準。**
2. **只寫從外面看得到的**：使用者做什麼、看到什麼、留下什麼結果、模型收到什麼。不寫怎麼實作。
3. **數字要寫出來**：上限、逾時、天數、筆數。
4. **每條規格都要對到至少一個測試**（`05` 的功能追蹤表檢查會擋）。
5. **測試用「動作」寫，不用 API 路徑和畫面元素寫**：新版的 API 和畫面都會重做（`00` 決定 2），測試要靠下面的動作詞彙，由測試驅動程式翻成實際操作。

## 測試動作詞彙

各組測試只用這一份詞彙（2026-11-24 整合時把六組各自補的寫法併進來，見檔尾「整合紀錄」）。〔〕是要填的值，「」是畫面上或模型收到的字。

**「」裡的中文怎麼讀（`09` K91）**：畫面、命令列、推播上的字，是那則訊息的繁體中文翻譯；程式和測試裡只用訊息代碼，測試照代碼比對，不寫中文字面。送給模型、頻道的範例內容（例如送「hi」、回「好」）是測試資料，測試可以換成英文。

**模型閘道的整合測試**（`models-*`，`09` K109 ⑪）：環境動作另外有「假模型用〔openai／vllm／Claude〕格式」「假模型：先想「…」再回「…」」「假模型：回用量〔…〕」「假模型：結束原因〔…〕」「假模型：回錯誤〔HTTP 碼〕（說明「…」、Retry-After N 秒）」「假模型：串流裡回錯誤〔忙／其他〕」「〔網址〕經代理對到假模型」「假模型：回 302 轉到〔網址〕」；觀察點另外有「閘道交出的結果是〔…〕」：模型閘道交給執行端的中立結果（文字、思考、工具呼叫、結束原因、用量、原生附件、錯誤類別和訊息代碼）。這個觀察點只給新寫的 `models-*` 段落用；原本預期寫「畫面出現」「任務狀態＝」的，要等有完整路徑（M7、M8）才算驗到，不能只在閘道這一層就算覆蓋（`09` K86）。

### 環境

所有測試都在**隔離環境**跑：假模型、假時鐘（可以快轉）、假推播、假聊天頻道、本機的伺服器、本機的 Bot 電腦；不碰真的帳號、金鑰、使用者的資料。隔離環境裡的本機 Bot 電腦用正式映像，跑得了指令、檔案、桌面、瀏覽器（只連假網站），但時間是假時鐘。要使用者**真的** Mac／Linux 桌面、真的系統權限、真的叫醒秒數、gVisor、Mac 上真的 App、真的 Docker 或 iPhone 畫面的，種類標「實機」。

隔離環境裡的假東西：

| 假東西 | 意思 |
|---|---|
| 假模型 | 照腳本扮演模型，記下收到的每個請求 |
| 假時鐘、假推播、假聊天頻道 | 假聊天頻道有 Slack、Discord、Telegram 三種（`09` K42），記下 AnyBot 送出去的每則訊息 |
| 假電腦端（宣告成〔Mac／Linux／Windows／沒有指令沙盒…〕） | 扮演某一種電腦的執行端，用電腦介面的能力宣告做出來（`00` B18），照腳本回應操作，用來測規則和流程；不用真的 Windows |
| 假網站 | 扮演公開網站的本機網站，瀏覽器和讀網頁工具都把它當成公開網址 |
| 假外部服務〔GitHub／Slack／Linear／Sentry／PagerDuty／郵件…〕 | 扮演事件觸發的來源（B10） |
| 假連接器 X | 測試用的網址型 MCP 伺服器，有 `echo`（照原樣回傳參數）、`post`（假裝發文）、`del`（假裝刪除）三個工具，記下收到的每個請求。「假指令連接器 Y」是同樣的工具、用指令啟動 |
| 假外部 agent | 照腳本發「AnyBot 執行事件」的外部 agent（`02` §11），可以宣告哪些工具有動作前掛鉤、能不能轉發金鑰、協定版本。它問模型的請求經執行端轉發到假模型，所以「假模型：呼叫工具 …」就是它這一步要做的動作。用它當腦的 Bot 叫「外部 agent Bot」 |
| 電腦供應者 | 隔離環境裡開、關 Bot 的電腦的那一層，記下每個操作（跟假模型、假推播一樣） |
| 舊資料 | OLD 最後一版在隔離環境實際產生的資料夾（`07` 的測試資料）；前提寫「舊版資料：…」 |

### 寫法約定

- 步驟欄直接寫 `工具(參數)` 的，是「假模型：呼叫工具 工具(參數)」的簡寫；「Bot A：工具(參數)」是 Bot A 那一輪的假模型呼叫它。
- 工具可以寫 `08` 裡給模型的對外工具名（B8，例如 `send_to_device`），或用〔說明〕寫它做什麼（例如〔指令〕(git push)、〔連接器 slack：發訊息〕(#team, "…")）；都不是新版程式裡的名字。
- 「掃描 Bot 電腦的磁碟」＝對整個磁碟做一次「檔案〔路徑〕內容是〔…〕」。
- 預期欄最後用括號標出這個測試驗到哪幾個情境，例如「（S1、S3）」「（永遠成立）」，給 `05` 的功能追蹤表用。

### 測試種類

| 種類 | 意思 |
|---|---|
| 端對端 | 透過前端（桌面或手機畫面）操作，看畫面和結果 |
| 整合 | 不經畫面，直接用前端會用的動作打伺服器和執行端 |
| 單元 | 純邏輯（例如規則判斷、合併），不碰網路和檔案 |
| 性質 | 自動產生大量隨機的順序或輸入，檢查某條規則永遠成立 |
| 形式驗證 | 模型檢查工具窮舉所有先後順序（例如核准卡片的路徑） |
| 實機 | 要真的 Mac／Linux 或真的 Bot 電腦才跑得了 |

### 測試裡的假金鑰

要用「看起來像真金鑰」的字串測遮罩時，**在測試執行時才組出來**，原始碼和規格裡都不寫死。這樣掃金鑰的工具不用為測試開任何例外（`09` K75、K76）。

## 寫好的範例

### chat-steer 插話

- 決定：留，加上 R26　服務：不理他　邊界：B1、B2、B8
- 行為：
  - S1 Bot 正在做使用者自己起的這一輪時，使用者再送一句（可以附檔）→ 畫面顯示「已排入：「…」」；Bot 的**下一步**就讀到這句和附檔。
  - S2 Bot 正在跑**不是使用者起的**一輪（例行任務、工作流、外部訊息、別的 Bot 交辦）→ 這句不混進去；那一輪做完後，開新的一輪回覆這句。
  - S3 這一輪已經在收尾、來不及讀 → 這句變成下一輪的開頭。
  - S4 使用者按停止時，還有沒被讀到的插話 → 放回輸入框，不丟掉（`09` R26）。
- 永遠成立：插話只會進「同一個使用者自己起的」那一輪。
- 測試：

| 編號 | 種類 | 前提 | 步驟 | 預期 |
|---|---|---|---|---|
| T-chat-steer-1 | 端對端 | 假模型第一步呼叫一個要跑 10 秒的指令 | 在手機送「A」；工作中再送「B」 | 畫面出現「已排入：「B」」；模型收到的下一個請求包含「B」 |
| T-chat-steer-2 | 整合 | 一個例行任務正在跑 | 送「B」 | 例行任務那一輪模型收到的請求不包含「B」；那一輪結束後開新的一輪，第一個請求包含「B」 |
| T-chat-steer-3 | 端對端 | 假模型第一步呼叫一個要跑 10 秒的指令 | 送「A」；工作中送「B」；在模型讀到之前按停止 | 輸入框裡是「B」；模型從沒收到「B」 |
