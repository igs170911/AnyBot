# 05 · 開發原則

> 來源：使用者 2026-11-24 的開發原則（原話照錄），加上落實的做法。
> 用途：寫新版程式時的規矩，人和寫程式的 AI 都適用。
> 互查：`04-product-core.md`（產品裡的「確定性優先」）、`02-architecture.md`（分層）。

## 使用者的原話

> 「可以靠工具做的就不要靠模型；有 code level 的 lint 可以做的，就不要靠模型感覺；要先把整個 codebase 寫好；可以用 code 來決定的就不要靠模型。」

## 1. 先打底，再寫功能

1. **照分層開好專案骨架**（`02` 的分層）：每一層一個套件，層與層之間的介面先定好。
2. **把第 2 節所有關卡裝好，並在 CI 上跑。**
3. **給寫程式的 AI 即時回饋**：每次改檔就自動跑格式、lint、型別檢查（例如 Claude Code 的 hooks），錯了當場看到，不等它自己說「應該沒問題」。
4. **然後才開始寫功能。** 每個功能進來都要過全部關卡。

**「完成」的定義：全部關卡是綠的，而且這個功能在規格裡對應的測試都通過。** 關卡沒過就不算完成，不管誰說它做好了。

## 2. 能用工具擋的規則，就用工具擋

| 規則 | 用什麼擋 |
|---|---|
| 分層方向：上層可以用下層，反過來不行，也不能循環 | 套件之間的依賴關係（建置工具本身就擋循環），再加一個檢查依賴圖的測試 |
| 新版不讀環境變數（A10） | lint 禁用讀環境變數的函式；唯一例外是「資料庫在哪」那一處 |
| Bot 的指令一定經過信任層 | 只有信任層可以「執行外部程式」，其他地方 lint 禁用 |
| 網路請求集中管理 | 只有網路層可以發 HTTP，其他地方禁用 |
| 金鑰不會被印出來或寫進紀錄 | 金鑰用專用型別：不能印、不能直接序列化，由型別系統擋 |
| 正式程式碼裡不能有會讓程式直接當掉的寫法 | lint 禁用，只在測試裡允許 |
| 每個寫入 API 都帶 `Idempotency-Key` | 檢查 API 規格的 lint |
| API 相容 6 個月（A14） | 比對新舊 API 規格的工具，有破壞性變更就擋 |
| SQL 查詢對得上資料庫表格 | 在編譯時檢查 SQL 的做法 |
| 舊資料遷移不壞 | 用 OLD 最後一版產生的真實資料當固定測資，每次都跑遷移並比對結果 |
| 每條功能都有測試 | 追蹤表檢查：規格裡每個功能編號都要對到至少一個測試，缺了就擋；測試用**名稱**標出規格編號（Rust 測試函式 `t_chat_steer_1`、TypeScript 測試標題開頭 `T-chat-steer-1`），不靠註解 |
| 同步合併正確（`02` §3） | 自動產生大量隨機的離線、重連、先後順序去測（性質測試），不靠人想幾個例子 |
| 核准卡片的答案只落在使用者看到的那張卡 | 模型檢查工具，窮舉所有先後順序（舊版用過 TLA+） |
| 桌面 App 和背景程式不吃太多資源 | CI 自動打開 App 量一次，超過上限就擋。上限先抓：**視窗閒置時 CPU 接近 0、記憶體 200 MB 以內；背景程式閒置時 50 MB 以內**，之後照實測調整（`06` §2.4） |
| 沒有混進舊程式（clean room） | 把舊程式的函式名、型別名、獨特字串做成黑名單，新程式碼出現就擋。黑名單本身是舊程式的內容，所以放在 ClearRoom **外面**，由看過舊程式的一方執行 |

## 2a. 使用者定的寫程式規則（2026-11-25，`09` K75–K79）

| 規則 | 用什麼擋 |
|---|---|
| **檢查擋下來的不能關掉，要修到過** | 掃程式碼：出現 `#[allow`、`#[expect`、`biome-ignore`、`@ts-ignore`、`@ts-expect-error` 一律擋。`07` §3 的套件豁免寫在那個套件自己的 `clippy.toml`，由依賴檢查工具核對只有准許的套件才有 |
| **例外只准一條**（RUSTSEC-2024-0370） | 檢查 `deny.toml` 的例外清單剛好只有這一條 |
| **每個檔案最多 300 行、每個函式最多 60 行** | 自家的檔案行數檢查；Clippy 的函式行數上限設 60；TypeScript 用 Biome 的對應規則，沒有的話自家檢查 |
| **不寫註解，程式即註解** | 自家檢查：產品程式碼和工具程式碼裡出現註解就擋（產生出來的檔案除外） |

## 3. 模型只做工具做不到的事

- **寫程式的 AI**：靠關卡的回饋判斷對錯，不靠自己的感覺。
- **審查**：先跑工具，工具抓不到的才請 AI 審，而且要附上它看了什麼、根據什麼。
- **產品裡的 Bot**：照 `04` §2 的順序，程式規則 → 程式檢查 → 模型判斷。
