## 監督者定了的（一點）

監督者定了：照建議做。規格已經改好（`spec/09` K118 ⑲、§0.1「在線」、`computers-online` S1、`conn-heartbeat` S1），第 3 段照改過的字做。

1. **伺服器怎麼知道一台電腦已經 60 秒沒有訊號**（§0.1「在線」、`computers-online` S1、`T-computers-online-1`、`server-n3` S2 的「超過 60 秒沒有它的任何訊號」）。
   - 現在的字：在線＝即時連線連著，或 60 秒內送過請求。
   - 問題：SSE 只有伺服器往外送，電腦那一端連上之後什麼都不送。網路斷了、電腦睡著了，伺服器這邊的連線看起來還開著。放在反向代理後面時，伺服器連的是代理，代理那條連線一直開著，伺服器更看不出來。測試用的代理是一般的程式，它所在的系統照樣會回 TCP 的確認，所以「看 TCP 有沒有確認」在測試裡也造不出來。照現在的字，`T-computers-online-1`（斷網後 61 秒寫離線）做不到、也驗不到。
   - 建議：
     - 電腦那一端（M6c 的函式庫）在 SSE 連著時，每 20 秒至少送一個請求。沒有別的要送時，就送一次「要帳號那條流第 N 號之後的」（沒有新的就回空的）。不另開入口；順便也補了「最後一個提示漏掉」的洞。
     - 伺服器的「在線」＝60 秒內有它送來的任何請求；SSE 連著本身不算。斷線那一刻＝最後一次請求進來的那一刻。
     - 要改的規格：§0.1「在線」、`computers-online` S1、`conn-heartbeat` S1（客戶端每 20 秒至少送一個請求）。M6c 跟著做（它的「監督者定了的」是同一點）。
   - 不同意的話：伺服器用 TCP 層的逾時判斷（Linux 的 `TCP_USER_TIMEOUT`，放在反向代理後面時照樣看不出來），`T-computers-online-1` 改成這次不驗，等有能真的擋網路的測試環境。第 3 段第 22 項和那一列跟著改。
   - 
---

這次做伺服器上「電腦」和「信箱」這一半：

- 帳號裡的電腦：用帳號登入的、用配對碼加入的；每台自己的憑證、名字、移除、交辦開關、最多 100 台。
- 配對碼。
- 在線和離線，伺服器重開也對。
- 伺服器上執行服務的那台裝置。
- 每台電腦的信箱：最小的「交一輪」、投遞、領走、改派、卡片答案的信。

做完後，下面列的 19 個規格編號要有整列驗到的測試，名稱照 `AGENTS.md` 第二節第 4 條。M6a、M6b-1、M6b-2a 的編號照樣通過，包括 `T-conn-auth-6`（它會自動打到你新加的每一條 GET 路由）。

**你是一次性執行的**：回合一結束，背景工作就會被收掉。`make check` 用前景跑、timeout 設 30 分鐘，不准結束回合去等通知。

## 第 1 段：帳號裡的電腦（`account-login` S6；`computers-online` S4；`computers-n8` S1–S3；`account-n12` S1、S3；`account-computers`；`computers-n2` S1；`server-n2` S2；K60；K118 ③⑮⑰）

1. **兩種加入的方式**：
   - 在那台用帳號和密碼登入，`credential` 填 `computer`：那台加入帳號、拿到自己的憑證和裝置編號。開了兩步驟的要過第二步。
   - 用配對碼（第 2 段）。
2. **第二步照第一步說的那一種發**（K118 ③）：用一個描述性的測試把 `cookie`、`bearer`、`computer` 三種都驗一次。M6b-2a 或 M6b-1 還沒接好的，你接好。
3. **每台電腦一把自己的憑證**：亂數產生，資料庫只存雜湊，用 `Authorization: Bearer`。接進 `Caller`，憑證種類多一個「電腦」。
   - 不受「登出所有裝置」、改密碼影響（`account-n9` S2、`account-n10` S3）。
   - 帳號被停用時停止，重新啟用就恢復（`server-n13` S4）。
4. **名字**：每台一個。
   - 最多 60 字，超過就拒絕。換行這類控制字元換成空白再存；伺服器的紀錄裡也不能有換行。
   - 登入時撞名：同名的那台在線 → 新的叫「名字 (2)」，不踢掉它；同名的那台不在線 → 換掉那一列（`computers-online` S4）。
   - 尾巴的數字用還沒人用的最小數字；加了尾巴超過 60 字，把原本的名字從尾端切短。登入撞名的切短規格只在配對寫了，照同一條做，寫進回報。
   - 改名改成帳號裡別台的名字 → 拒絕「帳號裡已經有叫「…」的電腦」。擁有者可以改別台的名字。
5. 每個帳號最多 100 台，滿了擠掉最久沒出現的。
6. **移除**：擁有者移除某台 → 那台的憑證作廢、它的 SSE 5 秒內斷、它之後的請求拿到「這台被移出帳號了：要重新登入」的代碼、它信箱裡還沒領的照第 5 段處理。那台自己登出也一樣。
7. **用配對碼加入的電腦不能做的事**（`computers-pair` S7、K60）：寫成一張表，放在一個地方檢查。
   - 現在有的動作接上去：產生配對碼、移除別台、「交一輪」（第 5 段）。
   - 之後的動作（分享和團隊、發布網站、匯出帳號資料）加路由時要在表裡登記。
8. **交辦開關**（`computers-n2` S1、K118 ⑰）：每台一個，預設關。**只有那台自己的憑證能改**；手機、別台、擁有者都不能。
9. **電腦清單**：每台的名字、在不在線、離線的時間和原因、交辦開關、是不是配對加入的。
   - 清單的變化寫進帳號的紀錄流，別的裝置 5 秒內從 SSE 收到「有新的」。
   - 執行服務的那台永遠不在清單裡（`computers-kinds` S4、K118 ⑬）。
10. `T-conn-auth-6` 會打到新的 GET 路由：讓它準備得出路徑參數。
11. 測試：`T-computers-online-4`、`5`；`T-computers-n8-2`、`3`；`T-computers-n2-5`。
    - `T-computers-n2-5` 的「P 的電腦清單 5 秒內顯示 A 的開關是開的」＝P 的 SSE 5 秒內收到帳號那條流的「有新的」，P 照 API 拿到的清單裡 A 的開關是開的。
12. `make check` 全綠，commit。

## 第 2 段：配對碼（`computers-pair` S1–S8；`safety-n10` S2；K118 ②⑮⑯）

13. 6 位數字、10 分鐘有效、只能用一次。同時在等的碼彼此不能一樣。

    - 那個碼原本的 10 分鐘還沒過；

    - 少一樣 → 跟「配對碼不對…」一模一樣，也照樣算一次錯。key 的紀錄只記「做過了」和是哪一台，不記憑證。

## 第 3 段：在線和離線（`computers-online` S1、S2；`server-n3` S2；K118 ⑭；`spec/02` §7 規則 1）

22. 在線＝60 秒內有那台送來的任何請求；SSE 連著本身不算（「監督者定了的」那一點）。最後一次請求進來的那一刻就是最後在線的時間。
23. 狀態放資料庫。「最後出現」不要每個請求都寫一次，照 M6a 工作階段的做法節流。正常停機時，把還沒寫進去的「最後出現」都寫進去。
24. 離線的原因用代碼。這次做兩種：「超過 60 秒沒有它的任何訊號（網路斷了，或電腦睡著了）」「這台被移出帳號了（或被同名的電腦換掉）」。其他五種之後做。
25. **伺服器重開**：
    - 離線的時間和原因都在資料庫，重開不清掉、不改寫。

## 第 5 段：信箱（要 M6b-1 的 B 段在 `dev` 上）（`mailbox-claim` S1–S5；`mailbox-reassign` S1、S2 第一句、S4、S6；`mailbox-route` S1–S6；`sync-referee` S1；`account-n12` S3；K118 ⑰）

35. 開始前 `git merge dev`。M6b-1 的 B 段還不在 `dev` 上：停在第 4 段的全綠 commit，回報做到哪。
36. **這一輪在哪跑**：`domain` 的純函式，照 `mailbox-route` 的順序。模型說的不算。輸入：
    - 從哪裡發起：伺服器從憑證認。電腦的憑證 → 那台；其他（瀏覽器、沒有電腦那一列的登入）→ 當成手機。
    - Bot 設定的「做事的電腦」（M6b-1 的設定）；有沒有指名電腦（給的是裝置編號）；那台在不在線；交辦開關。
    - 模型是不是只有某台連得到：伺服器還沒有這份資料（`computers-n5` 的回報是 M7），這次傳「沒有」；純函式的單元測試照樣涵蓋。
    - 是不是團隊成員：還沒有團隊，傳「不是」。
37. **「交一輪」**：POST，帶 `Idempotency-Key`。參數：哪個 Bot；要不要指名一台電腦。
    - 伺服器照第 36 項選一台，放進它的信箱，回這封信的編號和去了哪台。
    - 用配對碼加入的電腦不能叫（第 7 項的表）。
    - 伺服器不因為收到訊息紀錄就自己派工；信裡放什麼、一輪真正怎麼開始，M7 定。
38. **投遞**：信放進那台的信箱，經那台的 SSE 送一個提示，那台領走時拿到內容（K118 ⑧ 同一個想法：通知只是提示）。提示寫上那台 SSE 的那一刻就是「送到」，10 秒規則從這一刻算。要是你選別的做法，寫進回報。
39. **領走**：那台 POST 領走；伺服器只讓一台成功。**用資料庫的一道有條件的更新擋，不是先讀再寫。**
    - 已經被你領過 → 「你已經領過了」，不會變成第二次。
    - 被別台領走 → 「別台領走了」。
    - 已經改派 → 「這封已經改派」，它不做。
40. **改派到 Bot 的電腦**（執行服務那台）：
    - 送到 10 秒內沒領 → 當成不在線，改派；原本那封收回。
    - 選到的那台不在線、交辦開關沒開 → 不等，直接改派。Bot 的紀錄流加一行（伺服器寫的種類；代碼和參數：哪台、實際的原因）。
    - 例外：模型只有那台連得到 → 不改派（`mailbox-reassign` S6）。
41. **卡片答案的信**（K118 ⑰；`mailbox-claim` S5）：M6b-1 的卡片答案被伺服器收下時，放一封信到發出那張卡的那台的信箱（寫「卡片出現」的那台裝置）。不套 10 秒規則、不改派、不過期；那台被移出帳號時收回。
42. 一台被移出帳號：它信箱裡還沒領的一般信照第 40 項改派；卡片答案的信收回。
43. 定時的檢查（10 秒沒領、60 秒沒訊號）走 `Clock`。伺服器重開後，重開前就在等的信照樣到期、照樣改派（狀態在資料庫）。
44. 次數的紀錄、過期的配對碼、收回的信要清：接上 K116 ⑥ 每小時清一次的那個地方。
45. 測試：`T-mailbox-claim-1`、`T-server-brains-7`。
    - `T-mailbox-claim-1`：真的伺服器、真的 PostgreSQL、3 個照 API 收送的執行端替身（其中一個用執行服務的憑證，就是 X）。1 萬封信，隨機交錯「送達、領取、斷線、重連、10 秒沒領、改派」。每封的「應該怎樣」由產生器在產生時記下。可以跑到 120 秒；再慢就回報，不准縮小規模還用編號。亂數的種子印出來，失敗時重現得了。
    - `T-server-brains-7`：「測試從資料庫解出來」是準備的步驟，可以用產品的解開函式。
    - 用描述性的名字測每一條的伺服器這一半：10 秒沒領改派、之後來領被告知已改派；不在線直接改派、紀錄流有那一行；交辦開關關著改派、寫實際原因；只有那台連得到模型時不改派（純函式）；答案的信留著等那台回來、不改派；移除一台後它沒領的信改派、答案的信收回；兩台同時領只有一台成功；伺服器重開前在等的信照樣到期。
46. 全部做完：`git merge dev`，`make check` 全綠，commit。

## 規則（請照做）

- **帶規格編號的測試，要證明它擋得住**：
  - 每一個帶編號的測試寫好之後，把它守的那條產品規則故意改壞（一次改一處，不 commit），跑那個測試，確認變紅，再改回來。
  - 回報列一張表：測試、改壞了什麼、有沒有變紅。改壞了還是綠的，不准帶編號：先把測試補到會紅。
  - 例子：`T-computers-online-1` 讓 SSE 連著也算在線；`T-computers-pair-7` 改成換掉離線的那台；`T-computers-pair-9` 拿掉「還沒用過憑證」的條件；`T-computers-online-2` 重開後馬上寫離線；`T-computers-online-7` 重開時清掉原因；`T-computers-n2-5` 讓擁有者也能改；`T-mailbox-claim-1` 把有條件的更新換成先讀再寫；`T-server-brains-7` 啟動時不看有沒有就建。
- **預期的值不准呼叫被測的產品函式來算**：
  - 名字的尾巴、原因的代碼：在測試裡寫死。
  - 每封信該被誰領、該不該改派：由產生器在產生時記下。
  - 不准「先呼叫一次產品函式拿結果，再拿同一個函式的結果去比」。
- **測試啟動的每個程序都要收掉，被訊號或逾時砍掉時也一樣**：
  - PostgreSQL、代理、跑真的執行檔的，都接上 M6a 第二輪做的那一套（pid 檔、收到結束的訊號先停自己啟動的東西、啟動時清掉上次留下的、只照 pid 停）。
  - 你新加的每一種會啟動程序的東西，都要有一個「程序不會留下來」的自我測試，而且它要真的會失敗：故意不收，自我測試要變紅。
  - 回報前不要只跑 `ps` 就寫沒有殘留。用 pid 檔和連線埠確認，寫明怎麼確認的。
- **會啟動 PostgreSQL 的測試放在檔名 `pg_` 開頭的測試檔。**
- **遷移照 K118 ⑥**：
  - 檔名編號用 0250–0299。
  - 只准建新表、建不是唯一的索引、加可以是空的或有預設值的欄位、放固定的起始資料。
  - 要唯一的、主鍵、外鍵、檢查：一律寫在 `CREATE TABLE` 那一句裡面。已經有的表不加任何限制。
  - 搬資料由程式在啟動時做，不寫在遷移檔。
  - **已經合進 `dev` 的遷移檔一個位元組都不准改**（M6b-1、M6b-2a 的都是）。
- **編譯輸出是各工作區共用的**：看到「Blocking waiting for file lock」是正常的，等就好。**不准刪它、不准 `cargo clean`**。
- **整合測試從外面打**：真的 HTTP。伺服器當函式庫在測試裡啟動，假時鐘、資料庫、listener、主鑰匙都從建構函式或啟動檔傳。規格裡的「電腦 A」「電腦 B」「手機 P」「執行端」這次是替身。
- **替身照 README 那一段**：只走公開的 API，做真的裝置會做的事，規模不縮。回報寫明每個編號裡哪個角色是替身。
- **名稱帶編號＝驗完那一列全部的預期**。預期裡有畫面、有執行端真的做事或不做事的，用描述性的名字，編號留在基準檔。
- **等待都走假時鐘**：0.3 秒、10 秒、60 秒、5 分鐘、10 分鐘都不准真的等。等外面的東西另外包真時間的期限。用 `tests/app-test` 現成的「推假時鐘直到回來」的工具。
- 除了啟動 PostgreSQL 本身，每個測試 10 秒內跑完。例外只有 `T-mailbox-claim-1`（120 秒）；`T-computers-pair-4`、`T-safety-n10-3`、`T-server-n2-2` 要送很多請求，超過 10 秒先回報。
- **不准為了測試在產品加路由、旗標、環境變數**。沒有「直接往信箱放一封」「直接建一台裝置」的測試用入口。
- **不准把秘密存成明文**：電腦的憑證只存雜湊；配對碼只存帶鑰匙的雜湊；執行服務的憑證加密；`Idempotency-Key` 的紀錄不存任何一樣（K116 ⑤）。附一個描述性的測試：把每個動作做過一遍後，整個資料庫匯出成文字，找不到任何一個原值。
- **不准默默換成預設值**：`unwrap_or`、`unwrap_or_default`、把錯誤丟掉的 `.ok()` 都不要。解不開、讀不到就回錯誤。
- **每個 POST 都帶 `Idempotency-Key`**，沒登入的（兌換配對碼）也一樣，綁來源位址。
- **SQL 在編譯時檢查**；`.sqlx/` 一起更新。
