# M7a-2：模型閘道的加固和四個性質測試

M7a 驗收了，已經合進 `dev`：41 個規格編號有整列驗到的測試。這一輪做剩下的事：把「資料不外送」的保證做成繞不過去的，補完四個性質測試。

先做：`git merge dev`。做完 `make check` 全綠，commit 一次，再回報。

**你是一次性執行的**：回合一結束，背景工作就會被收掉。要跑很久的指令（`make check`）用前景跑、timeout 設長，不准結束回合去等通知。

## 1. 資料政策要繞不過去（`models-egress` S4、「永遠成立」）

現在資料政策只在 `Session::ask` 裡檢查。`Gateway::complete` 是公開的，不檢查政策；`Gateway::new` 收呼叫的人給的 `reqwest::Client`，那個 client 可以設成會跟轉址。之後寫執行端的人直接用 `Gateway`，就會繞過「只送本機和區網的 Bot 不送雲端」。

改成由型別來擋：

1. **送 Bot 資料的請求一定要帶通行證。**
   - 送出帶 Bot 資料的請求的函式（`Gateway::complete` 這類）要多收一個「通行證」參數。
   - 通行證是一個型別，只有資料政策的檢查通過時才產生得出來：建構函式不公開，沒有 `Default`、不能 `Clone` 給別的目的地用，裡面記著它是替哪個目的地、哪種用途（`ModelUse`）發的。
   - 送出前比對：通行證的目的地跟這次真的要連的網址不一樣，就拒絕。
   - 取得模型清單不帶 Bot 資料，不用通行證，照舊只檢查金鑰能不能送（`models-n6` S6）。
2. **閘道自己建 HTTP 客戶端。**
   - `Gateway` 不收外面傳進來的 `reqwest::Client`。它自己建，固定不跟轉址、不設 reqwest 的逾時（時間走 `Clock`）。
   - 測試要換的東西（名字對照、時鐘）照舊從建構函式傳。
3. 附測試：
   - 編譯失敗的測試：沒有通行證就呼叫不了送出的函式。用 `trybuild` 這類做法前，先照 `AGENTS.md` 查套件；不想加套件的話，用文件測試的 `compile_fail` 也可以。
   - 拿替本機網址發的通行證去送雲端網址：被拒絕，雲端那個假模型沒收到任何請求。
   - 跟轉址的設定從外面改不了。

## 2. 測試用的東西不要放在產品的公開介面

`crates/models/src/lib.rs` 現在公開了 `normalize_prop::{Fixture, closed_tool_matches, cut_has_no_tools, normalize_pair}`。這些是給測試用的，不該是產品套件的公開介面。

- 搬到測試那邊（`crates/models/tests/` 的共用模組，或 `tests/harness`）。
- 測試需要產品的某個內部函式時，測真正公開的行為，不要為了測試多開一個公開函式。

## 3. 補完四個性質測試

這四個編號，現在的測試只驗到那一列的一部分。照規格那一列寫的產生方式補完，整列驗到之後用編號命名。種類是「性質」，不用每一組都真的走 HTTP，但被測的要是產品真正在用的那段程式，不是另外寫一份。

| 編號 | 現在缺的 |
|---|---|
| `T-models-normalize-14` | 三種格式都要有（含 vllm 多出來的欄位）；在**隨機位置**切片和斷掉，不是只在最後一個事件之前；隨機的 `finish_reason`、隨機多出來的欄位 |
| `T-models-errors-4` | 隨機的**失敗序列**加上「有人在看／沒人在看」，跑產品真正的重試迴圈：不重試的類別只送 1 次；總次數不超過上限 |
| `T-models-handoff-9` | 把「問模型、串流片段、換模型的要求」隨機**交錯**，換模型的要求可以出現在回答到一半：每次回答的片段都來自同一個模型；要求只影響之後開始的請求；每次換都有一筆紀錄 |
| `T-models-egress-6` | 隨機的 Bot 設定（主模型、最多 8 個備用、政策、驗收的候選、用途、轉址）加上失敗序列，跑產品真正的詢問流程：只送本機和區網的 Bot，沒有任何請求到雲端；`models-egress` S8 的用途只到本機或區網 |

- 要跑產品真正的流程又不想每組都開連線，可以把「送出一個 HTTP 請求」做成可以從建構函式換掉的一層：正式用真的，性質測試用一個只記錄「送到哪裡、送了什麼」的假的。這是從建構函式傳假東西，不是為測試加旗標。
- 每個性質測試 1,000 組，用 proptest。
