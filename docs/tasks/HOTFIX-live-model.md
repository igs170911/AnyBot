# HOTFIX：`make live-model-check` 的第二段，假模型的腳本是空的

## 現象

有真的設定檔（`.local/live-model/`）時跑 `make live-model-check`，失敗：

```
Error: "fake normal failed: ... code: \"model-other\", http_status: Some(400) ...
        (\"detail\", \"model-script-empty\") ..."
```

真的模型那一段是好的（格式比對有拿到回應）。壞的是後面「產品客戶端」的比對。

## 我查到的原因（請你先確認）

`tests/live-model/src/compare.rs` 的 `run()`：

1. 先呼叫 `fake_shapes`：它替假模型設了 3 步的腳本，3 個請求把腳本用完。
2. 接著呼叫 `product::compare_product`：用**同一個假模型**再送 4 個請求（一般、串流、工具呼叫、思考），但沒有人再設腳本，所以假模型回 400。

這條路以前從來沒有被跑過：沒有真的設定檔時，`run()` 一開始就結束了；`make check` 裡的測試只跑 `compare_fakes`，走的是另一條路。

## 要做的

1. **修好**：產品客戶端比對之前，假模型要有對應那 4 個請求的腳本，順序跟 `product_cases()` 一致。請求的清單和腳本的清單放在同一個地方定義，不要兩邊各寫一份、之後又對不上。
2. **補測試**：加一個不需要真的設定檔、`make check` 會跑的測試，把 `run()` 裡「假模型那一側」完整走一遍：格式比對的 3 個請求，接著產品客戶端的 4 個請求，確認每一個都拿到結果。
   - 可以把 `run()` 拆成「假模型那一側」和「真的模型那一側」，讓測試呼叫前者；`run()` 自己也要用同一個函式，不准測試走一條、正式走另一條。
   - 「真的模型那一側」要 HTTPS 和釘住的憑證。harness 沒有現成的 HTTPS 假模型就**不要**為了這個去做，寫進回報就好。
3. **出錯時把已經拿到的寫出來**：現在只要中間一步出錯，前面已經比好的結果就全部看不到。改成：出錯時，已經比完的部分照樣印出來、照樣寫進報告檔，最後才回錯誤和非 0 的結束碼。印的內容和報告檔都不准包含金鑰。

## 範圍

- 只改 `tests/live-model`（需要的話加 `tests/harness` 的小東西）。`crates/` 不動，不改產品行為。
- 另一個 agent 正在 `ws/m7a` 改 `Gateway::complete` 的參數。為了之後好合：`product.rs` 裡呼叫閘道的那幾行盡量不要動。
- 不准讀、不准印、不准複製 `.local/live-model/` 裡的任何檔案。你的工作區沒有那個資料夾，這是對的：真的那一段由監督者在合併之後跑。
