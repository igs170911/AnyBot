# M7a-4：模型閘道的審核修正（合併前最後一輪）

M7a-2、M7a-3 做完之後，我請了一個獨立的審查把整個閘道重新讀過一遍，也對真的模型跑了比對。

好的部分：憑證的信任沒有找到任何會放行的洞；送出那一層正式和測試真的共用；真機比對整條跑通了，閘道連得上那台自己簽憑證的模型。

但找到下面這些。前兩項在第一次做閘道時就在，現在已經在 `main` 上；它們是「資料不外送」和「不會一直重送」的核心，這一輪一定要修掉。規則都寫在 `spec/09` K117，先讀。

先做：`git merge dev`。每一大項做完 `make check` 全綠就 commit 一次。

## 一、一定要修

1. **網址的分類判錯**（`crates/models/src/where_run.rs`，K117 ①，新測試 `T-models-where-4`）。
   - IPv6 位址在網址裡帶著中括號，現在認不出來是位址；又因為裡面沒有點，被「沒有點的名字算區網」那一條當成區網。任何公開的 IPv6 位址都會被當成區網，「只送本機和區網」的 Bot 就會送出去。
   - 名字只要以 `127.` 開頭就被當成本機。
   - 改成照解析出來的主機種類判斷（位址就是位址、名字就是名字），不要比字串。包著 IPv4 的 IPv6 位址照裡面那個 IPv4 判斷。分不出來一律當雲端。
   - `t_models_egress_6` 現在拿這個函式自己當標準答案，所以它錯了測試也不會知道。測試裡的標準答案要另外寫（例如產生網址時就已經知道它該是哪一類）。
2. **有兩種情況會一直重送，沒有上限**（`session_rest.rs`、`session_step.rs`，K117 ③，新測試 `T-models-errors-5`）。
   - 模型回空白：次數被扣回去，下一次又被當成「第一次」，再回空白就再扣回去。
   - 模型拒絕某個參數：拿掉之後次數也被扣回去；它如果繼續拒絕，就一直重送。
   - 兩種都不等待、不檢查停止、不換備用模型。
   - `client.rs` 把「等不到第一個字」和「出字之前串流斷掉」變成一個成功的空白結果。這兩種是失敗，要照 `models-errors` 分類。
   - `retry.rs` 裡那個沒有人用的上限，確認該不該接上。
3. **這一輪重構造成的退步**（`transport.rs` 的 `exchange`、`reqwest_wire.rs`，K117 ⑤）。
   - 非串流的回答現在整個被包在 15 秒的連線期限裡：一個要 20 秒才答完的請求會被當成連不上，然後重試。
   - 等第一個字、沒進度的那兩個等待被丟掉了。
   - 取得模型清單的等待從 45 秒變成 15 秒。
   - `client.rs` 有一段因此永遠走不到。
   - 附測試（假時鐘）：20 秒才答完的非串流請求要成功；模型清單等得到 45 秒。
4. **串流**（K117 ④）：
   - 片段是一塊一塊各自解成文字的：一個中文字被切在兩塊中間就會壞掉。先照位元組接起來再解。
   - 判斷錯誤和結束是在整段原始內容裡找字：回答的內容剛好有「error」這個字，整個好的回答會被丟掉。改成看事件的結構。
   - 串流的請求回 4xx、5xx 時，內容沒有被讀進來，所以「太長」「不支援這個參數」「額度用完」「不支援工具」這些都分不出來。
5. **換模型**（`session_chain.rs`、`session_switch.rs`、`session.rs`、`session_io.rs`，K117 ⑥）：
   - 換了之後，模型清單只剩那一個，備用模型從此不會再用到；它在休息時還會回「沒有金鑰」。
   - 換模型的要求在「主模型失敗、改用備用模型」的途中進來：紀錄寫的是被要求的那個模型，實際卻送到備用模型，然後把要求清掉。
   - 「要換成哪個」和原因分別放在兩把鎖裡，先讀再清，中間可能被改；鎖壞掉時被默默略過。
   - 模型只比種類和名字：兩台伺服器上同名的模型，互相換不會有任何作用。
   - 從備用模型回到主模型沒有記一筆。
   - 每次問都回整份累積的換模型紀錄。確認規格要的是這一次的，還是全部的，照規格改。
6. **資料政策的設計**（K117 ⑦⑧）：
   - 政策是每次問的時候傳進來的欄位，呼叫的人還是可以自己挑。改成建 `Session` 時給（那個 Bot 的），問的時候不能另外指定。檢查工具的訊息也要跟實際做法一致。
   - `Gateway::with_names`、`clone_with_names` 會在通行證和金鑰都檢查完之後改寫目的地；`gateway_pinned` 是公開的。這些名字對照的入口，產品程式不准用（加進工具的檢查），或者改成改寫發生在檢查之前、檢查看的是真正要連的地方。
   - 用途現在寫死成「Bot」：驗收、語意摘要、語意模型沒有自己的送出路徑（`models-egress` S8）。補上。
   - `providers.rs` 的 `key_allowed` 永遠回「可以」。照 `models-n6` S6 真的檢查。
   - `http_wire.rs` 裡金鑰是一般的字串，而且那個型別可以被印出來。改用 `Secret`。

## 二、應該修

1. **憑證錯誤的分類**：`tls_fail.rs` 還在用訊息的文字判斷。另外請確認一個懷疑：TLS 的錯誤被包在一層 I/O 錯誤裡，照種類判斷的那條路可能永遠走不到，所以「清單裡的憑證當簽發者」那條路的過期、名稱不對，會被歸成「不被信任」。現在只有「內容一模一樣」那條路有測到。兩條路都要測到四種錯誤。
2. **客戶端不讀環境變數**（K117 ②），下面兩個是懷疑，請你查函式庫的文件確認：
   - 讀作業系統信任清單的函式庫，會不會因為某個環境變數而改讀指定的憑證檔。
   - HTTP 客戶端會不會照代理的環境變數走，讓本機、區網的請求被轉到別的地方。
   - 確認之後照 K117 ② 處理，各附測試：設了那些環境變數，行為不變。代理從建構函式傳進來（設定畫面之後才接），本機位址永遠不走代理。
3. **iron-laws 的 `cfg` 檢查**漏掉幾種寫法：用 `not` 包起來的巨集形式、包在 `all`／`any` 裡的、`cfg_attr`。補上，各附測試。
4. **「產品程式不准自己發通行證」那道檢查**，現在的測試只確認清單寫得一致，沒有證明真的會擋。補一個真的會被擋下來的例子（照你做「沒有通行證編譯不過」的做法）。
5. 小的：
   - `certs.rs`：PEM 區塊外面的文字是不是被默默略過（任務檔要的是回錯誤）。
   - `client_http.rs` 把「作業系統清單裡有幾張壞掉」的資訊丟掉了；`certs_store.rs` 的測試什麼都沒驗。
   - `t_models_egress.rs` 的轉址測試分不出「跟了轉址」和「沒跟」。
   - `tests/harness/tests/model_https.rs` 有一個沒有期限的等待。

## 四、真機比對

對真的模型跑的結果：三種格式都一樣；產品客戶端「思考」那一項一樣，其餘三項不一樣。三項都是比對程式本身的問題：

1. **一般、串流**：真的那台模型每次都會帶思考的內容，假模型的腳本在這兩項沒有。假模型要照真的那台的樣子演。設定檔可以多一個欄位說「這個模型每次都會思考」，腳本照它產生；不准把「有沒有思考」從比對裡拿掉。
2. **工具呼叫**：原始請求那一半有要求模型一定要呼叫工具，產品客戶端那一半只送了「hi」加一個可以用的工具，所以真的模型直接回了文字。產品客戶端那一半也要讓模型真的去呼叫工具（用系統提示要求）；工具的參數要是一份完整的結構描述。
3. 目標：四項都是「結構一樣」。這一段你驗不到（真的設定檔只有監督者有），但假模型那一側要有測試。
