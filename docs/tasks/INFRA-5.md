# INFRA-5：「拿掉規則測試會不會紅」交給工具驗（變異測試，雲端跑）

審核一再抓到同一類問題：測試寫了，但把它守的規則拿掉，測試照樣綠（2026-11-26 M6b-1：設定合併的三條同一刻規則，各拿掉一條都沒有測試變紅）。這一類用讀的很貴，工具可以做：把改到的程式碼一處一處故意改壞（變異），看有沒有測試抓到。

你在工作區 `~/Documents/AnyBotNext-wt/infra2`，分支 `ws/infra-2`。

## 要做到

1. 用 `cargo-mutants`（固定版本）。只變異**這個分支改到的程式碼**（跟 `dev` 的分歧點比；`--in-diff` 或同等做法），只跑改到的套件的測試，用 nextest。
2. 在 `ci.yml` 加一個獨立的工作（跟 `check` 同時跑，不拖慢它），每個 `ws/*` 分支推上去都跑。沒被抓到的變異（missed）→ 工作失敗，列出哪個檔、哪一行、改成什麼。逾時的變異照實列出，不算過。
3. 例外：真的改了也一樣的變異（等價變異）放在一個設定檔，每一條寫原因；這個檔的改動審核時會逐條看。不准用註解或屬性在程式碼裡關掉。
4. `make mutants` 讓本機也能跑同一件事（agent 平常不用跑，雲端會跑）。
5. `docs/testing.md` 寫：這道關在驗什麼、沒過時怎麼讀報告、等價變異怎麼登記。
6. 先拿一個已知的例子證明它抓得到：在暫時的改動裡，把某個有測試的規則的測試弄弱（例如刪掉一個斷言），確認變異測試會報 missed；再改回來，不要 commit 弄弱的版本。

## 驗證和回報

這一件改到 `.github/`，雲端檢查會擋（CI 設定由監督者推）；本機跑 `make check-fast` 和 `make mutants`（只對你這個分支的改動）。commit，訊息開頭 `INFRA-5：`。`git merge dev`。回報：用的版本、一次在雲端估計要多久、第 6 點證明的結果。

你是一次性執行的：回合一結束，背景工作就會被收掉。指令用前景跑、timeout 設長。只在自己的工作區做，暫存檔放工作區的 `target/`，不改 `spec/`。不准改寫歷史、不准自己 push、不要用 `gh`、不准用 `pkill` 或 `killall`。遇到「Operation not permitted」是沙箱在擋，不要繞過。
