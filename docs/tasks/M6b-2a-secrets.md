## 第 1 段：啟動檔和主鑰匙（K118 ①；K113 ④；`install-n22` S1、S2；`server-privacy` S5；`server-n14` S2）

1. **啟動檔的新格式**：純文字，每行一個「名稱=值」，剛好兩行：
   ```
   database=postgres://帳號:密碼@主機:5432/名稱
   master_key=<64 個十六進位字>
   ```
   - 空行不算。
   - 少一個名稱、多一個不認得的名稱、同一個名稱出現兩次、主鑰匙不是 64 個十六進位字 → 不啟動，說是哪個名稱，不印出值，結束碼 2。
   - 只有一行連線位址的舊寫法不收。
   - 權限太開放照舊拒絕（`server-n14` S2）。
2. **`anybot-server new-master-key`**：用作業系統的亂數產生 32 位元組，在標準輸出印一行 `master_key=…`，結束碼 0。不讀啟動檔、不碰資料庫、不寫任何檔案。
3. **伺服器啟動時不自己產生主鑰匙**。測試由測試工具在執行時產生，不寫死。
4. **主鑰匙的核對**：
   - 資料庫記著「這份資料庫用的是哪一把」：一個核對值，不是鑰匙本身，也推不回鑰匙。怎麼算你定（例如從主鑰匙導出來的一個值），寫進回報。
   - **核對排在跑遷移之前**。資料庫裡有核對值、對不上 → 不啟動，回「主鑰匙不對：這份資料庫的秘密解不開。請用原本的啟動檔。」的代碼；遷移也不跑，資料庫一個位元組都不動。
   - 資料庫裡還沒有核對值（全新的，或是還沒有這一段的資料庫）→ 跑完遷移後寫進去。資料庫裡還沒有任何秘密時也要對得出來。
5. 主鑰匙不進資料庫、不進紀錄、不進錯誤訊息。
6. 改 `tests/app-test` 寫啟動檔的那一個地方，已經有的測試都帶主鑰匙。`T-install-n22-1`–`4`、`T-server-n14-2` 換成新格式後照樣要過。
7. 測試：`T-install-n22-5`。用描述性的名字：只有一行的舊寫法不啟動；核對在遷移之前（用一個還沒跑新遷移的資料庫配錯的鑰匙，遷移沒有跑）。
8. `make check` 全綠，commit。

## 第 2 段：秘密的加密、帶鑰匙的雜湊（K113 ④；K118 ②；`server-privacy` S3、S5；`account-n3` S5）

9. **加密**：
   - 照 `spec/06` 用 `ring` 的驗證式加密。不准自己寫演算法。每次加密用新的亂數。
   - 每筆密文記著用的是哪一把鑰匙（之後換鑰匙用）。
   - 每筆密文綁著它屬於哪張表、哪一列、哪一欄：搬到別的列、別的欄就解不開。
   - 解不開就回錯誤。**不准當成空的、不准當成「沒設定」、不准換成別的值。**
   - 明文只裝在 `Secret` 裡。
10. **帶鑰匙的雜湊**（恢復碼，之後的配對碼）：
    - 鑰匙從主鑰匙導出來，每一種用途各導一把。
    - 恢復碼的雜湊綁著帳號。
    - 每一筆記著用的是哪一種算法（之後要放得進別種算法的雜湊）。
    - 比對用固定時間。
11. 給 M6b-2b 用的介面：照（表、列、欄）加密和解開；照用途算帶鑰匙的雜湊、比對。
12. 單元測試（描述性的名字）：搬列、搬欄、改一個位元、換鑰匙都解不開；同一個明文加密兩次的密文不一樣；同一個恢復碼綁不同帳號的雜湊不一樣；記著的算法讀得回來。
13. `make check` 全綠，commit。

## 第 4 段：兩步驟驗證（`account-n3` S1–S6；`safety-n10` S2；K116；K118 ②）

18. **開始設定**：給 `otpauth://totp/AnyBot:<帳號>?…&period=30&digits=6` 的網址和 8 組恢復碼（每組 10 個十六進位字），只給這一次。輸入現在的六位碼才生效。
19. **已經開著**：換驗證器、關掉都要現在的碼。關掉時恢復碼一起清掉。
20. **登入**：
    - 密碼對了進第二步。第二步 5 分鐘有效、同一次第二步最多試 3 次，之後回「這次登入已過期，請重新輸入密碼」。
    - 30 秒一格，前後各容許一格。同一組碼 2 分鐘內不能再用。恢復碼每組用一次。
    - 碼錯：等 0.3 秒（走 `Clock`）才回「驗證碼不對」。
    - 「位址＋帳號」、「帳號」各 5 分鐘 8 次 → 「驗證碼錯太多次，請 5 分鐘後再試」，並作廢這次第二步。
    - 照 K116 ① 的同一套：同一筆交易裡先看有沒有超過、沒超過先記下這次，再驗；被擋的不再往上加；比對用固定時間。
21. **存法**：共用密鑰用第 2 段加密存；恢復碼用第 2 段的帶鑰匙的雜湊。
22. **`Idempotency-Key` 的紀錄**不存共用密鑰、恢復碼、六位碼。回應裡有它們的、或有憑證的，只記「做過了」。第二步帶同一個 key、同一份內容重送怎麼辦規格沒寫：照 K108 ⑥ 登入的做法，寫進回報。
23. **第二步通過後發憑證**：走密碼登入發憑證的那一個地方。
    - 做到這裡先 `git merge dev`。`dev` 上已經有 M6b-1 的 `credential` 欄位：照第一步說的那一種發（`cookie` 或 `bearer`），加一個描述性的測試。
    - 還沒有：照 M6a 的方式發，回報寫明。M6b-2b 會補上並驗證。
    - 不管哪一種，第一步說的那一種要記在第二步的那一筆裡，之後才接得上。
24. 管理員替別人重設密碼，那個人的兩步驟驗證不變（`account-n11` S1）。
25. **`anybot-server --bootstrap <檔> reset-two-step <帳號>`**（`account-n3` S6）：
    - 那個帳號的兩步驟驗證關掉，共用密鑰和恢復碼清掉。
    - 密碼不變，不登出，不用停伺服器，不用解開舊的密文（直接刪那幾列）。
    - 成功結束碼 0；帳號不存在 → 說原因，結束碼不是 0。
26. **算六位碼**：用還在維護的套件，或 `ring` 的 HMAC 照 RFC 6238 做。選哪個寫進回報；新的第三方套件照 `AGENTS.md` 查過維護者和 RustSec。
27. **假驗證器**（`tests/harness`）：給共用密鑰和假時鐘現在的時間，算出這一格、前一格的碼。
    - **它要是另外寫的一份 RFC 6238，不准呼叫產品算碼的函式。**
    - 自我測試：RFC 6238 附錄 B 的測試向量（SHA-1 那幾組）全對。
28. 測試：`T-account-n3-2`、`3`、`4`、`5`、`6`；`T-server-privacy-6`、`7`、`8`。
    - `T-account-n3-3`：「錯 3 次後過期」照 `safety-n10` S2「同一次驗證最多試 3 次」讀：同一次第二步錯 3 次之後，下一次（就算碼對）回「這次登入已過期…」。
    - `T-account-n3-4`：一次第二步最多 3 次，所以連錯 8 次中間要重新輸入密碼。8 次錯每次都至少 0.3 秒、回「驗證碼不對」；第 9 次（就算碼對）回「驗證碼錯太多次…」。跟登入的「8 次之後第 9 次被擋」同一個讀法，寫進回報。
    - `T-account-n3-5`：找共用密鑰的原始位元組、base32（`otpauth` 網址裡的寫法）、十六進位；找每組恢復碼的原值，和不帶鑰匙的 SHA-256（十六進位、base64）。
    - `T-account-n3-6`、`T-server-privacy-6`、`T-install-n22-5`：跑真的 `anybot-server` 執行檔，看結束碼和輸出。
    - `T-server-privacy-6`：資料庫「沒變」用啟動前後各匯出一次比對。
    - `T-server-privacy-7`：直接在資料庫搬密文（那一列的步驟就是這樣寫的）；「紀錄寫原因」看伺服器的紀錄。
    - `T-server-privacy-8`：主鑰匙的原始位元組、十六進位（大小寫）、base64 幾種寫法都要找。
29. 全部做完：`git merge dev`，`make check` 全綠，commit。

## 規則（請照做）

- **帶規格編號的測試，要證明它擋得住**：
  - 每一個帶編號的測試寫好之後，把它守的那條產品規則故意改壞（一次改一處，不 commit），跑那個測試，確認變紅，再改回來。
  - 回報列一張表：測試、改壞了什麼、有沒有變紅。改壞了還是綠的，不准帶編號：先把測試補到會紅。
  - 例子：`T-server-privacy-6` 把核對拿掉；`T-server-privacy-7` 拿掉密文綁的列；`T-account-n3-3` 拿掉「2 分鐘內不能重用」；`T-account-n3-4` 把上限改成 9；`T-account-n3-5` 把共用密鑰改存明文、把恢復碼改存明文各一次（測試另外也找每組恢復碼不帶鑰匙的 SHA-256，十六進位、base64 各一次，所以改成不帶鑰匙的雜湊也要紅）；`T-install-n22-5` 讓多一行不認得的名稱照樣啟動。
  - 假驗證器的自我測試也照這樣證明會紅。
- **預期的值不准呼叫被測的產品函式來算**：
  - 六位碼由假驗證器算，它是另外寫的一份 RFC 6238。
  - 找秘密的時候，十六進位、base64 在測試裡另外轉。
  - 不准「先呼叫一次產品函式拿結果，再拿同一個函式的結果去比」。
- **測試啟動的每個程序都要收掉，被訊號或逾時砍掉時也一樣**：
  - 這次會跑真的 `anybot-server` 執行檔。它和 PostgreSQL 都接上 M6a 第二輪做的那一套（pid 檔、收到結束的訊號先停自己啟動的東西、啟動時清掉上次留下的、只照 pid 停）。
  - 跑執行檔的那個測試工具要有一個「程序不會留下來」的自我測試，而且它要真的會失敗：故意不收，自我測試要變紅。
  - 回報前不要只跑 `ps` 就寫沒有殘留。用 pid 檔和連線埠確認，寫明怎麼確認的。
- **會啟動 PostgreSQL 的測試放在檔名 `pg_` 開頭的測試檔。**
- **遷移照 K118 ⑥**：
  - 檔名編號用 0200–0249。
  - 只准建新表、建不是唯一的索引、加可以是空的或有預設值的欄位、放固定的起始資料。
  - 要唯一的、主鍵、外鍵、檢查：一律寫在 `CREATE TABLE` 那一句裡面。已經有的表不加任何限制。
  - 搬資料由程式在啟動時做，不寫在遷移檔。
  - **已經合進 `dev` 的遷移檔一個位元組都不准改。**
- **編譯輸出是各工作區共用的**：看到「Blocking waiting for file lock」是正常的，等就好。**不准刪它、不准 `cargo clean`**。
- **整合測試從外面打**：真的 HTTP，或真的執行檔。伺服器當函式庫在測試裡啟動時，假時鐘、資料庫、listener、主鑰匙都從建構函式或啟動檔傳。
- **名稱帶編號＝驗完那一列全部的預期**。只驗一部分就用描述性的名字，編號留在基準檔。
- **等待都走假時鐘**：0.3 秒、30 秒、2 分鐘、5 分鐘都不准真的等。等外面的東西另外包真時間的期限。用 `tests/app-test` 現成的「推假時鐘直到回來」的工具。
- 除了啟動 PostgreSQL 本身，每個測試 10 秒內跑完。
- **不准為了測試在產品加路由、旗標、環境變數**。假的東西從建構函式傳。
- **不准把秘密存成明文**：共用密鑰、代理暗號加密；恢復碼只存帶鑰匙的雜湊；`Idempotency-Key` 的紀錄不存任何一樣。附一個描述性的測試：把每個動作做過一遍後，整個資料庫匯出成文字，找不到任何一個原值。
- **不准默默換成預設值**：`unwrap_or`、`unwrap_or_default`、把錯誤丟掉的 `.ok()` 都不要。解不開、讀不到就回錯誤。
- **每個 POST 都帶 `Idempotency-Key`**，還沒登入的第二步也一樣，綁來源位址（K116 ⑤）。
- **SQL 在編譯時檢查**；`.sqlx/` 一起更新。
- 次數的紀錄要清：接上 K116 ⑥ 每小時清一次的那個地方。
- 錯誤回 problem+json，帶代碼和參數；測試照代碼比對。新的 API 都寫進 OpenAPI，HTML 文件和 TypeScript 客戶端一起重新產生。改了登入的回應就照相容檢查的做法重新產生基準、加一行破壞性變更紀錄。翻譯檔兩種語言都要有，zh-TW 照規格裡的字，不准有簡體字。
- 函式庫的行為要查文件或原始碼確認（`~/.cargo/registry/src/` 可以讀），不要憑記憶寫。
- 規格沒寫清楚的不要猜，寫進回報。不得不先做時，選最小、之後好改的。
- **40 分鐘內要有第一個全綠的 commit**（第 1 段）。**同一個測試跑到第 3 次還不過，換做法；換了還不行，寫進回報、先做別的。**
- 只在自己的工作區和分支做。暫存檔放自己工作區的 `target/`。不改 `spec/`。不准改寫歷史、不准 push、不要用 `gh`、不准用 `pkill` 或 `killall`（要停程序只能指定 PID）。遇到「Operation not permitted」是沙箱在擋，不要繞過，寫進回報。
