# M6a 審核修正

M6a 我看過了。A、B 兩段都交了，任務要的編號都有測試，網路控制的程式沒有再動，491 個測試在你最後那次檢查是真的全過。停掉資料庫再開的做法也照做了。

但這一輪有不少要修的，其中幾個是安全問題。請照下面的順序做：**先安全，再行為，再測試**。每一大項做完 `make check` 全綠就 commit 一次。

先做：`git merge dev`。`dev` 多了三樣：
- 測試關卡的修正（`docs/tasks/HOTFIX-make-test.md`）：以前測試失敗時 `make check` 還是會過，現在會真的擋下來；iron-laws 多了一道掃 `Makefile` 的檢查，你加的目標（`sqlx-prepare`、`sqlx-check`）可能會被擋到，照它的要求改。
- 規格 `spec/09` K116：這份修正裡提到的規則都寫在那裡，先讀。
- 模型閘道那邊的改動（跟你沒有衝突的話不用管）。

## 一、安全（一定要修）

1. **拿掉 `/v1/server/stop`。**（`crates/server/src/status.rs`、`app.rs`、`apps/server/src/server_run.rs`）
   - 它不用登入就能把伺服器關掉，規格沒有這個入口，只有測試在用。K116 ⑦。
   - 測試要停伺服器：停自己啟動的那個程序（送訊號），或用函式庫啟動時拿到的關閉把手。
2. **`Idempotency-Key` 的紀錄不准存秘密**（K116 ⑤）。
   - 現在登入的回應整個被存進去，裡面有工作階段的金鑰。工作階段的表只存雜湊，這裡卻把明文存了一份。
   - 請求的指紋是整個內容的雜湊，內容裡有密碼（登入、註冊、改密碼、管理員重設）。
   - 改成：指紋不含秘密欄位；回應裡有金鑰的不存回應，只記「做過了」。
   - 附測試：登入、註冊、改密碼、重設密碼之後，把那張表整個讀出來，找不到金鑰，也找不到密碼和它的雜湊。
3. **登入的次數先記再驗**（K116 ①，新測試 `T-safety-n10-6`）。
   - 現在是「先看有沒有超過 → 驗密碼（很慢）→ 才記一次」。同時送很多個，全部都會通過前面的檢查。
   - 被擋的請求現在也會記成一次錯：一個位址可以讓某個帳號對所有位址一直被鎖。被擋的不再往上加。
   - `t_server_n2_1` 你把預期放寬成「401 或 429 都算對」，就是因為這個問題。修好之後改回規格寫的：第 9 次被擋、帳號總數到 40 次後所有位址都被擋，數字要釘住。
4. **不存在的帳號一律失敗**（K116 ②，新測試 `T-account-login-9`）。
   - 現在不存在的帳號會拿輸入去比一個固定的假密碼。輸入剛好是那個假密碼時會被當成「驗過了」，接著回「帳號已停用」，而且跳過等待和計數。
   - 照樣算一次雜湊，結果丟掉，一律當成失敗。
5. **被停用的帳號，密碼對了才說停用**（K116 ③）。現在密碼錯也會回「已停用」。
6. **註冊**（K116 ⑪）：
   - 失敗的註冊也要算進次數（規格：同一位址 5 分鐘 5 次，成功也算）。
   - 資料庫裡沒有邀請碼那一筆時，現在什麼碼都收。改成一律拒絕。
   - 「第一個註冊的是管理員」在兩個人同時註冊時會出現兩個管理員。用資料庫擋住，附測試。
7. **`Idempotency-Key` 的紀錄要綁對象**（K116 ⑤）：現在不分帳號、方法、路徑。同一個 key 和內容送到別的路徑或別的帳號，會直接回第一次存的結果。
8. **密碼雜湊**（K116 ⑧）：
   - `argon2` 用的是 0.1.5，很舊。換成目前還在維護的版本（照 `AGENTS.md` 查過）。
   - 確認雜湊真的用了規格的參數，不是套件的預設值。附測試：解析雜湊出來的字串，參數跟規格一樣。
   - 現在執行環境是單一執行緒，雜湊又是同步算的：每算一次，所有請求都停住，「同時最多 4 個」的限制也沒有作用。改成在不會卡住其他請求的地方算。附測試：一個登入在算雜湊時，健康檢查照樣馬上回。
9. **來源位址**（K116 ⑨⑩）：
   - `X-Forwarded-For` 有好幾行時只讀了第一行。全部接起來看最後一個值。
   - 代理的暗號不是固定時間的比對。
   - 埠、信任的代理這些設定值不合法時被默默略過。改成啟動時回錯誤。

## 二、行為

1. **改密碼把自己這台也登出了。**規格（`account-n10` S3）：其他手機和瀏覽器登出，只留這一個。附測試。
2. **重送要拿得到第一次的結果**（`conn-post` S2、K116 ⑤）：
   - 改密碼的結果沒有被記下來。
   - 註冊成功後重送，回的是「帳號已存在」。
3. **登入沒有把帳號名稱正規化**（K116 ④）：註冊「Bob」之後用「Bob」登入會失敗。
4. **舊紀錄沒有人清**（K116 ⑥）：清的函式寫了，沒有人呼叫。每小時清一次，時間走 `Clock`，附測試（假時鐘快轉）。
5. **遷移和啟動**：
   - 「這是不是 AnyBot 的資料庫」只看標記表在不在，沒有看裡面的標記。任務檔要的是用標記來認。
   - 遷移的鎖被關掉了；`reset-password` 的命令列也會跑遷移。兩個程序同時啟動會一起跑遷移。把鎖開回來；`reset-password` 不該自己跑遷移（資料庫版本不對就說明並結束）。
6. **默默換成預設值的地方**，逐一處理（該往上報的往上報）：`api_account.rs` 驗密碼那一段、`caller.rs`、`req_write.rs`、`problems.rs`、`server_run.rs`。整個 `crates/server`、`crates/store-server`、`apps/server` 找一遍 `unwrap_or`、`unwrap_or_default`、把錯誤丟掉的 `.ok()`。

## 驗證和回報

- 每一大項 `make check` 全綠就 commit。最後 `git merge dev` 再跑一次。
- 回報（簡短，逐項對照實際檔案）：每一項怎麼改的；第三部分那張表每一個是補齊了還是改名；`make check` 的結果和 nextest 的總結；結束後有沒有留下任何程序（自己用 `ps` 查過再寫）。

你是一次性執行的：回合一結束，背景工作就會被收掉。`make check` 用前景跑、timeout 設長（30 分鐘）。同一個測試跑到第 3 次還不過就換做法或寫進回報。不准改寫歷史、不准 push、不要用 `gh`、不准用 `pkill` 或 `killall`。暫存檔放自己工作區的 `target/`。
