## 送出去時每一塊的角色（K114 ⑰）

`crates/context/src/output.rs` 的 `block_role`：工具說明、釘選、限制、標準、目前這一步、還沒回答的問題、還沒確認的動作、狀態摘要、記憶，全部被標成 Bot（assistant）。第三段排在請求最後面，所以**整個請求以 Bot 的話結尾**：

- Claude 會把最後一則 Bot 的話當成「幫它起頭」，接著那段往下寫；
- OpenAI 的模型會以為自己已經回答過了。

照 K114 ⑰ 改：

1. 第一段（系統提示、工具說明、釘選的記憶、「關於你」，和其他你放在第一段的）全部併進 `TurnRequest.system`，照原本的順序。前段穩定的規則（`context-build` S4）照樣成立：第一段不變，系統提示的位元組就不變。
2. 第二段照原本是誰說的：你的話、舊對話是使用者；Bot 的回答和工具要求是 Bot；工具結果是工具。
3. 第三段（狀態摘要、目前這一步、還沒回答的問題、還沒確認的動作、找回來的記憶）合成**最後一則使用者角色的訊息**，開頭用一個訊息代碼標明「這是程式整理的、不是使用者說的」（放 `locales/`，`turn-` 開頭，照 K119 ⑯）。
4. 工具要求缺參數、或工具結果找不到對應的工具要求 → 回錯誤，不要默默丟掉其中一邊（現在缺參數時是不產生工具呼叫，結果就變成孤兒）。

測試（描述性的名字，預期寫死、不呼叫產品的函式來算），各證明會失敗：

- 任何組出來的請求，最後一則都是使用者或工具，不是 Bot。用性質測試，各種內容都要產生得到（有沒有第三段、最後一步是不是工具結果）。
- 第一段的東西都在 `system` 裡、不在訊息清單裡；第三段的東西都在最後一則使用者訊息裡。
- 只有第三段變了的兩次請求，`system` 的位元組一樣。
- 缺參數、孤兒結果 → 錯誤。
- 用模型閘道公開的介面打假模型，OpenAI 和 Claude 兩種格式各送一次：送出去的請求最後一則不是 Bot，工具要求和結果配得起來（`crates/models` 只讀、不改）。
