# M7a-3：模型閘道要能信任自己簽的憑證（`spec/09` K115）

## 為什麼

`make live-model-check` 第一次對真的本機模型跑過了。格式比對（用工具自己的 HTTP 客戶端）有拿到回應；但**產品的模型閘道連不上那台模型**，因為：

- 那台模型伺服器直接拿一張自己簽自己的憑證當伺服器憑證，而且這張憑證標成「可以簽發別的憑證」。
- 標準的憑證檢查會拒絕這種憑證，就算把它加進信任清單也一樣。
- 閘道現在自己建 HTTP 客戶端，沒有任何地方可以告訴它「這張憑證我信任」。

使用者自己架的模型伺服器常常是這樣。產品連不上使用者自己的模型，等於主要的使用情境不能用。

先讀：`spec/09` K115、K9；`spec/10-behavior/6-integrations-models-settings.md` 的 `settings-n9`（整段，S6、S7 是新的）；`AGENTS.md`。

## 要做的

1. **「信任的憑證」的型別和檢查邏輯，只寫一份。**
   - 之後連伺服器的客戶端、連接器也要用同一份（K115 ④），所以不要寫死在 `models` 裡面。放在哪個套件由你提出來，寫進回報；需要改 `spec/07` 的話在回報裡說，不要自己改 `spec/`。
   - 讀 PEM：一個檔可以有好幾張；不是憑證的內容要回錯誤，不准默默略過。
   - 檢查的規則（`settings-n9` S6）：
     - 作業系統信任的照舊相信。
     - 清單裡的憑證當簽發者：對方的憑證是它簽的 → 相信。
     - 對方直接拿清單裡的某一張出來 → 內容一模一樣才相信，就算它標成「可以簽發別的憑證」。
     - 上面每一種都照樣檢查：名稱或位址對得上、還沒過期。
   - **沒有任何方式關掉憑證檢查**（`settings-n9` S7）：不准出現「接受任何憑證」的程式，測試工具裡也不准。
2. **模型閘道從建構函式收「信任的憑證」清單**，自己建 HTTP 客戶端時套用。照舊不跟轉址、不設 reqwest 的逾時。
3. **憑證錯誤要分得出原因**：不被信任、名稱或位址不對、過期。對應的訊息代碼和翻譯一起加。錯誤分類照 `models-errors` 現有的做法，不要多開一類不必要的。
4. **`make live-model-check` 改用產品的這一份**（K115 ⑤）：
   - 設定檔裡的那張憑證，用「信任的憑證」交給閘道和格式比對用的客戶端。
   - `tests/live-model` 裡自己寫的那一套憑證比對拿掉，不留兩套。
5. **測試**（harness 現在沒有 HTTPS 的假模型，這次補上）：
   - 假模型可以用 HTTPS 啟動。憑證在測試執行時才產生，不存進 repo。產生憑證要用的套件，照 `AGENTS.md` 先查維護者和使用量。
   - 要測到：
     - 自己簽自己、標成可以簽發的憑證：沒加入 → 憑證錯誤；加入 → 連得上；換成另一張內容不同、名稱一樣的 → 憑證錯誤。
     - 清單裡的憑證當簽發者，簽出來的伺服器憑證 → 連得上。
     - 位址對不上、過期 → 憑證錯誤，而且假模型沒有收到任何請求內容。
     - 性質測試：隨機的設定組合，沒有任何一組能讓沒被信任的憑證通過。
   - `T-settings-n9-5`、`-6`、`-7` 那三列要從設定畫面操作，這次驗不到整列：**測試名稱不要用這三個編號**。
   - 把「真的模型那一側」也用 HTTPS 的假模型走一遍：整條 `run()` 在沒有真的設定檔時也測得到。

## 範圍

- 只做模型閘道和 `tests/live-model`、`tests/harness`。設定畫面、連伺服器的客戶端、連接器之後才接。
- 不准讀、不准印、不准複製 `.local/live-model/` 裡的任何檔案。真的那一段由監督者在合併之後跑。

## 回報

照 `AGENTS.md` 第六節，簡短。附上：信任的憑證放在哪個套件、對外的型別和函式；每個測試驗了什麼；新加的套件和你查到的資料。

你是一次性執行的：回合一結束，背景工作就會被收掉。`make check` 用前景跑、timeout 設長。不准改寫歷史、不准 push、不要用 `gh`、不准用 `pkill` 或 `killall`。
