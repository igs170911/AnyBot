# M6a 中途修正 2

我又把你停下來了：`T-server-n8-3` 的後半這次又花了 25 分鐘以上，而且還在改 `netctl`。工作區的改動都還在。

## 先說我寫錯的地方

上一份中途修正說「`net_down` 的時候代理一直開著」。**這句是錯的**：`dev` 上的 `net_down` 本來就會把代理的埠關掉，`net_restore` 再綁回同一個埠。你發現的是對的。

你量到的「綁回同一個埠要等幾十秒」可能也是真的。但這**不是 M6a 要解決的問題**：寫進回報（怎麼重現、量到幾秒），由監督者另外處理。不要再查它。

## 新的做法：不要代理，直接停掉資料庫

「資料庫連不上、之後上線」不需要在 PostgreSQL 前面放任何代理。把測試用的 PostgreSQL 本身停掉、再開起來就好。

1. `tests/harness/src/postgres.rs` 加兩個函式（名字你定）：
   - 停：把 PostgreSQL 停下來，**不刪資料夾**。
   - 開：用同一個資料夾、**同一個埠**再啟動；啟動後確認埠跟原來一樣，不一樣就回錯誤。
   - 重新啟動時埠會不會變，先用一個小測試確認。會變的話，第一次啟動時就把埠固定下來。
   - 附 harness 自己的測試：停下之後連不上；開起來之後用同一個網址連得上，之前建的資料表還在。
2. `T-server-n8-3` 的後半這樣寫：
   - 啟動 PostgreSQL、建好資料庫、記下網址，然後把它停掉。
   - 伺服器當函式庫啟動，傳假時鐘進去。
   - 等紀錄出現第 1 次「連不上」→ 假時鐘快轉 5 秒 → 等第 2 次 → 再快轉 5 秒……一步一步走到假時鐘的第 20 秒。
   - **不要用一個一直自動快轉時間的背景工作。**那會讓伺服器在真實時間裡不停重連，結果不可預期。每一步都是「等到看見上一步的結果，才快轉下一步」，等待要有期限。
   - 把 PostgreSQL 開起來 → 再快轉 5 秒 → 伺服器連上、正常啟動。
   - 要驗到：每次重試之間假時鐘剛好隔 5 秒；紀錄有寫原因；這段時間伺服器沒有退出；資料庫上線後正常啟動。
3. 其他用到「資料庫連不上」的測試（`pg_server_blocked.rs` 這類）一樣改成停掉 PostgreSQL。

## 網路控制的程式，這次完全不改

- `tests/harness/src/netctl.rs`、`netctl_state.rs`、`netproxy.rs`、`netproxy_flow.rs` 要跟 `dev` 一模一樣：`git diff dev -- <檔>` 沒有任何輸出。
- 刪掉你加的 `netctl_bind.rs`、`netproxy_raw.rs`、`net_start_raw`、`net_cut_target`、`net_probe_open`，還有只為它們存在的測試、匯出、相依套件。
- M6a 的 28 個編號裡，沒有一個需要新的網路控制功能。你覺得有的話，先寫進回報，不要自己加。

## 時間

- **同一個測試跑到第 3 次還不過，就停下來。**要嘛換一個更簡單的做法，要嘛寫進回報、先做別的項目。這一條上次就有，這次請照做。
- 除了啟動 PostgreSQL 本身，任何一個測試都不該跑超過 10 秒。跑了 63 秒的測試就是設計有問題，直接換做法，不用再查它為什麼慢。
- A 段全綠就馬上 commit。
