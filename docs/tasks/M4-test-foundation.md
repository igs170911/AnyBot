# 里程碑 M4：整體測試的地基

M5 之後每個功能都要有整合測試和端對端測試，這次把它們要用的地基做好。這次**不做產品功能**，所以規格編號的覆蓋數字不會變，這是正常的。

先讀：
- `AGENTS.md` 的第五條鐵律（程式碼和測試裡不准有中文）。這次寫的程式、測試資料、假模型的腳本內容都用英文。
- `spec/10-behavior/README.md` 的「測試動作詞彙」（環境、環境動作、觀察點、測試種類）。
- `spec/09` K86、K87、K90。
- `docs/plan.md` 的完成條件。

分成 **A、B 兩段**。A 做完 `make check` 全綠就 commit 一次，再做 B，B 做完再 commit 一次。

## 大方向（先照這個設計，有更好的做法先寫進回報問）

- **整合測試把伺服器當函式庫，在測試程式裡啟動。** 假的東西（假時鐘、資料庫位址、要聽的埠）從建構函式傳進去，跟 `main.rs` 傳真東西的是同一個函式。測試透過真的 HTTP 打它，這樣算「從外面打」（K86）。
- **不為了測試加命令列旗標或環境變數**（`--port` 這類）。執行檔層級的測試只測命令列行為。
- **端對端測試（Playwright）透過一個「測試環境」程式控制假的東西**，見 B 段。

## A 段：Rust 的測試地基

1. **沒被編譯到的原始碼檔要擋。**
   - 上一輪的 `versions_tests.rs` 在 repo 裡、沒接進模組，等於從沒跑過，關卡卻全綠。
   - iron-laws 加一道檢查：每個套件 `src/`、`tests/`、`benches/`、`examples/` 底下的 `.rs` 檔，都必須真的被編譯到。例如讀 cargo 建置時產生的 dep-info（`.d`）檔來比對。
   - 附「塞一個沒接上的檔案會被擋」的測試。
2. **時間只能從 `Clock` 拿。**
   - 在 foundation 的 `Clock` 介面加上「等待」：睡到某個時間、等一段時間、逾時。產品程式碼的等待和計時都透過它，假時鐘才快轉得了。
   - clippy 禁用清單加上：`std::time::SystemTime::now`、`std::time::Instant::now`、`std::thread::sleep`、`tokio::time` 的 `sleep`、`sleep_until`、`interval`、`timeout`。
   - 只有 foundation 的真時鐘和 `tests/harness` 豁免，寫進 `spec/07` §3 要求的那種套件自己的 `clippy.toml`，iron-laws 的表格也要更新。
   - 附「塞進去會被擋」的測試。
3. **假時鐘。**
   - 實作 `Clock`，多個元件共用同一個。
   - `advance(多久)` 會讓到期的等待全部醒來，順序照到期時間。
   - 測試要有：
     - 快轉 1 小時，伺服器的 `/v1/health` 回的 `now` 剛好多 1 小時。
     - 兩個等待照到期順序醒來。
     - 逾時在快轉後觸發。
4. **假模型**（`spec/10-behavior/README.md`「假模型」和「環境動作」的第一列）。
   - 一個本機的 HTTP 服務，同時扮演：
     - OpenAI 相容的 Chat Completions。
     - Anthropic 的 Messages API。
   - 兩種都要有串流和不串流，格式照兩家**官方公開的 API 文件**，回報寫你照的是哪一版文件。
   - 腳本動作：
     - 回「…」
     - 呼叫工具〔名稱〕(參數)
     - 不回應
     - 回到一半斷掉
     - 回「…」之後停在思考中（連線開著、不再出字）
     - 回錯誤〔HTTP 碼〕
   - **記下收到的每個請求**（內容和標頭）。金鑰類的標頭只記「有沒有帶」，不記值。
   - 自我測試：用真的 HTTP 客戶端，兩種格式、每個腳本動作都打一次，檢查回傳的格式（例如事件名稱、結尾標記、工具呼叫的欄位）。
5. **網路控制。**
   - 測試裡的連線都經過一個 harness 的代理，用來做：
     - 斷網／恢復：切掉現有連線、拒絕新的。
     - 網路變慢：延遲、頻寬。
     - 伺服器停機／恢復：對外看起來連不上。
     - 「中間的代理」的三種行為：會緩衝串流；閒置 N 秒就切；帶來源位址 X。
   - 每一種都有自我測試，例如串流被緩衝時，客戶端要等到連線結束才收到內容。
6. **測試用的 PostgreSQL**（`spec/09` K90：不用 Docker）。
   - harness 在 `target/` 裡啟動一個臨時的 PostgreSQL 程式：一次測試執行一個，每個測試一個自己的資料庫。跑完用 PID 收掉。
   - 建議用 `postgresql_embedded` 這類套件，安裝位置設在 `target/` 裡、版本固定、下載要驗證雜湊。照 `AGENTS.md` 先查維護者和 RustSec 紀錄，寫進回報。
   - 提供連線位址（用金鑰型別裝），並能跑 `migrations/server/` 的遷移。現在是空的，放一個建表的測試用遷移在 `tests/fixtures/`。
   - 自我測試：
     - 建表、寫入、讀回。
     - 兩個測試的資料庫互相看不到。
     - 收掉後程式和連接埠都釋放了。
   - CI 用同樣的方式。
7. **harness 的寫法照動作詞彙**：函式名稱和參數，讓人一眼對得上 `spec/10-behavior/README.md` 的動作和觀察點。只做這次有的部分。

## B 段：端對端和推播

8. **測試環境程式**：`tests/harness` 裡加一個執行檔。
   - 它啟動一整套隔離環境：伺服器（函式庫、假時鐘）、假模型、網路代理，之後再加別的。
   - 開一個**只聽本機**的控制 API，給 Playwright 用，可以：
     - 寫假模型的腳本。
     - 讀假模型記下的請求。
     - 時間快轉。
     - 斷網、恢復。
     - 讀推播紀錄。
   - Playwright 開始前啟動它，結束後用 PID 收掉。
   - 時間快轉要連瀏覽器的時間一起快轉（Playwright 的 clock 功能）。
9. **Playwright 和手機情境**：`tests/e2e` 做成一個 pnpm 套件。
   - 每種情境是一個 Playwright project：
     - 小 iPhone 加最大字級：WebKit。回報寫清楚「最大字級」怎麼模擬。
     - 大螢幕。
     - 從右到左的語言（阿拉伯文）。
     - 深色模式。
     - 中文、英文。
   - 每種情境都跑一份冒煙測試，對 `apps/web` 檢查：
     - 畫面有出來。
     - 手機寬度沒有橫向捲動。
     - 主控台沒有錯誤。
   - 「從右到左的版面對不對」要等 M8 做多語言才驗，這次不驗。
   - 寫幾個照動作詞彙命名的輔助函式，都用**畫面上的字**找元素，不用 CSS 選擇器。畫面上的字要用訊息代碼，從那個情境語言的翻譯檔查出來，測試裡不寫字面（`spec/09` K91）：
     - 按「…」
     - 在〔欄位〕填〔值〕
     - 畫面出現「…」／畫面沒有出現「…」
   - 一個跨兩邊的自我測試：
     1. Playwright 透過控制 API 寫假模型的腳本。
     2. 直接打假模型，確認照腳本回答。
     3. 再從控制 API 讀回請求紀錄。
     4. 快轉時間，確認 `/v1/health` 的時間跟著動。
   - 截圖放在 `target/`，不 commit。
   - 接進 `make check`（`e2e` 關卡），CI 也要裝瀏覽器。
10. **假推播。**
    - 扮演 Web Push 的推播服務（RFC 8030）。
    - 用測試自己產生的訂閱金鑰解開內容（RFC 8291），記下「送給誰、內容」。
    - 加解密用現成的函式庫，不手寫。
    - 自我測試：用 Web Push 的送出端函式庫送一則，假推播記下的內容要一模一樣。
11. **`docs/testing.md`**：說明怎麼用 harness、測試環境程式、情境。程式碼不寫註解，說明寫在這裡。

## 這次不做（之後的里程碑做，`docs/plan.md` 已更新）

- 假電腦端、電腦供應者：M7 和 M9，等電腦的介面定好。
- 假聊天頻道：做訊息管道的里程碑，等頻道怎麼連定好。
- 假網站、假外部服務、假連接器 X、假外部 agent：各自的里程碑。
- `T-conn-post-*`、`T-conn-sse-*`：M6。要有紀錄的 API 才測得了，這次的網路控制就是給它們用的。
