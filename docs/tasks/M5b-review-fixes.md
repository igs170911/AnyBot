# M5b 審核修正

M5b 我讀過了。大方向對：到上限本身不算超過、/goal 的三個預設每一輪各算各的、使用者自己設的上限整件累計、拒絕後換做法做完算完成；「會失敗」那張表也做得很好。有兩件要修，一件要記下來留給之後。

## 一、時間只在一輪結束時才加上去

現在「時間」的用量只在「一輪結束」那一筆事件才算進去。一輪還沒結束時，不管跑了多久，用量都是 0。所以一輪跑了 10 個小時，4 小時的上限也擋不住它，要等這一輪自己結束才發現。

- 改成：每次看預算的時候（每次問模型之前、每個動作開始之前，`task-budget` S3），用**那一筆事件的時間**算出這一輪到目前為止跑了多久（扣掉卡片開著的時間），加上之前幾輪的，拿去跟上限比。不讀系統時鐘，只用事件的時間。
- 測試：一輪開始；4 小時又 1 秒後套用一筆「問模型」（中間沒有任何「一輪結束」）→ 卡住（超過預算：時間）。同樣的情況，中間有一張卡片開了 3 小時才回答 → 不是卡住。

## 二、問模型之前只看了步數

`task-budget` S3：預算在兩個地方看，**每一項都看**。現在：

- 問模型之前只看步數。
- 動作開始之前只看工具呼叫和時間。

所以 token 剛好用到 1,000／1,000 的時候，下一次問模型不會被擋。改成兩個地方都看每一項（步數、工具呼叫、時間、token、花費；有設上限的才看）：

- 問模型之前：步數、時間、token、花費。工具呼叫不用看（問模型不開動作）。
- 動作開始之前：工具呼叫、時間、token、花費。步數不用看。
- 「到上限本身不算超過」照舊：用量已經到上限、又要再問一次或再開一個動作，才算。
- 測試：token 上限 1,000，第一次的回答用量剛好 1,000 → 不是卡住；接著套用一筆「問模型」→ 卡住（超過預算：token 1,000／1,000）。花費一樣做一組。

這兩項都要照之前的做法證明測試會失敗（把修好的地方改回去，看到變紅），列進回報的表。

## 三、記下來，這次不做

「輪數」這一項（`task-budget` S1 的表：自己接的下一輪，/goal 100、其他 3）要分得出這一輪是誰起的：使用者送一句話起的那一輪不算，自己接的才算。現在「一輪開始」那一筆事件沒有「發起者」，引擎分不出來。`task-events` S2 已經寫了「一輪開始」要帶發起者，那是 M7d 補事件欄位時的事。這次不要動「輪數」，也不要給它預設上限；在程式裡也不要先猜。

## 其他

- 你問的第 1 點：沒有 M5a 這個里程碑，`dev` 上也沒有那個 commit。照現在的 `dev` 做是對的。任務檔也沒有「不准跑 `cargo fmt`」這一條；跑 `cargo fmt` 沒有問題。
- 第 2 點（共用的編譯輸出讓別的工作區的執行檔被拿來跑）：你說得對，是我的設定造成的，已經改回每個工作區自己一份。現在 `cargo metadata` 的 `target_directory` 會是你自己工作區的 `target/`。第一次編譯會比較久。
- 第 3 點：快照版本升到 2、舊的作廢，可以。快照是可以丟掉重算的衍生資料。
- 第 4 點：重試次數預設不限，照規格。

## 驗證和回報

`make check` 全綠就 commit；`git merge dev`、`make check`；簡短回報（兩項怎麼改的、「會失敗」的表）。

你是一次性執行的：回合一結束，背景工作就會被收掉。`make check` 用前景跑、timeout 設長（30 分鐘）。只動 `crates/domain`（和必要時 `crates/protocol`）。只在自己的工作區做，暫存檔放工作區的 `target/`，不改 `spec/`。不准改寫歷史、不准 push、不要用 `gh`、不准用 `pkill` 或 `killall`。遇到「Operation not permitted」是沙箱在擋，不要繞過。
