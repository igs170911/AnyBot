## 第 3 段：匣子和送出（`sync-outbox` S1、S2、S4、S5；`sync-id`；`sync-offline` S5；`conn-batch` S1；`account-n5` S2；K118 ⑦）

10. 加一筆紀錄：當場給編號（`foundation` 的 `RecordId`），先寫進匣子、確定存進磁碟，再回來。
11. 連上後，每條流各自照建立的順序送，一次可以一批。斷線多久都等。
12. **帳號那條流先送**；一個 Bot 的「建立」被伺服器收下了，才送那個 Bot 的流（K118 ⑦）。
13. 網路錯誤一律重送，節奏照第 5 段，不放棄。回應沒收到就當沒送到，照同一個編號再送（伺服器會去重）。
14. 伺服器明確拒收（Bot 已刪除、沒有權限、帳號被停用、不認得的設定…）：那一筆標「沒送出」和原因的代碼，後面的照送。7 天沒拿回的丟掉（走 `Clock`）。
15. 每一筆記著送過沒有。沒送過的可以取消、拿回來；送過一次、可能已經到了的不能取消（`account-n5` S2）。
16. 建立時連不到伺服器、在匣子裡等超過 5 秒才送出的，送的時候標「離線時送出」（`sync-offline` S5）。
17. 相鄰兩次送出至少隔 0.2 秒；有東西要送時最多隔 0.5 秒（`conn-batch` S1）。
18. 測試：`T-account-n5-3`（「回應丟了」用 M6b-1 的「回應在路上掉」）。用描述性的名字：匣子重開後還在、順序不變；帳號那條流先送；被拒收的那一筆有原因、後面的照送、7 天後丟掉；離線時送出的標記。
19. `make check` 全綠，commit。

## 第 4 段：要回來、對不上、本機資料庫壞了（`sync-after` S1–S3；`sync-replica` S2–S4；`server-n8` S1；K118 ⑫）

20. **要第 N 號之後的**：帶 N 和「第 N 號是哪一筆」（N 是 0 時不帶）；還有就接著要，直到沒有。
21. 收到的號有缺（有 N＋2 沒有 N＋1）：從 N 重新要。有缺號的那一段不交給讀副本的人。
22. **對不上**（伺服器回「你比我新」，或 SSE 的「進度」裡同一個號是不同一筆）：
    - 把這條流從第 0 號重新要一遍。
    - 自己有、伺服器沒有的那幾筆，照原本的裝置給的編號重新送上去；伺服器給新的號。
    - 本機這條流照伺服器的號重排。
    - 只補裝置本來就能直接送的種類。伺服器自己寫的那幾種（裁判的事件、刪除和清除那四種）不送，數量記下來交出去。
23. **本機資料庫讀不了**（`sync-replica` S3；`server-n8` S1）：
    - 不當成空的、不覆蓋：把壞的那份**原樣**移到旁邊（位元組不變、名字不撞、不刪），開一份新的，從第 0 號重新同步。
    - 壞的那份裡的匣子，救得回來的照常送出；救不回來的列出來。
    - 交出一個狀態（代碼和參數：原因、壞的那份在哪）給之後的畫面用。
    - 「讀不了」包括：檔案壞了、不是 SQLite、遷移的版本比這一版新到認不得。各自怎麼處理寫進回報；任何一種都不准刪資料。

## 第 5 段：連線、SSE、心跳、重連（`server-n16`；`conn-sse` S2、S4、S5；`conn-heartbeat` S1、S4；`account-n4` S2；`account-n8` S1；K118 ⑧⑪）

27. **連線階段 5 秒**（連上對方、做完 TLS）建不起來就算失敗。**不准用 reqwest 自己的 timeout、connect_timeout**（它們走 tokio 的時間，假時鐘轉不動）：用 `Clock` 自己計時，連線階段要能分開算。
28. **一個客戶端對一台伺服器只有一個重連的節奏**，送匣子、補資料、SSE 共用：
    - 間隔 1、2、4、8、16、30、30…秒，每次另外加 0.5–2 秒的亂數。亂數從建構函式傳進來。
    - 間隔從上一次判定失敗算到下一次開始連。
    - 任何一個背景請求拿到回應就算連上：馬上開 SSE、送匣子、補資料，不等間隔。
    - 連上超過 30 秒才又斷的，下次從 1 秒重來；不到 30 秒又斷的，接著原本的間隔往下走。
    - 間隔的純函式已經有（`outbox.rs`），接著用。
29. **背景的請求連上之後，30 秒沒有任何位元組進來才算失敗**；只要還有位元組進來就不算。很慢的線上補很多資料不會被切。
30. **SSE 客戶端**：
    - 一條 SSE 收提示。收到「進度」：每條流跟本機比，比較新的就用第 20 項去要；同一個號是不同一筆就照第 22 項。
    - 收到「有新的」：號比本機的大就去要；不大就不理。提示漏了、重複了、亂了都不影響結果。
    - 30 秒沒收到任何東西（包括心跳）就照第 28 項重連。
    - 一連上就馬上補，不等下一次（`account-n4` S2）。
    - 伺服器重開：照第 28 項重連，收到「進度」後從自己的進度接著要，不漏、不重複。
    - **每 20 秒至少一個請求**（「監督者定了的」那一點）：SSE 連著時，20 秒內（走 `Clock`）沒送過任何請求，就送一次「要帳號那條流第 N 號之後的」。用描述性的名字測：連著 2 分鐘、沒有別的事，伺服器每 20 秒收到一次；有別的請求時不多送；沒連上時不送。
31. **憑證失效（401）**：停下來，交出「要重新登入」的狀態，不要一直重試。**版本太舊**：停下來，交出那個狀態。
32. **給畫面看的狀態**（`account-n7` S1、S2；`account-n8` S3）：連不到超過 5 秒、有幾筆在等、是不是剛打開還沒連上、連不到的原因、上次同步的時間、大小、花多久。只交資料，用描述性的名字測。

## 規則（請照做）

- **帶規格編號的測試，要證明它擋得住**：
  - 每一個帶編號的測試寫好之後，把它守的那條產品規則故意改壞（一次改一處，不 commit），跑那個測試，確認變紅，再改回來。
  - 回報列一張表：測試、改壞了什麼、有沒有變紅。改壞了還是綠的，不准帶編號：先把測試補到會紅。
  - 例子：`T-server-n16-1` 拿掉亂數；`T-server-n16-3` 拿掉「撐過 30 秒從 1 秒重來」；`T-conn-heartbeat-5` 改成 30 秒沒收到完整的一筆就重連；`T-sync-replica-1` 每次從第 0 號要；`T-sync-replica-5` 不帶「第 N 號是哪一筆」；`T-account-n5-3` 送過一次的也能取消；`T-account-n6-5` 間隔加上亂數；`T-conn-sse-4` 只靠提示、不在重連時看「進度」。
  - 第 1 段的自我測試也照這樣證明會紅。
- **預期的值不准呼叫被測的產品函式來算**：
  - 重連的間隔、亂數的範圍、100 秒裡每一次的時間：在測試裡寫死。
  - 「本機副本跟伺服器一樣」：伺服器那一邊直接讀資料庫，或用替身照 API 拿，不准用被測的函式庫拿。
  - 不准「先呼叫一次產品函式拿結果，再拿同一個函式的結果去比」。
- **測試啟動的每個程序都要收掉，被訊號或逾時砍掉時也一樣**：
  - 伺服器、PostgreSQL、代理都接上 M6a 第二輪做的那一套（pid 檔、收到結束的訊號先停自己啟動的東西、啟動時清掉上次留下的、只照 pid 停）。
  - 你新加的每一種會啟動程序的東西，都要有一個「程序不會留下來」的自我測試，而且它要真的會失敗：故意不收，自我測試要變紅。
  - 函式庫的背景工作：丟掉把手後全部停掉。加一個會失敗的自我測試（例如丟掉把手後，代理再也收不到它的任何請求）。
  - 回報前不要只跑 `ps` 就寫沒有殘留。用 pid 檔和連線埠確認，寫明怎麼確認的。
- **會啟動 PostgreSQL 的測試放在檔名 `pg_` 開頭的測試檔。** 這次的整合測試都要。
- **遷移照 K118 ⑥**（`migrations/client/` 也一樣，M6b-1 的遷移檢查會掃它）：
  - 只准建新表、建不是唯一的索引、加可以是空的或有預設值的欄位、放固定的起始資料。
  - 要唯一的、主鍵、外鍵、檢查：一律寫在 `CREATE TABLE` 那一句裡面。已經有的表不加任何限制。
  - 搬資料由程式做，不寫在遷移檔。
  - **已經合進 `dev` 的遷移檔一個位元組都不准改。**
- **編譯輸出是各工作區共用的**：看到「Blocking waiting for file lock」是正常的，等就好。**不准刪它、不准 `cargo clean`**。
- **整合測試打真的伺服器**：伺服器當函式庫在測試裡啟動（`tests/app-test`），真的 PostgreSQL、假時鐘。客戶端經網路控制的代理連過去。

- **名稱帶編號＝驗完那一列全部的預期**。預期裡有「畫面」的，用描述性的名字，編號留在基準檔。

- **SQL 在編譯時檢查**。
- 測試的檔案都放自己工作區的 `target/`。不碰使用者真的資料夾和鑰匙圈。
