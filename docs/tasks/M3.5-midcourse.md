# M3.5 中途修正

你跑 `cargo test -p anybot-app-server --test install_startup` 卡了 10 分鐘，我把你停掉了。工作目錄裡的修改都還在，接著做，但先照下面改方向。

## 卡住的原因

- `cargo test` 在同一個程式裡同時跑好幾個測試，不管 nextest 的分組，所以好幾個測試同時搶 8787。
- `second_server_exits_with_one_while_first_keeps_serving_health` 的第二台伺服器因此成功開起來，一直不結束。
- `run_program` 讀它的 stdout 要讀到結束，又沒有期限，就永遠等下去。
- 以後 Rust 測試一律用 `cargo nextest run` 跑（或 `make` 的目標）。`AGENTS.md` 第三節已經加上這條。

## 要改的

1. **拿掉 `--lang` 和 `--json-lines`。**
   - 規格沒有這兩個旗標，任務也寫了「不改產品行為」。`AGENTS.md` 第三節加了一條：不准為了測試在正式程式加旗標、環境變數、輸出模式。
   - 伺服器印的字照 K92：現在還沒有伺服器設定，一律用英文。M6 伺服器設定進資料庫之後，才照設定的語言。
   - 測試照 M3.5 任務第 6 項做：用 `messages` 以 `en` 排出那個代碼加參數的字，跟執行檔真的印出來的那一行比。
   - 如果你覺得「機器讀得懂的輸出」是需要的產品功能，寫進回報的「要問的問題」，不要先做。
2. **`messages` 不准依賴其他內部套件**（`spec/07` 的依賴表：`messages` 是「無」）。
   - `messages` 只做「代碼＋參數＋語言 → 字」。「印出一行、寫到 stdout 還是 stderr」這類事（現在 `emit.rs` 做的）放到用它的程式，例如 `apps/server`。
   - foundation 的錯誤怎麼對到訊息代碼，放在同時看得到兩邊的地方（例如 `apps/server`）。
   - depcheck 的表格要照 `spec/07`。如果你為了這次改了表格，讓 `messages` 可以依賴別的套件，改回來。
3. **不准悄悄換成預設值**（`AGENTS.md` 第三節「算不出來的值要回錯誤」）。
   - 例如 `MessageCode::from_str(...).unwrap_or(...)`、`Lang::parse(...).unwrap_or(Lang::En)`。代碼不存在代表程式寫錯了，要靠產生出來的列舉在編譯時擋，不要執行時轉成字串再猜。
   - 這次改到的檔案，全部掃一次 `unwrap_or(`、`unwrap_or_default(`、`unwrap_or_else(`。是「算不出來的值」的就改成回錯誤；不是的，在回報裡逐一說明。
4. **harness 等外面的東西都要有期限。**
   - `run_program`、`next_stdout_line`、`finish` 這類函式，等程式結束或等一行輸出時都要有期限，例如預設 10 秒、可以調整。
   - 到期就用 PID 收掉那個程式，回錯誤。錯誤訊息寫清楚：等的是什麼、等了多久、目前收到的輸出。
   - stdout 和 stderr 要同時讀。現在是讀完 stdout 才讀 stderr：程式把 stderr 寫滿時會卡住，兩邊互相等。
   - 附自我測試：
     - 跑一個不會自己結束的程式，要在期限內回錯誤，而且那個程式已經不在了。
     - 跑一個在 stderr 寫很多字（超過 pipe 緩衝，例如 1 MB）才結束的程式，不能卡住。
