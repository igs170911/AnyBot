# M7d 分成四件小的

`docs/tasks/M7d-turn-thin-slice.md` 是 M7d 的完整說明（規格、監督者定了的六點、要用到的公開介面、規則）。照「每件約一小時、做完就驗、就合」的做法，分成下面四件，**一次派一件**，前一件合進 `dev` 才派下一件。每一件都讀完整說明，但只做自己那幾段、只拿自己那幾個編號。

開工條件（四件都一樣）：`dev` 上已經有 M7a（模型閘道）、M7b（上下文編譯器）、M7c（信任層的單一入口）。

## M7d-1：只有對話的一輪

- 範圍：A 段（事件、紀錄的介面、先記再做的順序）；B 段的第 4–6 項（組上下文、問模型、記下回答）；C 段的第 8–10 項（開始、停下的原因、模型說的話不改狀態）。這一件**沒有工具**：回答裡有工具要求時，先記成「這一版還不能做工具」的結果給模型（第 2 件接上）。
- 編號：`T-turn-loop-11`（送「你好」、回「你好」：完成（已回覆）、沒有交付報告、請求 1 個）。只有對話的任務不出報告：這一件只做「判斷要不要出」，報告本身是第 4 件。
- 另外用描述性的名字測：上下文預算不夠 → 假模型沒有收到請求、任務卡住；閘道失敗 → 任務失敗；固定那一段的三塊照順序、照語言；回覆裡寫「完成了」不改任何狀態；「問模型」那一筆早於請求送出（性質測試）。

## M7d-2：一步裡的動作

- 範圍：B 段第 7 項（每個工具要求走 M7c 的單一入口、紀錄的順序、被拒和沒執行、證據的短編號、每個要求都有結果給模型、完整輸出交給「存原文」）。
- 編號：`T-turn-loop-3`、`T-turn-loop-9`、`T-trust-pipeline-1`、`T-trust-verify-1`、`T-computer-ops-2`、`T-files-shell-4`、`T-files-edit-7`、`T-files-edit-8`。
- 另外用描述性的名字測：一步 3 個工具、中間被一律拒絕 → 第三個沒執行；入口回「要問」→ 沒執行、沒有自動允許；「要做什麼」那一筆早於假電腦端記下的操作（性質測試，500 組）。

## M7d-3：多步的一輪和 Bot 的電腦上的規則

- 範圍：同一輪跑很多步；Bot 的電腦上的把關規則從回合這一層看。
- 編號：`T-turn-loop-1`、`T-sandbox-deny-3`、`T-sandbox-levels-4`、`T-files-n2-2`、`T-context-build-4`、`T-context-state-2`。
- `T-context-build-4`、`T-context-state-2` 是編譯器的行為從回合這一層看；編譯器有問題就回報，不要改 `crates/context`。

## M7d-4：收尾、完成閘門、交付報告、整條路

- 範圍：D 段（收尾的順序、完成閘門、交付報告的純函式、整條路）。
- 編號：`T-turn-loop-2`（這是 M7d 最重要的一個：在桌面送一句話，改檔、跑指令、回一句，任務完成（已驗收））、`T-turn-loop-12`、`T-task-done-gate-7`。
- 另外用描述性的名字測：改檔之後重讀的雜湊不相符 → 不是完成；最後一個不是只看的動作失敗 → 未驗收（驗收沒通過）；所有事件重播一次得到一樣的狀態。

走完第 4 件，就有第一條完整的路：你說一句話 → 開任務 → 用工具 → 把關 → 留證據 → 驗收 → 交付報告。
