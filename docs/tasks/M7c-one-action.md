# M7c：一個動作從頭到尾（電腦介面、假電腦端、信任層的單一入口、三個工具）

> 定稿，照 K119 之後的規格寫（`spec/09` K119、`spec/07` §3、`10-behavior/README.md` 新的幾段、`turn-loop`）。
> 原本的〔待定〕都定了，見「監督者定了的五點」和「已經定了的」。

Bot 要做的每一件事（改檔、跑指令…）都走同一條路：**把關 → 做 → 留證據 → 驗收**（`spec/02` A15、`trust-pipeline`）。這次把這條路做出來，先只接三個工具：改檔、讀檔、跑指令。

這次**沒有模型、沒有回合**。輸入是「一個工具要求、一台電腦、一份把關設定」，輸出是把關紀錄、證據、給模型看的結果、一行摘要。把它接進回合迴圈是下一個任務（M7d）。

做完後，下面列的 4 個規格編號要有整列驗到的測試，名稱照 `AGENTS.md` 第二節第 4 條。

你在並行工作（`AGENTS.md` 第七節）：自己的工作區和分支，從 `dev` 切，分支名用 `ws/m7c`。

**你是一次性執行的**：回合一結束，背景工作就會被收掉。`make check` 用前景跑、timeout 設長（30 分鐘），不准結束回合去等通知。

**`models` 和 `context` 還在別的分支審查。這次不准依賴它們，也不准讀別的分支。**

## 監督者定了的五點（照每一點「建議」那一行做）

這五點原本規格沒寫，監督者看過，都照建議定了。第 1 點多一條：路徑先把符號連結解開再判斷；解開之後落在工作資料夾外面的，不算自己的資料夾，照六類的「刪除」先問。第 3 點已經寫進 `turn-loop` S3。第 4 點：不拿 `T-trust-pipeline-8`。第 5 點：套件叫 `tests/runner-test`。

1. **Bot 的電腦上，怎麼算「只動它自己資料夾的刪除」**。`safety-n5` S2 說這種 `rm` 直接做，沒說程式怎麼認。
   - 建議：看刪除類指令的每一個路徑參數。相對路徑、或落在工作資料夾裡的絕對路徑，才算自己的資料夾。有 `..` 跳到外面、絕對路徑在外面、用了變數或看不出會展開成什麼的寫法 → 不算，照六類的「刪除」先問。
   - 這次照建議做，寫進回報。
2. **輸出太長時「錯誤位置的前後」那一段，由哪個套件算**。`files-shell` S3 和 `context-mask` S2 用同一份固定樣式。這次不准依賴 `context`，兩邊各寫一份又會走樣。
   - 建議：這次 `shell` 只做「頭尾各約 6,000 字」那一半；錯誤位置的三段不做，也不拿 `T-files-shell-3`。之後把找錯誤位置的純函式放在兩邊都能依賴的 `domain`，另外開工。
3. **電腦連不上的那個動作要記哪幾筆**。`turn-loop` S3 寫「沒執行的動作沒有把關、沒有證據」，但連不上是過了把關、要動手時才發現的。
   - 建議：把關紀錄照有；結果是「沒執行（電腦連不上）」；不寫證據（沒有實際回傳）；給模型「〔電腦〕現在連不上：〔原因〕」。這次照這樣做。
4. **`T-trust-pipeline-8` 這次拿不拿**。那一列要四種來源的動作（內建、連接器、重播、外部 agent），後三種產品裡還沒有。
   - 建議：不拿。用測試裡的假執行器替後三種，只證明得了入口，那三種真的接上時沒有人會再驗這一列（K86：基準檔不能藏東西）。這次用描述性的名字把同樣的性質測起來；編號等四種來源都接上入口再拿。
   - 要是監督者決定拿，編號是 5 個，測試的寫法見「C 段」第 11 項的說明。
5. **新的測試輔助套件叫什麼**。建議 `tests/runner-test`，M7d 也用它。

## 套件分工（照 `spec/07`）

- `computers`：
  - **電腦介面**：一組操作，這次只要：回報能力宣告、跑指令、讀檔、寫檔、查一個路徑在不在。每個操作回一份**實際結果**（`computer-ops` S2）。
  - 跑指令、寫檔、讀檔都要收一張通行證才能呼叫。`computers` 可以依賴 `trust` 就是為了這個。
  - 失敗分兩種：電腦連不上、操作本身失敗（`computer-ops` S4）。
  - 這次不做任何真的電腦，也不做線上的格式和版本號。骨架裡的佔位函式可以拿掉；iron-laws 和 depcheck 對這個套件的檢查要照樣過。
- `trust`：
  - **通行證**：只有把關的結果是「直接做」或「問了、你允許了」才產生。欄位私有，別的套件建不出來。
  - **單一入口**：收一個動作，照 `safety-gates` 的順序算出結果和把關紀錄；放行就發通行證、叫執行的人去做、把實際結果記成證據、做動作層驗收。
  - 規則的前半（從一個動作算出 M5 那個引擎要的輸入）：`sandbox-deny`、`sandbox-levels`、每種電腦的預設規則。
  - 證據紀錄、把關紀錄的產生。
  - 執行的那一方是 `trust` 定的一個介面，由呼叫的人傳進來。`trust` 自己不依賴 `tools`、`computers`、`mcp`。
- `tools`：
  - 工具的登記表：名稱、給模型的說明和參數、等級（`task-effects` S1）、怎麼從參數算出把關要看的東西（指令原文、路徑）。
  - 三個工具的最小版：`edit_file`、`read_file`、`shell`。
  - 給模型看的結果：從實際結果算出「代碼加參數」，再照語言排成字。
- 實際結果、證據紀錄、把關紀錄的型別放 `protocol` 還是 `domain`，照 `spec/07` 的依賴方向決定，寫進回報。**放在新檔**，不要改 `known_task_event_kind.rs` 和 `task_events.rs`（M7d 才改）。
- `tests/runner-test`（新的測試輔助套件，名字見「監督者定了的」第 5 點）：假電腦端。產品套件只能把它當開發用依賴。`tests/harness` 不動。
- 根目錄 `tools/`（自家的檢查工具，不是 `crates/tools`）：
  - `depcheck` 的表照 `spec/07` §3 改：`tools`、`computers`、`mcp` 可以依賴 `trust`；`models` 另列一列；加上新的測試輔助套件。
  - 加一個檢查：`trust` 以外的套件建不出通行證。
- `locales/`、`messages`：新的訊息代碼，en 和 zh-TW 都要有。工具的結果用 `tool-` 開頭，把關和拒絕用 `gate-` 開頭。
- **這次不碰**：`runner`、`context`、`models`、`store-*`、`server`、`sync`、`domain` 的事件引擎和預算。

## A 段：規則的前半（純邏輯）

1. **一律拒絕的指令**（`sandbox-deny` S1–S3）：
   - 10 種照 S1。
   - 用 `;`、`|`、`&`、`&&`、`||`、換行串起來的，拆開一段一段看；有一段命中，整串拒絕。
   - 前面的 `VAR=值`，和包在 `env`、`command`、`nohup`、`time`、`nice`、`stdbuf`、`timeout` 裡的，要看穿。
   - Bot 的電腦上可以 `sudo`，但 `sudo` 後面接的照樣比。
   - `trust_floor.rs` 現在那 6 個開頭字串換成這一套。已經有的 `T-trust-floor-4` 要照樣過。
   - 測試：`T-sandbox-deny-1`、`T-sandbox-deny-2`。
2. **使用者電腦上的三種結果**（`sandbox-levels` S1–S4）：
   - 24 種唯讀指令照 S2 的清單，一個都不能多、不能少。
   - 一串指令每一段都是唯讀、而且沒有用 `>` 寫檔，才算直接做。
   - 「每次問」的幾種照 S4：寫檔、會改東西的選項、引號或括號沒成對、藏起來的子指令、開互動 shell。
   - 測試：`T-sandbox-levels-1`。
3. **每種電腦的預設規則**（`safety-n5` S2、S6、S7，`sandbox-n4` S1、S2）：
   - 輸入：動作（哪個工具、指令原文或路徑）、這台宣告的能力（是不是 Bot 的電腦、是不是使用者的電腦、有沒有指令沙盒）、工作資料夾。
   - 輸出：直接做／先問／每次問／拒絕，加上是哪一條規則。
   - 沒宣告的能力當成沒有；沒宣告有沙盒就當成沒有沙盒。
   - **Bot 的電腦**：
     - 指令和檔案直接做。
     - 屬於寄給別人、分享、發佈、付款的指令（例如 `git push`、`npm publish`）先問。六類怎麼認用 M5 的 `safety_n5.rs`，不另外寫一份。
     - 只動自己資料夾的刪除直接做，把關紀錄的規則寫「Bot 的電腦：自己的資料夾」。怎麼算「只動自己的資料夾」照「監督者定了的」第 1 點。
   - 這一層算出來的結果餵給 M5 的引擎（`gate_full.rs` 的 `decide`）。引擎的先後順序不要改。
4. **這個動作是不是「只看」**：唯讀的工具，或只用那 24 種唯讀指令的指令，才算（`task-done-gate` S6）。把關紀錄帶著這個答案；M7d 的完成閘門要用。
5. 這一段全是純函式：不看時鐘、不碰檔案。

## B 段：電腦介面和假電腦端

6. **電腦介面**（`computers`）：
   - 能力宣告的型別：照 `computer-caps` 那張表的列。這次用得到的是：跑指令、讀寫檔、是哪一種電腦、有沒有指令沙盒。其他能力的欄位先有，值是「沒有」。
   - 實際結果的內容照 `computer-ops` S2：
     - 跑指令：指令原文、哪台、結束碼、完整輸出、花了幾秒。
     - 寫檔：路徑、改前和改後的 SHA-256；新建的改前記「不存在」。
     - 讀檔：路徑、內容的雜湊。
   - 時間一律走 `Clock`。
7. **假電腦端**（`tests/runner-test`），照 README 那一列：
   - 建的時候給能力宣告：宣告成 Bot 的電腦、Linux、Mac、Windows、沒有指令沙盒。
   - 檔案：記憶體裡的一棵樹。讀、寫、查存不存在、算雜湊都照真的語意做。
   - 指令：照腳本。腳本一條是「指令原文 → 輸出、結束碼、花多久、順便改了哪些檔」。花多久走假時鐘。
   - **沒有腳本的指令 → 回「操作本身失敗」，說這個假電腦沒有這條指令的腳本。不准回空白當成功。**
   - 可以設成連不上。
   - 記下收到的每個操作，測試用它確認「沒有執行」。
   - 附自我測試：寫了讀得回來、雜湊對、沒有腳本會錯、連不上會錯、花多久真的照假時鐘。
8. `computers` 裡**沒有**任何假的實作，也沒有只給測試用的建構函式。

B 段做完，`make check` 全綠，commit。

## C 段：通行證和單一入口

9. **通行證**：
   - 只有 `trust` 的把關函式建得出來。沒有公開的建構函式，也沒有「給測試用」的那種。
   - 記著它放行的是哪一個動作。拿別的動作的通行證去做，要被擋下。
   - 附兩個測試：沒有通行證，呼叫電腦介面的跑指令編譯不過；`trust` 以外的套件建不出通行證（照 `crates/foundation/tests/compilefail` 的做法）。另外加上根目錄 `tools/` 的那個檢查。
10. **單一入口**（`trust-pipeline` S1–S5、`turn-loop` S7）：
    - 輸入：一個動作、電腦介面、把關的設定、執行的人，加上呼叫的人給的：哪個任務、哪一輪、證據的短編號、要排成哪個語言。
    - 結果只有三種：直接做、先問、拒絕。每個結果都有把關紀錄：第幾關、哪一層、哪條規則、判斷來源（`safety-gates` S4、`autonomy-n1` S1），和「是不是只看」（第 4 項）。
    - **先問**：這次不做卡片。入口回「要問」，附上卡片要的資料；呼叫的人給了答案，再接著走。答案只有「允許」和「拒絕」兩種進得來。
    - **放行後才做**。做完，同一份實際結果算出三樣，不各算各的：
      - 證據（帶著呼叫的人給的短編號）。
      - 給模型看的結果：代碼加參數，帶著那筆證據的短編號。
      - 一行摘要的欄位：哪個工具、參數的摘要、成功或失敗、結束碼、多大、原文的編號（`context-mask` S1）。這次只交出欄位，排成字是之後用到它的人的事。
    - 動作的結果是這四種其中一種：完成、失敗、被拒、沒執行（`turn-loop` S1）。
    - **拒絕的、問了被拒的，也各寫一筆證據**：結果是「被拒」，帶原因。
    - **動作層驗收**（`trust-verify` S1），算在那個動作裡：
      - 寫檔：重讀那個檔，雜湊要等於寫進去的內容。結果寫進同一筆證據，判斷來源「程式檢查」。重讀的那一次照樣要通行證，但不另外多一筆證據。
      - 指令：結束碼有記到就算驗到。結束碼不是 0，這個動作是「失敗」。
    - **沒辦法在動作前把關的動作**（外部 agent 自己的內建工具）：入口另外有一條「只回報結果」的路，證據標「未經把關」（S5）。這次只做這條路本身，不接外部 agent。
    - 電腦連不上：照「監督者定了的」第 3 點。
11. **證據紀錄**（`activity-evidence` S1）：
    - 欄位：編號、短編號、時間、哪個任務、哪一輪、哪台電腦、哪個工具、放行紀錄、結果、驗收、判斷來源。
    - 這次做四種：看了、改了、執行了、核准。
    - 指令的輸出在證據裡留前後各 6,000 字；完整的照內容算一個編號，交給呼叫的人去存。這次不做存的地方。
    - **建證據的函式只收實際結果和把關紀錄。沒有任何入口收一段自由的文字。**
12. 用描述性的名字測：
    - 改檔在 Bot 的電腦上直接做，證據有前後雜湊、同一筆有「重讀雜湊相符，程式檢查」。
    - 指令結束碼 3：證據有結束碼 3，動作的結果是「失敗」。
    - 被拒的動作沒有碰到電腦（看假電腦端的紀錄），有一筆「被拒」的證據。
    - 重讀的雜湊不相符時（假電腦端設成寫進去的跟讀回來的不一樣），驗收是沒通過。
    - Bot 的電腦上 `rm a.txt`：直接做，把關紀錄的規則是「Bot 的電腦：自己的資料夾」。`git push`：回「要問」，類別是發佈。
    - 電腦連不上：結果是「沒執行」，沒有證據，假電腦端沒有收到那個操作。
    - 同一份實際結果算出的三樣，結束碼、雜湊、路徑都一樣。
    - 性質（500 串，每串 1–20 個動作，放行和拒絕隨機，另外混進走「只回報結果」那條路的）：每個執行過的動作都有把關紀錄；沒有掛鉤的都標「未經把關」；證據筆數＝執行過的＋被拒的。這就是 `T-trust-pipeline-8` 的內容，名字照「監督者定了的」第 4 點。入口要是產品真正的那一個；標準答案由產生器在產生時就記下。

C 段做完，`make check` 全綠，commit。

## 規則（請照做）

- **每個對外動作都過把關**：電腦介面的跑指令、寫檔、讀檔沒有通行證就呼叫不了。不准開一條不用通行證的路，測試用的也不行。
- **模型的字不會變成證據**：證據只從電腦介面的實際回傳和把關紀錄來。
- **帶規格編號的測試，要證明它擋得住**：
  - 每一個帶編號的測試寫好之後，把它守的那條規則在產品程式裡故意改壞（一次改一處，不 commit），跑那個測試，確認變紅，再改回來。
  - 回報列一張表：測試、改壞了什麼、有沒有變紅。
  - 改壞了還是綠的測試，不准帶編號：先把測試補到會紅。
  - 例子：`T-sandbox-deny-2` 把「看穿 `nohup`」拿掉；`T-sandbox-levels-1` 在唯讀清單多放一個 `rm`；`T-files-shell-7` 把上限的檢查拿掉。
- **預期的值不准呼叫被測的產品函式來算**：
  - 雜湊：在測試裡另外算，或寫死已知的值。
  - 該不該放行、是哪一類：由產生器在產生時就記下，或在測試裡一條一條寫出來。
  - 不准「先呼叫一次產品函式拿結果，再拿同一個函式的結果去比」。
- **不准默默退回**：算不出雜湊、讀不到檔、沒有腳本、參數不對、規則讀不懂，都回錯誤或拒絕。不准用 `unwrap_or`、`unwrap_or_default`、把錯誤丟掉的 `.ok()` 換成某個值。
- **不准為了測試加東西**：產品套件不准有只給測試用的旗標、建構函式、`cfg(test)` 的另一條路。假的東西從建構函式傳進去。`#[cfg(test)]` 只准掛在 `mod` 和 `use` 上。
- **被測的要是產品真正在用的那段程式**。
- **時間走 `Clock`**。測試用假時鐘；等待都要有真時間的期限。
- **測試啟動的東西要收掉**。這次應該不用啟動任何程序；真的啟動了，要有「離開範圍就一定停掉」的保護，回報前用 `ps` 確認。
- **名稱帶編號＝驗完那一列全部的預期**。只驗一部分就用描述性的名字。
- 翻譯檔兩種語言都要有。zh-TW 的字照規格裡的字，不准有簡體字。
- 規格沒寫清楚的，不要猜，寫進回報的「要問的問題」。不得不先做時，選最小、之後好改的做法，也寫進回報。
- **40 分鐘內要有一個全綠的 commit**。做不到就先停下來回報做到哪。
- **同一個測試跑到第 3 次還不過，就換做法；換了還不行就跳過，寫進回報。**
- 不准改寫歷史、不准 push、不要用 `gh`、不准用 `pkill` 或 `killall`。暫存檔放自己工作區的 `target/`。不改 `spec/`。
