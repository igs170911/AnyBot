# M7c 審核修正

M7c 在 GitHub 的 Linux 檢查是綠的（538 個測試全過），規格編號也比之前誠實。但獨立審查找到三個嚴重的安全洞，全綠的檢查抓不到；我對過前三項的程式。**這一輪只修阻擋項**，範圍是下面四節；其他改進（逾時、stderr、`..` 的處理、prefix 比對太寬…）之後另外排，這一輪不要順手做。

行號是 `ws/m7c` 審查時的位置，動手前自己再對一次，清單寫錯的照實回報。先 `git merge dev`（我已經幫你合過一次，`dev` 的歷史改寫過：commit 編號都變了、內容一樣，屬於正常）。

## 一、通行證和「要問」的單子不能偽造（最重要）

1. **把關結果可以自己造**（`crates/trust/src/gate_flow.rs` 的 `GateVerdict`，從 `lib.rs` 匯出）：欄位全公開，還有一個公開的函式，只要結果欄位是「允許」就發通行證。任何套件都能自己造一個「允許」、或把真的「拒絕／要問」改成「允許」，拿到任何動作的通行證。
2. **「要問」的單子可以自己填**（`pipeline.rs`、`pipeline_run.rs`）：單子的欄位公開、可以複製；回答的函式是公開的，不檢查單子是不是把關發的、原本是不是「要問」。所以可以把 `sudo rm -rf /` 放進一張單子、自己回答「允許」，就拿到通行證、真的執行。「已經允許、直接執行」的那個函式也是公開的。
3. 要做到：
   - **套件外面拿到通行證的唯一方法，是呼叫單一入口。** 把關結果的欄位和發通行證的函式都不公開（`pub(crate)`）；「直接執行已允許的」那條路也不公開。
   - **單子是不透明的**：欄位不公開、不能複製、不能自己建；回答時把單子交回去（用掉就沒了）。單子裡記著把關原本的結果和要做的動作，回答只能把「要問」變成允許或拒絕；原本是「拒絕」的，任何回答都不能放行。
   - **通行證只對它發給的那一個動作有效**，不能複製、不能拿去做別的動作。
   - 加測試（描述性的名字）：沒有任何公開的方法能在不經過把關的情況下拿到通行證（用編不過的測試證明：自己建把關結果、改它的欄位、自己建單子、複製單子、複製通行證，各一個）；把關「拒絕」的動作，經過「要問、回答允許」也不會執行；`ls` 的通行證拿去跑別的指令會被電腦端拒絕。
   - `tools/iron-laws` 的通行證守護只找建構通行證的那一段字，抓不到上面這些。編不過的測試比較可靠；守護改不改你決定，但要寫清楚它擋得到什麼、擋不到什麼。

## 二、真的電腦端：這一輪拿掉

`crates/computers` 的 `BotComputer` 每一個操作都不看通行證，所以拿 `ls` 的通行證也能跑任何指令；它還宣稱自己有指令沙盒，其實是直接在主機上跑；也沒有自己再擋一次一律拒絕的指令（`sandbox-deny` S4）。任務本來就說這一輪不做真的電腦端。

- 把 `BotComputer` 和它的整合測試拿掉。`crates/computers` 只留電腦介面（型別和 trait），之後做 Bot 的電腦時再做真的。
- 介面的規定寫清楚：每個實作在每一個操作開始時，都要先確認通行證是發給這個操作的，不是就拒絕。測試用的假電腦端（`tests/runner-test`）照這條做，加一個測試證明它會拒絕不對的通行證。
- 沒有用到、又不需要通行證的那個介面（`runner.rs` 的 `ComputerRunner`）拿掉。

## 三、安全規則被繞過

1. **一律拒絕的指令**（`sandbox_deny.rs`）：
   - 換行接起來的指令沒有被拆開：整理字串時把換行變成空白，才去拆。要先照換行、`;`、`&&`、`||`、`|`、`&` 拆，再整理每一段。
   - `sudo` 後面有選項的（例如 `sudo -u root mkfs.ext4 /dev/sda1`）沒有被看穿：只拿掉了開頭剛好是 `sudo ` 的那一種。把 `sudo`、`doas`、`env`、`nohup`、`nice`、`timeout`、`xargs` 這類外包裝（連同它們的選項）一律看穿，再判斷裡面的指令。
2. **「會離開這台電腦」的四類**（`machine_rules.rs`、`safety_n5.rs`）：現在只看整行開頭的兩個字，沒有拆、沒有看穿外包裝，所以 `cd repo && git push`、`git -C r push`、`nohup npm publish` 在 Bot 的電腦上都直接做了。改成每一段都拆開、看穿外包裝再判斷；git 的全域選項（`-C`、`-c` 這類）要跳過再看子指令。
3. **「只動它自己資料夾的刪除」**（監督者定的第 1 點）：
   - 只檢查第一個路徑（`command_target.rs`），所以 `rm a.txt /etc/passwd` 被當成自己的資料夾。每一個路徑都要檢查，有一個在外面就不算。
   - `$VAR`、`~`、萬用字元被當成相對路徑。看不出會展開成什麼的寫法，一律不算自己的資料夾。
   - 路徑在判斷前被轉成小寫。不要改大小寫。
   - 解析符號連結時失敗，現在會退回原本的字串、然後直接放行。解析不了一律不算自己的資料夾。
   - 自己的資料夾以外的刪除，現在是「拒絕」，監督者定的是「要問」。
   - 判斷用的工作資料夾是請求裡帶的；改成用電腦宣告的那一個。

每一項加測試（描述性的名字），並證明會失敗：把修好的地方改回去，看到變紅，再改回來。回報裡列成表。

## 四、規格編號和證據

1. `T-sandbox-levels-1` 放回基準檔、測試改描述性名字。唯讀清單（`sandbox_levels.rs`）跟規格 S2 對不上：多了 `less`、`more`、`egrep`、`fgrep`、`ps`、`top`、`uptime`、`free`、`vm_stat`、`iostat`、`purge`，少了 `echo`、`rg`、`date`、`which`、`sort`、`uniq`、`diff`。照規格改清單；測試的預期要照規格那一列**寫死**，不准拿產品自己的清單跑迴圈（現在把 `rm` 加進清單也會綠）。另外有一個測試說 `echo hello` 要問，跟規格相反，改掉。改好、證明會失敗之後，才可以把編號拿出基準檔。
2. `T-sandbox-deny-2` 放回基準檔：產生器永遠把危險的指令放在第一段、無害的只接在後面，所以「拆開」從來沒被測到（拿掉任何一種連接符號都還是綠的，換行那個洞就是這樣漏掉的）。那一列要危險的指令前後都有無害的。改好、證明會失敗之後，才可以拿出基準檔。
3. **證據的種類**：被拒、失敗、沒執行的證據現在都用「已核准」那一種（`evidence.rs`）。照 `activity-evidence` 加上對應的種類，不要用「已核准」加一段說明代替：之後的完成閘門、活動頁、報告都會照種類算。
4. 建證據的函式不公開（`pub(crate)`）：證據只能由單一入口從電腦介面的實際結果、或把關的拒絕產生。

## 驗證和回報

- 順序：一 → 二 → 三 → 四。每一節 `make check` 全綠就 commit，不要累積。
- 全部做完 `git merge dev`、`make check`，簡短回報：每一項怎麼改的；「會失敗」的表；基準檔裡這個里程碑最後拿出來的編號（應該只剩 `T-sandbox-deny-1`、`T-files-shell-7`，加上你修好、證明過的那兩個）。
- 沒做完的照實寫，不要寫成做完了。編號寧可少報。

你是一次性執行的：回合一結束，背景工作就會被收掉。`make check` 用前景跑、timeout 設長（30 分鐘）。同一個測試跑到第 3 次還不過就換做法。只在自己的工作區做，暫存檔放工作區的 `target/`，不改 `spec/`。不准改寫歷史、不准 push、不要用 `gh`、不准用 `pkill` 或 `killall`。遇到「Operation not permitted」是沙箱在擋，不要繞過。
