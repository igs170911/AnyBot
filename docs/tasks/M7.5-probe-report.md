# M7.5 探路報告（B13）

本報告依 `docs/tasks/M7-plan-brain-context.md` B13 執行實測，回答 7 項技術探路問題並建立兩個守門整合測試；所有試編探針 crate 皆置於工作區 `target/probe/`，未更動 `deny.toml` 與 workspace `Cargo.toml`。

## 一、7 題結論、證據與影響

### 1. SQLite FTS5 與 `trigram`、`unicode61` + `bm25()`
- **結論**：可用。`sqlx` 內建 `libsqlite3-sys 0.40.0`（SQLite `3.54.1`）已編入 FTS5，支援 `tokenize='trigram'` 查詢 3 字以上路徑片段與中文片段，並支援 `tokenize='unicode61'` 搭配 `bm25()` 排序。
- **證據**：
  - 指令：`cargo nextest run -p anybot-store-client --test brain_probe --no-capture`
  - 守門測試：`crates/store-client/tests/brain_probe.rs`（`sqlite_fts5_trigram_available`）
  - 輸出：
    ```text
    bm25_top=1 score=-0.00000176
    sqlite_version=3.54.1
    PASS [   0.018s] (1/1) anybot-store-client::brain_probe sqlite_fts5_trigram_available
    ```
- **影響**：B18（客戶端副本索引）可直接使用 SQLite FTS5 `unicode61` 與 `trigram` 兩張表，不需額外 SQLite 擴充套件。

### 2. 測試用 PostgreSQL（`postgresql_embedded 0.22` theseus `=17.6.0`）擴充套件
- **結論**：**`pg_trgm 1.6` 可用；`vector`（pgvector）與 `pg_bigm` 皆不存在**。
- **證據**：
  - 指令：`cargo nextest run -p test-harness --test pg_brain_probe --no-capture`
  - 守門測試：`tests/harness/tests/pg_brain_probe.rs`（`pg_brain_extensions_report`）
  - 輸出：`ext=pg_trgm default=1.6 installed=none`，且 `CREATE EXTENSION IF NOT EXISTS pg_trgm` 成功；`pg_available_extensions WHERE name IN ('pg_trgm', 'vector', 'pg_bigm')` 未回傳 `vector` 與 `pg_bigm`。
- **影響**：
  - B17（伺服器搜尋）的 `pg_trgm` 可立即進行與驗證。
  - 確認採納 **Q-4**：M7.5 先做字詞搜尋與兩路 RRF，向量（pgvector）與語意搜尋延至 M10 之後（屆時測試與正式環境需改用含 pgvector 的 PostgreSQL 版本／映像）。

### 3. PostgreSQL 17 字元分類（UTF-8 `LC_CTYPE`）、`to_tsvector('simple', ...)` 與 `gin_trgm_ops` 索引計畫
- **結論**：
  1. PostgreSQL 17 已移除 `SHOW lc_ctype`（執行會報 `unrecognized configuration parameter "lc_ctype"`），改查 `pg_database` 的 `datctype`、`datcollate`、`datlocprovider`、`datlocale`。
  2. `LC_CTYPE 'C'` 時，**中文 trigram 完全失效**：`show_trgm('測試用')` 回傳 `{}`（空陣列），強關 seqscan 後 GIN 成本高達 `618465.63..618469.64`。
  3. 使用 PG 17 內建 **`LOCALE_PROVIDER builtin BUILTIN_LOCALE 'C.UTF-8'`** 建立資料庫（不依賴宿主機 OS locale）：`datctype=UTF-8 datcollate=C.UTF-8 provider=b locale=C.UTF-8`，`show_trgm('測試用')` 正常產生 `{0x90b74f,0xb9bac4,0xdab90c,0x3d2afd}`，且在 25,000 筆資料開 `SET LOCAL enable_seqscan = off` 下，`'%log/app%'` 與 `'%測試用%'` 皆走 `Bitmap Index Scan on idx_probe_trgm`（成本 `896.85..948.68`），`terms @@ to_tsquery('simple', '測試')` 走 `Bitmap Index Scan on idx_probe_terms`（成本 `531.91`）。
  4. `to_tsvector('simple', '台灣 台 灣 ERR_42 a/b/c')` 回傳 `'42':5 'a/b/c':6 'err':4 '台':2 '台灣':1 '灣':3`（保留中文詞、單字與路徑，並把 `ERR_42` 依 `_` 拆成 `err` 與 `42`）。
- **證據**：同上 `pg_brain_extensions_report` 輸出：
  ```text
  default: enc=UTF8 datctype=UTF-8 datcollate=C.UTF-8 provider=c locale=
  default: tsvector='42':5 'a/b/c':6 'err':4 '台':2 '台灣':1 '灣':3 cjk_trgm={0x90b74f,0xb9bac4,0xdab90c,0x3d2afd}
  loc_c_only: enc=UTF8 datctype=C datcollate=C provider=c locale=
  loc_c_only: tsvector='42':5 'a/b/c':6 'err':4 '台':2 '台灣':1 '灣':3 cjk_trgm={}
  loc_builtin_c_utf8: enc=UTF8 datctype=UTF-8 datcollate=C.UTF-8 provider=b locale=C.UTF-8
  loc_builtin_c_utf8: tsvector='42':5 'a/b/c':6 'err':4 '台':2 '台灣':1 '灣':3 cjk_trgm={0x90b74f,0xb9bac4,0xdab90c,0x3d2afd}
  explain_loc_builtin_c_utf8_cjk_trgm_noseq=Bitmap Heap Scan on probe_mem  (cost=896.85..908.05 rows=3 width=4) |   Recheck Cond: (content ~~ '%測試用%'::text) |   ->  Bitmap Index Scan on idx_probe_trgm  (cost=0.00..896.85 rows=3 width=0)
  ```
- **影響**：B17 建庫與 `tests/harness/src/postgres.rs` 若需要固定跨系統一致的 UTF-8 分類，應顯式用 `TEMPLATE template0 LOCALE_PROVIDER builtin BUILTIN_LOCALE 'C.UTF-8'`；並請 B14/B17 注意 `to_tsvector('simple', ...)` 會把含 `_` 的識別碼拆開，精確識別碼比對不能只靠 `'simple'`。

### 4. `jieba-rs 0.11.0` 可用性、成本與實測 `cut` 輸出
- **結論**：`jieba-rs 0.11.0`（MIT）在 macOS 本機可編譯並通過 `cargo deny check`（無 RustSec、授權相容）。預設 `default-dict` 會拉入 `include-flate 0.3.5`、`zstd-sys 2.2.0+zstd.1.6.0`（C 程式碼）與 `proc-macro-error3 3.1.1`（編譯時間與執行檔大小皆顯著增加）。另確認 `jieba-rs` `0.11.0` 的 `cut(sentence, hmm)` 回傳 `Vec<Token<'a>>`（讀取 `.word` 欄位），且僅在 HMM 模式可選或固定句子下決定。
- **證據**：
  - `cargo deny check`（`target/probe/jieba_probe`）：`advisories ok, bans ok, licenses ok, sources ok`（共 38 個套件，含本體 1 個）。
  - Release 編譯時間與執行檔大小（對照 `probe_base`：`0.19s`、`433,792 bytes` / `424 KiB`）：
    - `jieba_probe`：`9.13s`、`3,445,952 bytes`（`3.29 MiB`，增加約 `+2.87 MiB`）
    - 內附未壓縮辭典檔（`~/.cargo/registry/src/.../jieba-rs-0.11.0/src/data/`）：`dict.txt` `4.8 MiB`（`idf.txt` `5.9 MiB`、`posseg.txt` `2.4 MiB`）。
  - 5 句固定句實測 `Jieba::new().cut(s, false)` 輸出（供 B14 測試對照）：
    1. `我喜歡養貓咪和喝美式咖啡` → `["我", "喜", "歡", "養", "貓", "咪", "和", "喝", "美式", "咖啡"]`
    2. `台北天氣預報明天會下雨嗎` → `["台北", "天", "氣", "預", "報", "明天", "會", "下雨", "嗎"]`
    3. `測試使用PostgreSQL儲存長期記憶` → `["測", "試", "使用", "PostgreSQL", "儲", "存", "長", "期", "記", "憶"]`
    4. `請幫忙查詢ERR_CONN_RESET錯誤碼` → `["請", "幫", "忙", "查", "詢", "ERR", "_", "CONN", "_", "RESET", "錯", "誤", "碼"]`
    5. `臺灣和台湾各自切分` → `["臺", "灣", "和", "台湾", "各自", "切分"]`
  - 註：`jieba-rs` 預設辭典偏簡體字表，因此「喜歡」「測試」等繁體詞會切為單字，這正是 K107 同時需要「單字＋重疊兩字詞＋jieba 詞」的原因。
- **影響**：B14 需決定是否維持 `default-dict`（Q-3，若維持則帶入 `zstd-sys` C 依賴與兩項單一作者傳遞套件）；`Jieba::new().cut(text, false)` 回傳 `Token.word`；雲端三系統編譯結果待合併後由監督者跑完整雲端檢查驗證。

### 5. NFKC 套件比較：`unicode-normalization 0.1.26` vs `icu_normalizer 2.4.0`
- **結論**：兩者皆已在根目錄 `Cargo.lock` 且皆通過 `cargo deny check`；**建議選 `unicode-normalization 0.1.26`**。理由：僅 2 個依賴套件（vs `icu_normalizer` 30 個）、編譯快（`1.07s` vs `4.93s`）、API 最單純（`use unicode_normalization::UnicodeNormalization; s.nfkc().collect::<String>()`），不需攜帶 ICU4X 資料表與常態器物件。
- **證據**：
  - `norm_un`：`3` 個套件（含本體）、`1.07s`、`570,048 bytes`（`557 KiB`）、`advisories ok, bans ok, licenses ok, sources ok`；`"ＥＲＲ＿４２ ﬁle ①".nfkc()` → `"ERR_42 file 1"`。
  - `norm_icu`：`31` 個套件（含本體）、`4.93s`、`540,736 bytes`（`528 KiB`）、`advisories ok, bans ok, licenses ok, sources ok`；輸出同為 `"ERR_42 file 1"`。
- **影響**：B14 直接使用 `unicode-normalization`。

### 6. B10 分詞器套件：`tiktoken-rs` 與 `tokenizers`
- **結論**：
  - **`tiktoken-rs 0.12.1`（MIT）**：純 Rust（19 個依賴套件），通過 `cargo deny check`，離線可建 `o200k_base()` 並正確算 token（編譯 `6.18s`、執行檔 `6,294,256 bytes` / `6.00 MiB`，增 `+5.59 MiB`）。
  - **`tokenizers`（Apache-2.0）重大阻塞**：
    - `0.23.2`（最新穩定版）：關閉預設功能、只開 `features = ["fancy-regex"]`（不含 C 的 `onig`、不開 `esaxx-rs/cpp`）可純 Rust 編譯（85 個依賴套件、`12.97s`、`4,653,200 bytes` / `4.44 MiB`），`Tokenizer::from_bytes` 可跑；**但 `tokenizers 0.19.1`–`0.23.2` 全部直接依賴已標記 unmaintained 的 `paste 1.0.15`，導致 `cargo deny check` 失敗（`RUSTSEC-2024-0436`）**。
    - `1.0.0-rc.5`（預覽版，2026-11-20）：雖已移除 `paste`，但經 `tk-encode -> ptr_hash` 拉進已標記 unmaintained 的 **`fxhash 0.2.1`，`cargo deny check` 同樣失敗（`RUSTSEC-2025-0057`）**，且把 `criterion`/`plotters` 拉進正式依賴樹（139 個套件）。
    - **備註對照**：額外探測純 Rust BPE/WordPiece 套件 `morpheme 0.5.0`（MIT），依賴 62 個套件且 `cargo deny check` 全過（無 RustSec、無 C），但屬單一作者且 `spec/06` 與 `spec/09` K112 ⑨ 明訂使用 `tokenizers`，未經使用者同意不可自行替換。
- **證據**：
  - `tiktoken_probe` run：`o200k en=7 zh=13`（`"Hello, AnyBot context budget!"` = 7；`"台北天氣預報：今天有陣雨。"` = 13）；`cargo deny check`：`advisories ok, bans ok, licenses ok, sources ok`。
  - `tokenizers_probe` (`0.23.2`, `default-features = false, features = ["fancy-regex"]`) `cargo deny check`：
    `error[unmaintained]: paste - no longer maintained ... ID: RUSTSEC-2024-0436 ... advisories FAILED, bans ok, licenses ok, sources ok`
  - `tokenizers_rc` (`=1.0.0-rc.5`) `cargo deny check`：
    `error[unmaintained]: fxhash - no longer maintained ... ID: RUSTSEC-2025-0057 ... advisories FAILED, bans ok, licenses ok, sources ok`
- **影響**：B10 中 `TokenizerKind::O200k` 技術上可行（仍須確認單一作者規範），而 **`TokenizerKind::TokenizerJson` 被 `tokenizers` 的 RustSec 警告與不可擅改 `deny.toml` 的規則阻塞**，須使用者決定解法。

## 三、需要使用者決定的事項

1. **B10 `tokenizers` 違反 `deny.toml` 的解法（阻塞 `TokenizerKind::TokenizerJson`）**：
   - `tokenizers 0.23.2` 因直接依賴 `paste 1.0.15` 觸發 `RUSTSEC-2024-0436`；`1.0.0-rc.5` 因 `fxhash 0.2.1` 觸發 `RUSTSEC-2025-0057`。依規則 `deny.toml` 僅豁免 `RUSTSEC-2024-0370` 且 agent 不得擅改 `deny.toml`。
   - 請裁決：(a) 同意在 `deny.toml` 暫時加入 `RUSTSEC-2024-0436` 豁免並以 `tokenizers = { version = "0.23", default-features = false, features = ["fancy-regex"] }` 接入；(b) 改用純 Rust 無 RustSec 的套件（如單一作者 `morpheme 0.5.0`，或自行解析 HuggingFace `tokenizer.json`）；或 (c) 本回合僅實作 `O200k`（若確認採用單一作者 `tiktoken-rs`），`TokenizerJson` 維持待處理。
2. **單一作者套件確認（`AGENTS.md` 第三節）與 `jieba-rs` 辭典策略（Q-3）**：
   - 確認同意在產品程式碼正式加入單一作者套件 `jieba-rs 0.11.0`（`messense`）與 `tiktoken-rs 0.12.1`（`zurawiki`）。
   - Q-3：`jieba-rs` 採 `default-dict`（拉進 `include-flate`、`proc-macro-error3`、`zstd-sys` C 編譯，二進位 +2.87 MiB），還是關掉 `default-dict` 改將 MIT `dict.txt`（4.8 MiB）附在 repo 以達成純 Rust 零 C 依賴。
3. **B17 PostgreSQL UTF-8 locale 與 pgvector 缺席**：
   - 嵌入式 PG 17.6 無 `vector`（pgvector）與 `pg_bigm`，驗證 Q-4 維持 M7.5 延後向量是正確決定。
   - 確認 B17／`tests/harness/src/postgres.rs` 是否統一使用 PG 17 內建 `LOCALE_PROVIDER builtin BUILTIN_LOCALE 'C.UTF-8'` 建立資料庫，避免系統 locale 落回 `'C'` 使中文 `pg_trgm` 失效。
4. **雲端三系統編譯驗證（`jieba-rs` / `tiktoken-rs`）**：
   - 本探路僅完成 macOS 本機實測；`jieba-rs`（含 `zstd-sys`）與 `tiktoken-rs` 在 Windows／Linux 雲端編譯將於併入後由監督者跑雲端檢查一併確認。
