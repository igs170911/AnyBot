   - 畫面上的字一律從翻譯檔來，不寫死。拿掉 `data-message-code` 這種只給測試用的屬性。
   - 測試：分別用 `en` 和 `zh-TW` 畫出畫面，從那個語言的翻譯檔排出預期的字來比對，測試裡不寫字面。另外測「瀏覽器語言是 `fr` 時用英文」。

## 二、程式錯誤

2. **還沒聽成功就印「listening」。**
   - 實際跑兩台伺服器，第二台會先印 `AnyBot server v0.1.0: listening on 127.0.0.1:8787 …`，再印 `Cannot use port 8787: Address already in use`。M3 就有這個錯，`main` 在 `bind_plan` 之前就印出啟動那一行。
   - 改成兩個位址都聽成功之後才印（`spec/10-behavior` install-n22 S3）。這是修錯，不算「改產品行為」。
   - 測試：第二台的 stdout 不能有啟動那一行，第一台的 stdout 第一行是它。
3. **命令列參數錯誤被說成「The request was malformed.」。**
   - 現在 `--lang zh-TW` 這種打錯的參數，印出 `problem-bad-request`。那是 HTTP 錯誤的代碼，而且 clap 說的錯在哪裡被丟掉了。M3 會印出 clap 的錯誤說明，這次退步了。
   - 給命令列參數錯誤自己的代碼，例如 `server-arguments-invalid`，參數帶 clap 產生的說明。clap 的說明是函式庫產生的英文，可以直接當參數。結束碼維持 2。
   - 測試：給一個不存在的旗標，stderr 等於用 `en` 排出的那一行，結束碼是 2。
4. **排字時參數對不上不會報錯。**
   - 第 3 點傳了 `reason` 參數，但 `problem-bad-request` 的訊息根本沒有參數，排字照樣成功。
   - `messages` 排字時，給的參數跟那則訊息要的參數必須剛好一樣，多給、少給都回錯誤。附測試。
5. **用字串寫的訊息代碼打錯，關卡擋不住。**
   - foundation 的 `error.rs` 和 `apps/server` 的 `bridge.rs` 各有一份代碼字串。我在複本裡加了 `pub const CODE_PLANTED: &str = "server-planted-missing";`，`locale-gen check` 照樣通過。回報卻寫「引用不存在的代碼＝錯誤」。
   - 去掉重複的那一份：`apps/server` 直接用 foundation 的常數轉成 `MessageCode`，不再自己抄一份。
   - 關卡補上：程式裡每個當作訊息代碼的字串（例如 `CODE_` 開頭的字串常數），都必須在 `en.ftl` 裡。附「塞一個打錯的代碼會被擋」的測試。
   - 加一個測試：foundation 的每個代碼常數都轉得成 `MessageCode`。
