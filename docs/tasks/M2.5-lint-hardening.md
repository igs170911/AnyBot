# 里程碑 M2.5：四條鐵律的關卡，和 lint 加強

先讀 `AGENTS.md` 第二節（四條鐵律）、`spec/05` §2a、`spec/09` 的 K75–K79。這個里程碑**不寫任何功能**。

## A. 四條鐵律的關卡

新寫一個檢查工具，或擴充 depcheck。每道關卡都要有單元測試。

1. **不准關掉檢查**
   - 掃 `crates/`、`apps/`、`tools/`、`web/`、`adapters/`（產生出來的檔案除外）。出現下面任何一個就擋：`#[allow`、`#![allow`、`#[expect`、`#![expect`、`biome-ignore`、`@ts-ignore`、`@ts-expect-error`、`@ts-nocheck`、`eslint-disable`。
   - `spec/07` §3 的套件豁免，改成寫在**那個套件自己的 `clippy.toml`**（Clippy 會先找套件資料夾裡的設定檔）。
     - Clippy 只讀最近的那一個設定檔，不會合併，所以套件的設定檔要跟根目錄的一模一樣，只少它被准許的那幾條禁用項目。
     - 檢查工具核對兩件事：只有准許的套件有自己的 `clippy.toml`；內容跟根目錄的差異剛好就是准許的那幾條。
   - 測試裡可以用 `unwrap` 這類寫法，靠 `clippy.toml` 的測試設定（`allow-unwrap-in-tests` 這類，以 Clippy 1.98 實際支援的為準）。
   - 現在 M1、M2 程式裡所有的 `#![allow(...)]`、`cfg_attr(test, allow(...))` 全部拿掉，改成修程式或改用設定檔。
     - 例如 spec-trace 為了 `unused_crate_dependencies` 加的 allow：改**程式結構**讓它不需要。
     - `let _ = (name, matches);` 這種塞掉警告的寫法也要修掉。
2. **例外只准一條**：`deny.toml` 的 `advisories.ignore` 剛好是 `RUSTSEC-2024-0370`；其他區段也不准有任何例外或略過。多一條就擋。
3. **檔案最多 300 行、函式最多 60 行**
   - 自家的行數檢查涵蓋 Rust、TS、TSX，產生出來的檔案除外。
   - `clippy.toml` 設 `too-many-lines-threshold = 60`。
   - TypeScript 的函式行數用 Biome 的對應規則；Biome 2.6 沒有的話，自家檢查也要管。
4. **不寫註解**
   - 自家檢查掃 Rust 和 TS、TSX 的註解（`//`、`/* */`、`///`、`//!`），字串裡的不算；產生出來的檔案除外。
   - 現有的註解全部拿掉。說明本來就寫在 `spec/` 裡。
5. **規格追蹤改用測試名稱**
   - spec-trace 改找 Rust 測試函式（`#[test]`、`#[tokio::test]` 等）的名稱 `t_<編號>`，例如 `T-chat-steer-1` 對到 `t_chat_steer_1`；以及 TypeScript `test(` 和 `it(` 的標題開頭 `T-…`。
   - 舊的 `spec:` 註解格式整個拿掉。
   - 單元測試的測試資料也跟著改。

## B. lint 加強（K79）

1. **Clippy**（workspace lints，等級 deny）：
   - 規則：`allow_attributes`、`allow_attributes_without_reason`、`dbg_macro`、`todo`、`unimplemented`、`unreachable`、`print_stdout`、`print_stderr`、`exit`、`mem_forget`、`indexing_slicing`、`string_slice`、`get_unwrap`、`unwrap_in_result`、`wildcard_enum_match_arm`、`let_underscore_untyped`、`let_underscore_must_use`、`clone_on_ref_ptr`、`rc_buffer`、`float_cmp_const`、`lossy_float_literal`。
   - 加上個別打開 `cognitive_complexity`，`clippy.toml` 設 `cognitive-complexity-threshold = 15`。
   - 命令列程式和檢查工具需要輸出時，用 `writeln!` 寫到 stdout，不要用 `println!`。
   - 因為不寫註解（K78），workspace lints 把 pedantic 裡要求寫文件的 `missing_errors_doc`、`missing_panics_doc` 設成 allow。這是 workspace 的規則選擇，不是在程式碼裡關掉。
2. **Rust 編譯器**：`unreachable_pub`、`unused_qualifications`、`let_underscore_drop`。
3. **rustfmt**（只用 stable 有的選項）：`newline_style = "Unix"`、`use_field_init_shorthand = true`、`use_try_shorthand = true`。
4. **cargo-deny**：
   - `[sources]`：`unknown-registry = "deny"`、`unknown-git = "deny"`，只准 crates.io。
   - `[bans]`：`wildcards = "deny"`，加上 `allow-wildcard-paths = true`。
   - `[advisories]`：`yanked = "deny"`。
5. **掃金鑰**：`brew install gitleaks`；`make check` 和 CI 都掃整個 repo，包含 git 歷史。
6. **Biome**：
   - 打開型別感知的規則，最重要的是 `noFloatingPromises`。設定方式**以已安裝的 2.6 版的 schema 和官方文件為準**，網路上的說法不一致。
   - 再加：`noConsole`、`noExcessiveCognitiveComplexity`（15）、函式行數規則。
   - CI 用 `biome ci`，並把警告也當錯誤（照 2.6 實際支援的旗標）。
7. **tsconfig**：補 `allowUnusedLabels: false`、`allowUnreachableCode: false`、`noUncheckedSideEffectImports: true`。

加上這些後，M1、M2 的程式碼有不合格的，**全部修到過，不准關掉**。

## C. 驗收

- `make check` 全綠；`make check-fast` 也包含四條鐵律的檢查。
- 每道新關卡都有單元測試，至少包含這些情況：
  - 塞一個 `#[allow]` 會被擋。
  - 301 行的檔案會被擋。
  - 一行註解會被擋。
  - `deny.toml` 多一條例外會被擋。
  - 不准的套件有自己的 `clippy.toml` 會被擋。
- commit 一次。
