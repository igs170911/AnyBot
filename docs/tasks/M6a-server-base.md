## 套件分工（照 `spec/07`）

- `store-server`：連線池、遷移、所有 SQL。只有它碰資料庫。
- `server`：
  - axum 路由和 handlers。
  - 啟動順序。
  - 次數限制、來源位址、`Idempotency-Key`。
  - 密碼雜湊。
  - OpenAPI。
  - 照舊不准依賴 `runner`、`models`、`tools`、`computers`。
- `domain`：純規則。
  - 帳號名稱的規則、邀請碼的格式（亂數從外面傳進來）。
  - 5 分鐘窗口的計數判斷、來源位址的判斷。
  - 工作階段的失效和擠掉。
  - 不碰網路、資料庫、非同步、時鐘：時間從外面傳進來。
- `protocol`：API 的請求和回應型別（TypeScript 客戶端由它產生）。
- `foundation`：
  - 啟動檔（已經有）、`Clock`。
  - `Secret`：密碼、工作階段的金鑰、代理暗號都用它裝。
- `messages` 和 `locales/`：這次新的訊息代碼，包括紀錄、命令列、API 錯誤。
- `apps/server`：命令列，包括 `reset-password`。`main` 保持極簡。

## A 段：資料庫、設定、測試地基

1. **遷移**（`server-boot` S2、S3；`server-n8` S3）：
   - 遷移檔放 `migrations/server/`，用 `sqlx::migrate!` 編進執行檔。
   - 遷移只加不刪（`02` A14）：不准 `DROP`、改名、改型別。
   - 伺服器當函式庫啟動時，遷移的那一組從建構函式傳進去；`main.rs` 傳編進去的那一組。測試才換得了「新版、舊版」。
   - 啟動時的判斷：
     - 資料庫完全空的 → 建表。
     - 是 AnyBot 的 → 遷移。用第一個遷移建的標記表來認，不要猜表名。
     - 有別的程式的資料 → 不動它，印 `server-n8` S3 那句，結束碼 2。
     - 連不上 → 每 5 秒再試（透過 `Clock`），紀錄寫原因，不退出。
   - 遷移失敗：資料庫保持遷移前的樣子、不啟動、紀錄寫原因、結束碼不是 0。
   - 資料庫裡有這一版不認得、比較新的遷移（退回舊版的情況）→ 照常啟動，不報錯。
   - SQL 一律用編譯時檢查的寫法（`query!` 這類）。
     - 離線查詢資料 `.sqlx/` 提交進 repo。
     - 加一個 make 目標，用 harness 的臨時 PostgreSQL 重新產生它。
     - `make check` 要檢查它是最新的。
     - 給 sqlx-cli 的連線位址只在 make 目標裡傳，產品程式照舊不讀環境變數。
   - 測試：`T-server-n8-3`、`T-server-boot-2`、`T-server-boot-3`。
     - `T-server-n8-3`：「連不上、20 秒後上線」用 harness 的網路代理擋在 PostgreSQL 前面做。
     - `T-server-boot-2`：要從執行檔看到結束碼。做不到又不想為測試加旗標的話，用描述性的名字，編號留在基準檔，寫進回報。
     - `T-server-boot-3`：「版本 N＋1」是 `tests/harness/fixtures/` 裡多一個只加不刪的測試用遷移。
2. **伺服器設定放資料庫**（`server-n14` S1、S4；`account-bind` S1、S4；`09` K92）：
   - 這次的設定：
     - 要聽的位址：預設 `127.0.0.1` 和 `::1`，加上埠。
     - 對外網址。
     - 邀請碼。
     - 相信哪個反向代理，和它的暗號。
     - 伺服器的語言：預設英文。
   - 啟動順序：讀啟動檔 → 連資料庫 → 檢查、遷移 → 讀設定 → 聽 → 印啟動那一行。
   - 啟動那一行照 `install-n22` S3，列出實際在聽的每個位址。
   - 要聽的位址寫的不是位址（例如 `abc`）→ 不聽，紀錄寫原因。
   - 環境變數沒有任何作用（`server-n14` S4）。
   - 伺服器印的字照資料庫裡的語言。還沒連上資料庫時印的照英文。
   - 資料庫裡還沒設定時，預設聽 `127.0.0.1` 和 `::1` 的 8787 埠（`09` K108 ①）。
   - 埠被占用（`09` K108 ②）：預設那一對本機位址全有或全無，綁不到就結束碼 1（`install-n22` S3）。資料庫另外設定的位址綁不到時，寫紀錄、每 5 秒再試，這次不做（`T-account-bind-3`），之後做。
   - 測試：`T-account-bind-1`、`T-account-bind-4`、`T-server-n14-1`、`T-server-n14-4`。
3. **測試改用臨時埠**：
   - 測試裡不准再出現 8787。
   - 執行檔層級的測試：harness 先遷移、在資料庫寫好要聽的位址（臨時埠，IPv4、IPv6 都空著的那個），再啟動執行檔。不准為了測試加 `--port` 這類旗標。
   - 已經有的 `T-install-n22-1`–`4`、`T-server-n14-2` 和兩個健康檢查的測試，改成這樣，照樣要過。`T-install-n22-3` 占住的是資料庫裡寫的那個埠。
   - 伺服器當函式庫啟動的測試，可以像 M4 的 testenv 一樣，從外面傳已經聽好的 listener 進去。
   - harness 要能「伺服器停機／恢復」：同一個資料庫，停掉再開一個新的伺服器。
   - `tests/testenv` 也要起 PostgreSQL 並傳給伺服器，`make e2e` 照樣全綠。
   - 要 PostgreSQL 的測試放在名稱以 `pg_` 開頭的測試檔。`.config/nextest.toml` 用測試檔的名稱分組，`check-fast` 也用它排除。不要靠測試名稱的樣式，也不要讓測試自己判斷要不要跳過。
   - harness 要依賴產品套件來準備資料庫的話，`tools/depcheck` 的表格跟著改，寫進回報。

## B 段：帳號和登入

4. **註冊和邀請碼**（`server-invite` S1、S2、S4、S5；`account-login` S3；`server-n13` S1）：
   - 邀請碼的格式：`xxxx-xxxx`，不用 0、O、1、l、I。存在資料庫，大家共用一組，沒期限、沒次數。
   - 註冊都要邀請碼，第一個帳號也要。第一個註冊的帳號是伺服器管理員。
   - 帳號 2–64 字，只能英數和 `. _ @ -`，一律轉小寫。密碼至少 8 字。
   - 同一位址 5 分鐘最多註冊 5 次，成功也算。
   - 啟動時還沒有帳號 → 紀錄印 S5 那句。
   - 還沒有安裝程式、資料庫裡也沒有邀請碼時，伺服器第一次啟動自己產生一組，印在紀錄裡（`09` K108 ③）。
   - 測試：`T-server-invite-1`、`T-server-invite-2`、`T-server-invite-4`、`T-account-login-3`。
5. **登入和工作階段**（`account-login` S4；`account-n9` S1–S3；`safety-n10` S1、S4）：
   - 密碼用 argon2id；同時最多算 4 個（`server-n2` S3）。
   - 登入錯：
     - 等 0.5 秒才回，等待透過 `Clock`。
     - 回「帳號或密碼不對」。
     - 不存在的帳號也照樣算一次雜湊，花一樣的時間。
   - 被停用的帳號：「這個帳號已被伺服器管理員停用」。
   - 錯誤次數：同一位址＋同一帳號 5 分鐘 8 次，同一帳號 40 次。
     - 計數存在資料庫，伺服器重開不歸零。
     - 時間從 `Clock` 拿。
   - 工作階段：
     - 隨機產生的金鑰，資料庫只存雜湊。
     - 90 天沒用就失效；「最後使用」最多每分鐘記一次。
     - 每個帳號最多 50 個，超過時最久沒用的先失效。
     - 有登出這一個、登出所有裝置。
   - 每個工作階段記下「最後一次輸入密碼的時間」。M6b 的配對碼要用（`computers-pair` S2）。
   - 測試：`T-account-login-4`、`T-account-n9-3`、`T-safety-n10-1`、`T-safety-n10-2`、`T-safety-n10-5`、`T-server-n2-1`、`T-server-n2-5`。
     - `T-account-login-4` 量的是真的時間：伺服器用真時鐘啟動。
     - 規格已經改成各登入 6 次，不會碰到次數上限。
6. **改密碼、重設密碼**（`account-n10` S1–S3；`account-n11` S1、S2）：
   - 改密碼：
     - 錯誤照 S1 的三句。
     - 同一帳號 5 分鐘 8 次。
     - 成功後這個帳號其他工作階段全部登出。
   - 管理員替別人重設密碼：那個人的工作階段全部登出。
   - 命令列 `anybot-server --bootstrap <檔> reset-password <帳號>`：
     - 問兩次新密碼，不顯示；至少 8 字。
     - 不用停伺服器；成功後這個帳號全部登出。
   - 標準輸入不是終端機時（自動化、測試），從標準輸入讀兩行當作兩次輸入（`09` K108 ④）。
   - 測試：`T-account-n10-2`、`T-account-n11-2`。
7. **來源位址**（`safety-n11` S1、S2 為準；`server-n1` S1–S3）：
   - 預設用連線的對方位址。
   - 設了相信的反向代理：只對從它來的請求取 `X-Forwarded-For` 的最後一個值；超過 64 字就不信。
   - 再設了暗號：只信帶對暗號的請求。
   - 影響註冊、登入、改密碼的次數限制，和紀錄裡的位址。
   - 本機只有 `127.0.0.1` 和 `::1` 兩個來源位址可用（macOS 上沒有別的 `127.x`），照 `09` K108 ⑤：
     - 規格裡的 10.0.0.9、1.2.3.4 這類位址，測試可以換成本機做得到的位址。
     - 角色要對得上：哪個是連線的對方、哪個是標頭裡的。
     - 換了哪些，寫進回報。
   - 測試：`T-safety-n11-1`、`T-safety-n11-2`、`T-safety-n11-3`、`T-server-n1-1`、`T-server-n1-2`、`T-server-n1-3`。
8. **伺服器管理員**（`server-n13` S1、S4、S5；`server-invite` S3；`server-n14` S1）：
   - 只有管理員能做：
     - 看、換一組邀請碼：舊的立刻失效。
     - 改對外網址。
     - 停用、啟用帳號：停用時那個人的工作階段全部停止；不能停用自己。
     - 重設密碼（第 6 項）。
   - 別人送管理動作 →「只有伺服器管理員能做這件事」。
   - 管理員看不到別人的內容（K17）。這次還沒有內容，只是不要開這種 API。
   - 測試：`T-server-n13-4`。換邀請碼、停用的其他行為，用描述性的名字測。
9. **`Idempotency-Key`**（`conn-post` S1–S4 的伺服器這一側）：
   - 每個 POST 都要帶。沒帶的回錯誤。
   - 同一個 key、同樣內容 → 直接回第一次的結果，不做第二次。
   - 同一個 key、內容不一樣 → 拒絕：「這個請求編號已經用過，內容不一樣」。
   - 至少記 7 天，時間從 `Clock` 拿。記錄存在資料庫。
   - 重送登入（`09` K108 ⑥）：工作階段的金鑰只存雜湊，回不出第一次的，所以重送的登入開一個新的工作階段。
   - 測試：`T-conn-post-2`，用管理員「改對外網址」當那個「改設定」。

## 寫法

- 整合測試從外面打：真的 HTTP，或真的執行檔（K86）。伺服器當函式庫在測試裡啟動，假的東西從建構函式傳進去：假時鐘、資料庫、listener、遷移的那一組。
- 錯誤回 problem+json，帶代碼和參數，`title` 用英文（K91）。測試照代碼比對。
- 每個新的 API 都寫進 OpenAPI：摘要、說明、請求和回應的範例、錯誤回應。API lint 全綠，HTML 文件和 TypeScript 客戶端一起重新產生。
- 規格裡的中文訊息，翻譯檔要有英文和繁體中文兩份。
- 規格沒寫清楚的，不要猜，寫進回報的「要問的問題」。不得不先做時，選最小、之後好改的做法，也寫進回報。
- 這次不做（之後的里程碑做）：
  - 裝置、配對碼、在線和離線、這台電腦的名字、紀錄和同步、SSE、心跳、信箱：M6b。
  - 兩步驟驗證、秘密的靜態加密：`account-n3`、`server-privacy` S3。主鑰匙放哪還沒定（`06` 說放檔案或鑰匙圈，`02` §6 說資料庫以外只有啟動檔）。
  - 要聽的位址還沒出現時每 5 秒再試（`T-account-bind-3`）。
  - 安裝程式、自簽憑證、https：`server-install`、`server-address`、`account-n2`。
  - 公開位址的連線數、請求本文的大小上限：`T-server-n2-3`、`T-server-n2-4`、`T-safety-n10-4`。
  - 團隊分享、推播、發布網站、匯出：各自的里程碑。
  - 例行任務相關：`T-server-n13-3`。
  - 端對端（有畫面的）：M8。這次沒有畫面，Playwright 只要照樣全綠。
