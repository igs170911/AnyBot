# M7a-6 審核修正

M7a-4 交件後，我推上 GitHub 驗（Linux 編不過，那一項已經另外交給你，叫 M7a-5），也請獨立的審查把整個閘道對了一遍。這一份是審查的結果。行號是 `e54dbc0` 當時的位置；我對過第一節的兩項，其餘的你動手前自己再對一次，清單寫錯的照實回報。

先講修對了的：**網址分類站得住了**。審查試了中括號裡的 IPv6、包著 IPv4 的 IPv6、各種數字寫法的 IPv4、大小寫、網址裡帶帳號、全形字的名字，都分對；`0.0.0.0`、帶區域編號的、長得像位址的名字、結尾有點的名字都當雲端。串流照位元組接、憑證錯誤照種類分、`cfg` 的檢查也都修對了。每個迴圈都有上限。

先做：`git merge dev`（`spec/09` K117 ② 的字改清楚了：代理只用建閘道時傳進來的；三種系統各讀自己的信任清單）。

## 一、阻擋項

1. **檢查完才改目的地。** `client.rs` 的 `complete`：通行證和金鑰是對「清單上的網址」檢查的，檢查完才用名稱對照表把網址換掉再送。`with_names`、`clone_with_names`、`gateway_pinned` 都是公開的，也沒有被禁用。一個把本機網址對到雲端主機的對照表，就能把「只送本機和區網」的 Bot 的對話和金鑰送出去。
   - 通行證和金鑰的檢查，要對**實際連過去的那個目的地**做；檢查和送出之間，目的地不能再變。
   - 測試要把某個名字指到假模型的位址，這個需求是合理的。做法：網址不動（名字、憑證上的名稱檢查都照原樣），只在連線那一層把這個名字固定到指定的位址；而且分類和通行證把「被固定到的位址」也算進去：名字是雲端、固定到的位址是本機，照比較嚴的那一個（雲端）算。
   - 產品的程式不准用到這個入口：比照通行證，用工具擋，並有一個真的去編一份違規範例的測試。
2. **「15 秒沒連上」把等回答的時間也算進去了。** `transport.rs` 的 `open_wire` 拿 15 秒去跟 `open` 賽跑；而真的那一層（`reqwest_wire.rs`）的 `open` 要等到回應的標頭來了才回來。不是串流的請求，伺服器想了 20 秒才回 → 被當成「連不上」，然後重送。模型清單也一樣。上一輪加的兩個測試用的是照腳本演的那一層，它的 `open` 馬上就回來，所以驗不到。
   - 15 秒只管「連上」。連上之後照 `models-errors` 的表：等第一個字、出字後 35 秒沒動靜；模型清單 45 秒。
   - 測試要走真的 HTTP 那一層：假模型接了連線、過 20 秒（假時鐘）才回標頭 → 成功，不是連不上；一個連不上的位址 → 15 秒後是連不上。

## 二、應該修

1. **通行證還是可以在套件外面發**：`SendPermit::issue` 是公開的、沒被禁用。另外那個「違規範例編不過」的測試（`tools/iron-laws/src/permit_block.rs`）只要輸出裡有那個呼叫的字就算擋到，隨便一個不相干的編譯錯誤也會過。要比對到那一條規則的名字。
2. **重試預設不等。** 沒有呼叫 `with_stop` 的 `Session` 把「停」的那一端丟掉，`ask.rs` 把關掉的通道當成「馬上重試」：一個接一個重送，不理 Retry-After。測試只驗了通知和次數。等待照 `models-n1`，走 `Clock`；沒有人會按停的時候也照樣等。
3. **不接受參數、空白的回覆**（`models-errors` 的表、K117 ③、`T-models-errors-5`）：
   - 同一個參數被拒第二次，現在還有重試的計畫，同一個請求會送 3 或 8 次。要的是：拿掉一次；再被拒就是失敗。
   - 拿掉參數再送、空白再問，現在都算進重試的次數。規格寫不算。
   - 第二次還是空白，現在回成功。要回失敗。
   - 這兩種再問之間沒有等、也沒有看「停」。補上。
4. **不是串流的回覆收到一半斷掉，回成空白的成功**（`client.rs`、`stream_fail.rs`）。要回失敗。
5. **代理。** 不走代理的名單只有 `localhost`、`127.0.0.1`、`::1` 三個字串，所以 `127.0.0.2`（分類是本機）會走代理。改成跟網址分類用同一個判斷：分類是本機的都不走。加測試：設了 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 也不影響（閘道不讀環境變數）。
6. **換模型的紀錄。** 從備用回到主模型沒有記一筆；「讀要求」和「清要求」還是分兩次拿鎖；全部都在休息的時候，回的是「沒有金鑰」而不是它真正的原因。
7. **金鑰。**
   - 「金鑰只送到它那一家」的檢查，是拿端點的網址去比一個從它自己組出來的網址，永遠會過。要比的是實際要連的目的地和這把金鑰登記的那一家。
   - `ask.rs` 先截成 300 字才遮金鑰：金鑰剛好跨在第 300 個字上時，會留下前半段。先遮再截。
8. **小的**：PEM 區塊後面和區塊之間的文字還是被接受；等第一個字的計時在收到第一個位元組就停（要等到第一個字）；`tests/live-model` 的 `always_thinks` 有讀進來但沒人用，`side.rs` 裡寫死了。

## 三、測試

共同的規則，這一輪寫進來：**預期的值不准呼叫產品的任何函式來算。** 測試裡要自己有一份獨立的、照規格寫的答案（寫死的表、或測試自己的幾行判斷）。上一輪點名的就是這件事，這一輪還有兩個是這樣。

| 測試 | 現在的問題 |
|---|---|
| `t_models_normalize_14` | 工具那幾條是拿輸出自己的結束種類去對；切片固定切成四等份，不是隨機切，切不到一個中文字的中間 |
| `t_models_errors_4` | 「不重試的類別」那個集合是從產品的分類函式來的；有一個斷言不可能失敗 |
| `t_models_errors_5` | 只有 40 種不同的情況、沒有交錯、從來沒有用串流 |
| `t_models_handoff_9` | 唯一會發生的失敗是 404，而 404 本來就不換備用；次數只驗「至少」 |
| `t_models_egress_6` | 預期的分類是用產品的分類函式算的；轉址是在照腳本演的那一層 |
| `t_models_capabilities_4` | 那個斷言不管有沒有帶參數都會過 |
| 真機比對的那個測試 | 拿假模型跟自己比 |

**每個帶編號、這一輪動到的測試，都要證明它會失敗**：把它守的那條產品規則暫時改壞（例如讓被拒的參數繼續帶、讓 404 換備用、讓雲端的網址過政策），看到測試變紅，再改回來。回報裡列成表：測試、改壞了什麼、有沒有變紅。改壞了還是綠的，回去修測試。修不到整列的，把編號放回 `tools/spec-trace/baseline.txt`，寧可少報。

## 驗證和回報

- 順序：一 → 二 → 三。每一大項 `make check` 全綠就 commit。
- 全部做完 `git merge dev`、`make check`。
- 回報（簡短）：每一項怎麼改的；第三節「會失敗」的那張表；清單裡哪幾項你對過之後認為寫錯了；有沒有哪一項你認為不該照做、為什麼。
- 沒做完的照實寫。

你是一次性執行的：回合一結束，背景工作就會被收掉。`make check` 用前景跑、timeout 設長（30 分鐘）。同時有別的 agent 在別的工作區做事，測試會互相等，屬於正常。只在自己的工作區做，暫存檔放自己工作區的 `target/`，不改 `spec/`。不准改寫歷史、不准 push、不要用 `gh`、不准用 `pkill` 或 `killall`。函式庫的行為要查文件或原始碼確認（`~/.cargo/registry/src/` 可以讀），不要憑記憶寫。遇到「Operation not permitted」是沙箱在擋，不要繞過。
