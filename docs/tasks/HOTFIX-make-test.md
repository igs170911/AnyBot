# HOTFIX：測試失敗時 `make test`（和 `make check`）還是回報成功

## 現象

`Makefile` 的 `_test-body`：

```
$(CARGO) nextest run --workspace --test-threads 1 2>&1 | tee target/nextest.log; \
	! grep -q "ignoring unknown configuration keys" target/nextest.log
```

兩個指令用 `;` 接起來，整行的結束碼只看最後那個 `grep`。nextest 有測試失敗時，只要紀錄裡沒有那句警告，整行就是成功，`make check` 照樣全綠。

監督者驗過：用這份 Makefile 的 `SHELL` 設定，把前半換成 `false`，`make` 的結束碼是 0。

這個洞從 M4 審查修正那一版就在。之後每一次「`make check` 全綠」，包括 GitHub 上的，都不保證測試真的過了。（`dev` 上最新一次的紀錄是 438 個測試全過，所以目前沒有壞東西混進去；壞的是關卡。）

## 要做的

1. **兩件事都要擋得住，缺一不可**：
   - nextest 的結束碼不是 0 → 這個目標失敗。
   - 紀錄裡出現「ignoring unknown configuration keys」→ 這個目標失敗。
   - 另一個工作區有人改成「記下 nextest 的結束碼，最後 `exit` 它」：這樣前一項對了，後一項卻變成不管有沒有警告都不會失敗。不要照那個改。
2. **把整份 `Makefile` 和 `tools/`、`deploy/` 裡的腳本找一遍同樣的毛病**：
   - 用 `;` 接起來、前面指令的失敗被吃掉的。
   - 接了管線（`|`）、前面指令的失敗被吃掉的。
   - 找到的一起修，列進回報。
3. **附「塞進去會被擋」的自我測試**，放進 `make check`：
   - 用跟 `_test-body` **同一段**邏輯（抽成一支小腳本或一個共用的寫法，兩邊都用它，不准複製一份），餵一個結束碼不是 0 的指令 → 要失敗。
   - 餵一個結束碼是 0、但輸出裡有那句警告的指令 → 要失敗。
   - 餵一個結束碼是 0、輸出乾淨的指令 → 要成功。
   - 這個自我測試不准真的去跑整個測試套件（要快，幾秒內）。
4. **iron-laws 加一道檢查**，掃 `Makefile` 的 recipe：
   - 同一個邏輯行裡，管線或指令後面用 `;` 接著別的指令（這次出事的寫法）→ 擋。要這樣寫的，改成呼叫腳本。
   - 附「塞進去會被擋」的測試。
   - 現有的 recipe 有被這條擋到的，一起改掉；不准加例外清單了事。

## 範圍

- 只改 `Makefile`、`tools/`（腳本和 iron-laws）、需要的話 `docs/testing.md`。不改產品程式，不改測試內容。
- 修完之後，如果有原本就壞掉、只是一直沒被擋到的測試冒出來：**不要自己修那些測試**，列進回報（哪個測試、錯誤訊息）。那種情況下 `make check` 不會綠，照實回報，不准為了綠去跳過。

## 驗證和回報

- `make check` 的結果（照實）。commit 一次。
- 回報（簡短）：怎麼改的；整份找一遍另外找到幾處；自我測試叫什麼、三種情況各是什麼結果；iron-laws 新檢查擋了什麼。

你是一次性執行的：回合一結束，背景工作就會被收掉。`make check` 用前景跑、timeout 設長（30 分鐘）。同時有別的 agent 在別的工作區做事，測試會互相等，屬於正常。不准改寫歷史、不准 push、不要用 `gh`、不准用 `pkill` 或 `killall`。暫存檔放自己工作區的 `target/`。
