這一頁講現在能做什麼，以及之後打算怎麼裝。適合想試用，或想在自己的電腦上跑檢查的人。

對你的意義：**現在沒有可以安裝的版本。**不能拿來聊天，也不能把事情交給它。想參與開發的人，可以從原始碼跑檢查和測試。

## 現在能做什麼

| 你想做的 | 現在 | 狀態 |
|---|---|---|
| 安裝一個 App 來用 | 沒有安裝檔 | 📝 |
| 跟 Bot 聊天、看任務 | 畫面只有一行「畫面骨架：沒有功能」 | 📝 |
| 看伺服器還活著 | 開發時可以打健康檢查 | 🚧 |
| 跑專案的檢查和測試 | 可以，要先裝工具 | ✅ 檢查關卡已在本機跑過 |

伺服器的命令列認 `--help`、`--version`、`--bootstrap`。`--bootstrap` 指向一個小檔，裡面是資料庫的連線位址。啟動時會印它在聽哪裡，不印密碼。子指令 `reset-password`、`logs`、遷移，列在說明裡，還沒實作。

預設聽本機的 8787 埠（`127.0.0.1` 和 `::1`）。這只是開發時的骨架，不是給人用的服務。

健康檢查是 `GET /v1/health`。它回版本、現在時間、協定版本。不用登入。帳號、聊天、任務的 API 還沒有。

## 從原始碼跑檢查

這一節假設你會基本的命令列。

需要：

| 工具 | 用途 |
|---|---|
| Rust（版本寫在 `rust-toolchain.toml`，目前 1.98.1） | 後端和檢查工具 |
| rustfmt、clippy | 格式和 lint |
| cargo-deny、cargo-machete、cargo-nextest | 授權、沒用到的依賴、測試 |
| Node 22 以上、pnpm | 畫面 |
| gitleaks | 掃金鑰 |
| oasdiff | 看 API 有沒有破壞性變更 |

不要用 Docker 跑測試。測試用的資料庫會下載到這個 repo 的 `target/`，跑完就收。

常用指令：

```sh
make check-fast
```

改完一批就跑這個。它跑最快的關卡：格式、lint、一組較快的測試、依賴方向、鐵律、翻譯、API 文件。

```sh
make check
```

這是「完成」的定義。全部關卡，包含完整測試和端對端。比較久。

關卡各自擋什麼，見[[開發流程]]。

桌面視窗（仍然沒有功能）可以這樣開：

```sh
pnpm install
cargo install --locked tauri-cli
cargo tauri dev
```

手機網頁的骨架：

```sh
pnpm --filter @anybot/web preview
```

打開之後你會看到標題 AnyBot，和一句「畫面骨架：沒有功能」。這是預期的。

## 之後怎麼裝

下面是規格和發佈計畫，**都還沒做**（📝）。

| 版本 | 從哪裡來 | 跟正式版的關係 |
|---|---|---|
| 開發版 | `dev` 檢查全綠後，掛在固定的預先發佈頁。舊的自動換掉 | 用不同的 App 名稱和資料夾，可以跟正式版並存 |
| 正式版 | 在 `main` 上打版本標籤 `v*`，三種系統的安裝檔和伺服器映像 | 先出草稿，檢查後公開 |
| 預先發佈 | 標籤像 `v1.0.0-rc.1` | 標成預先發佈，不是正式版 |

伺服器映像打算推到容器倉庫。桌面安裝檔掛在 GitHub Release。

個人沒有遠端伺服器時，桌面 App 要在你的電腦裡裝好伺服器和 Bot 的電腦。這台裝不起 Docker，就先只在本機聊天和做事，並說清楚手機和例行任務要等。這也是 📝。

發佈流程的圖在[[分支與發佈]]。

## 還沒簽章時，系統會跳什麼警告

先不簽章（K110）。簽章過的安裝檔是目標，還沒做到。

所以之後第一次裝開發版或正式版時，系統會警告。Release 的說明要寫怎麼放行。要不要買 Apple 開發者帳號、Windows 憑證，之後再定。

| 系統 | 你可能看到的 |
|---|---|
| macOS | 這份 App 來自身分不明的開發者，要你到系統設定放行 |
| Windows | SmartScreen 說發行者不明，要你選仍要執行 |
| Linux | 套件沒有簽章，套件管理器會警告 |

這些警告是預期的，直到簽章做完。不要為了躲警告關掉系統的安全檢查。
