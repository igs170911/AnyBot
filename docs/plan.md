# 開發路線（總規劃）

> 規劃和監督：Claude（Claude Code）。動手的：pi-bolt（所有程式和測試都由它寫）。
> 規格來源：`spec/`。每個里程碑一份任務檔：`docs/tasks/M<n>-*.md`。

## 每個功能里程碑的完成條件（缺一不可）

1. **規格測試**：任務檔列出的每個規格編號都有對應的測試、而且通過；spec-trace 的基準檔把它們移除。
2. **三層測試**
   - **單元**：純邏輯，在各套件裡。
   - **整合**：經 API 打伺服器和執行端，用測試驅動程式（`tests/harness`）和假的外部服務：假模型、假時鐘、假推播、假聊天頻道、假電腦。
   - **端對端**：有畫面的功能用 Playwright 跑手機寬度和桌面寬度。手機一律跑這幾種情境：小 iPhone 加最大字級、大螢幕、從右到左的語言、深色模式、中文和英文。
3. **API 文件**
   - 每個新的 API 都在 OpenAPI 裡寫齊：摘要、說明、請求和回應的範例、錯誤回應。
   - API 文件的 lint 全綠。
   - 產生出來的 HTML 文件和 TypeScript 客戶端一起更新。
   - 執行事件協定有變更的，寫進 AsyncAPI。
4. **五條鐵律**（`AGENTS.md` 第二節），加上 `make check` 全綠。
5. **回報**：覆蓋數字前後的變化、新的 API 文件在哪。

Claude 每個里程碑都獨立檢查：
- 自己重跑 `make check`。
- 抽查測試是不是真的測到規格寫的行為，不是為了過關的空測試。
- 跑 clean room 污染檢查。
- 翻 pi-bolt 的工作紀錄。

不合格就退回修，修到過為止。
